Key Takeaways

  • COSMOS-3 is a Mixture-of-Experts (MoT) based model that unifies reasoning, world/video generation, and action generation into a single omni-model[1][2].
  • The front-end Reasoner handles language and vision understanding, while the back-end Generator uses a diffusion transformer to produce video, audio, and actions[3][4].
  • Actions are unified as camera-frame end-effector 3D poses and 6D rotations, aiming for cross-embodiment learning[5][6].

Summary

Criteria for Omni-models and COSMOS-3’s Positioning

COSMOS-3 is presented as an omni-model that handles multimodal inputs and outputs[7]. Here, “native” likely refers to learning multiple modalities together during the pre-training stage rather than post-hoc integration[8]. The publicly disclosed scales are Edge 4B, Nano 16B, and Super 64B[9]. Inputs include image, text, audio, and action, while outputs include video, language, audio, and action[10].

Compared to LLMs, it typically has a smaller parameter count around 14B, which can be linked to real-time processing requirements[11]. The bar for omni-models continues to rise[12]. Compared to existing omni-modal research, the inclusion of both action and audio modalities is particularly notable[13]. Its open-source release is also expected to contribute to various application development[14]. In short, it should be viewed as an omni-model that includes action generation, rather than just a VLM for understanding or a language-centric LLM.

MoT Architecture Divided into Reasoner and Generator

The architecture is divided into a Reasoner and a Generator[15]. The Reasoner operates like an autoregressive VLM, passing through a vision encoder and a language tokenizer[16]. The Generator uses a diffusion transformer to generate video, audio, and actions conditioned on the Reasoner’s features[17]. Similar to existing VLAs, causal self-attention operates in the front part, while full attention operates in the back part[18].

This differs from GPT-4-style structures that sequentially generate all tokens in a single stream[19]. The core is MoT, which separates parameters like WQ/WK/WV and MLP by modality and shares only information during the attention stage[20]. In output, autoregressive and diffusion modes can operate in parallel[21]. A method of keeping the language model fixed while sharing KV caches is also discussed[22].

It is also explained that COSMOS-3 does not start from scratch but begins from Llama 3 (needs verification)[23]. It is noted that starting with a vision-language model by tuning Llama 3 VL differently for each component is not a bad approach, as it leverages good priors[24].

Functionality as a World/Action Model and Unified Action Space

A world action model refers to the functionality of taking observations and outputting the next frame and action together[25]. Forward dynamics, which predicts future frames given an action as input, can also be viewed as one of its functions[26]. Inverse dynamics, which backtracks the corresponding action from a video, can also be defined within the same model[27].

The explanation is that by adjusting the noise handling method in diffusion, multiple tasks can be bundled into a single model[28]. The video also presents the perspective of viewing this model as a dataset generator rather than the policy itself[29]. Due to its omni-modal nature, it can be used to create datasets with desired inputs or for action polishing[30]. There is also a method of defining autonomous vehicle trajectories as actions[31].

Action representation is trending towards unification in SE(3)/SO(3) families, specifically camera-frame end-effector 3D poses and 6D rotations[32]. The cross-embodiment action space is nearly standardized[33]. This reduces dependence on specific robot morphologies, allowing joint motor commands to be recalculated via inverse kinematics[34]. It also provides a basis for co-training with robot hands by estimating hand poses and 6D rotations from human hand videos[35].

Lineage of Omni-modality: Chameleon, Transfusion, MoT

Early omni-modal approaches started with the Chameleon-style approach, which tokenized images using VQ-based methods and inserted them into LLM next-token prediction[36]. It was an attempt to treat text and images in the same discrete token space[37]. However, since images are continuous, converting them to discrete tokens caused problems where subtle changes were cut off into different tokens or grouped into the same token[38].

Consequently, Transfusion emerged, processing text autoregressively and images via diffusion/flow matching[39]. This was followed by a method that inputs noise in image token segments to generate patches with full attention, using Variational Autoencoders (VA) that create continuous embeddings instead of VQ-GAN[40]. The concern that vector spaces and parameters must be separated for each modality leads to MoT[41].

Asymmetry Between Understanding and Generation, and the World Model Debate

Flow matching performs velocity prediction[42]. It is repeatedly observed that using different encoder weights for understanding and generation is performance-beneficial[43]. Models where the encoder integration problem is not fully resolved are also mentioned[44]. In other words, while integrating understanding and generation into a single encoder may be a goal, current separation methods are more effective[45].

Analysis suggests that text has high learning efficiency because it is already an abstracted medium of human thought[46]. There is also analysis suggesting that the trend in the big tech industry is that raising intelligence through text reasoning is the most efficient[47]. Since images are not structured as a sequence of pixels, determining which visual signals to select for learning is a difficult problem[48].

It is also pointed out that visual intelligence does not easily emerge from just predicting the next video frame[49]. Therefore, negative forecasts even suggest that native JEPA-style world models without separate encoders are unlikely to succeed immediately[50]. However, it is mentioned that one must consider the speed of technological change, similar to how early LLM predictions were rapidly overturned after ChatGPT[51].

Practical Perspectives

What follows is analysis inferred from the video, not something the video states directly.

VLA Policy Structure and Action Representation

  • Reasoner/Generator separation and modality-specific parameter separation[52] → One can design a VLA that fixes or shares existing LLM/VLMs for language/vision understanding, attaching only action generation via a diffusion/flow head. In this case, learning rules can be established to share KV caches while freezing LM weights[53].
  • Camera-frame end-effector 3D pose and 6D rotation actions[54] → Robot arm data and human hand video data can be gathered into the same action space for co-training. Before actual control, a pipeline to convert joint commands via inverse kinematics is required[55].

World Model / World Action Model

  • Structure that outputs next frame and action together from observations[56] → By inputting candidate actions, future frames can be generated, creating an evaluation loop to estimate policy success or reward based on the results.
  • Defining forward/inverse dynamics in a single model via diffusion noise adjustment[57] → When robot data is scarce, action labels can be backtracked from human videos to augment training data, or generated rollouts can be used to select learning candidates.
  • Discussion on unifying per-robot frequencies and handling them with interpolation/smoothing, extending FPS as a time resolution[58][59] → If control frequencies differ per robot, instead of slicing data at a fixed Hz, one can decide on a pipeline that learns FPS as a continuous variable and performs interpolation/smoothing to match the target frequency during inference. Supporting various resolutions and time resolutions is an advantage of diffusion models over autoregressive models[60].

Robot Hands and Cross-Embodiment

  • 3D pose/6D rotation estimation from human hands[61] → Egocentric hand manipulation videos can be collected, hand poses estimated, retargeted to robot hand end-effector poses, and learned in the same action space.
  • Backtracking ego pose, which is camera movement[62] → In addition to hand movements, head/camera movements can be included as conditions or actions, allowing viewpoint changes to be represented alongside manipulation data.

Further Reading

  • It needs to be verified whether it truly lives up to the name “world model” and how well the precision of next-state prediction has been validated[63].
  • Corner cases and deployment constraints brought by initialization based on existing language models[64] must be checked before actual implementation.
  • When applying the unified action space to real devices, one should examine how inverse kinematics back-calculation[65] and per-robot frequency unification[66] affect control quality.
  • It is necessary to confirm how support for various FPS/time resolutions is implemented in actual training data and inference pipelines, and its consistency with fixed control cycles[67].
  • It is worth checking whether a universal reward/value model that takes V/VL as input to the action model and outputs scalar values can actually evaluate all tasks, examining evaluation criteria and data bias[68][69].
  • Further verification is needed on how empirically validated the superiority of text abstraction and negative forecasts for JEPA-style world models are, and on the limitations of next-frame prediction experiments[70][71].
