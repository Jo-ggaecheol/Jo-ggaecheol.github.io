Key Takeaways

  • Gemini’s “Argon” demonstrated top-tier performance in LLM-based robot control benchmarks, successfully completing 36 out of 78 tasks, surpassing Opus (21) and Astra (24). It also showcased zero-shot control in real-world environments and self-improvement loops incorporating human feedback[1][2][3].
  • Real-to-Sim automation and system identification (estimating physical properties such as gain, damping, and friction coefficients) are considered bottlenecks in robotics research. AI performing these processes is expected to accelerate research[4][5].
  • Methods where LLMs directly output end-effector coordinates or joint values, along with cloud inference, suggest the possibility of a “dark factory” setup where a single server controls factory robots[6][7][8][9].

Summary

Technical Shift in LLM-Based Robot Control

Previously, models like RT-1, RT-2, and OpenVLA showed low performance even when fine-tuned with discrete action tokens. However, the current approach of having LLMs output coordinate values as text tokens and solving Inverse Kinematics (IK) to control robots has proven effective[10][11]. Argon can directly output not only end-effector coordinates but also joint values (Q-pose) for specific robot bodies[12]. In the simulator’s 78 high-difficulty tasks, Argon achieved the highest success rate with 36 successes, compared to 21 for Opus and 24 for Astra[13].

In the RoboCove benchmark, Argon offers the highest performance at a relatively low cost but is slower in speed. Astra is fast but expensive, while Opus occupies a middle position[14]. In real-world environments, robots can be controlled zero-shot by providing only visual coordinates; Spot autonomously performed a mobile balancing task of placing a can into a trash bin[15][16]. Specific robot models like YAM are included in the training data, potentially enabling more precise control. Furthermore, in unseen environments, state-of-the-art LLMs demonstrate generalization by adjusting joint values to grasp objects based solely on specifications[17][18].

Real-to-Sim Automation and Self-Improvement Loops

In Real-to-Sim, simulations are reproduced based on actual teleoperation videos, after which physical properties such as gain, damping, and friction coefficients must be matched[19][20]. This property matching process is known as system identification and is considered the most tedious manual labor even among robotics researchers[21]. Since AI can perform the iterative process of checking discrepancies between simulation and real-world movement and adjusting values, it is expected to accelerate robotics research[22][23].

In the folk game throwing demo, after demonstrating human movements, a Real-to-Sim environment was built, and the AI calculated friction coefficients and other parameters to learn by running loops in the real-world environment[24][25]. The AI repeatedly made the mistake of hitting its thigh but showed a self-improvement process after receiving human feedback (“hits the thigh”). After several loop iterations, it achieved 7 consecutive successes[26][27]. If Real-to-Sim becomes easier, handling deformed objects may become possible. Furthermore, if a self-loop is formed, there is potential to solve difficult physics problems such as fluid simulation[28][29].

Cloud Inference and Hybrid Control Structures

LLM-based robot control may be enabled through cloud inference rather than edge devices, overturning the existing notion that physical intelligence must be processed locally[30]. Unlike autonomous driving, which is processed on the edge using Tesla hardware, LLM-based robot control can be executed in the cloud and could potentially be applied to autonomous driving in the future[31]. In the concept of a “dark factory,” a single cloud inference server controlling all robots in a factory enables more perfect control[32].

WAMs like Dream-1 exhibited hand tremors during movement, while LLM-based models tend to have the non-active hand remain completely still[33]. Although Dream-1 is fast, LLM-based structures are slow due to repeated calls and movements, currently limiting their use in tasks requiring precise manipulation or quick responsiveness[34]. The core capability of LLMs is reasoning independently to manipulate unseen objects[35]. Research is ongoing to combine both approaches, such as passing WAM outputs to Argon for correction or using VLA to control drift. A hybrid structure is expected to emerge in the future[36][37][38].

Integration of Heterogeneous Sensor Modalities

Sensor values other than vision and text, such as tactile data, are difficult to integrate due to their variety in type, dimension, count, and format[39][40]. Even if hardware is heterogeneous, such as Company A’s vision-based tactile sensor and Company B’s pressure-based tactile sensor, LLMs can perform tasks well when provided with characteristic description manuals and few-shot samples[41]. Therefore, it is expected that modalities other than vision/text can be processed simply by informing the agent how to interpret sensor signals[42].

Application Perspectives

What follows is analysis inferred from the video, not something the video states directly.

VLA (Vision-Language-Action)

  • Redesigning Action Representation: Compare output methods such as 6-DoF end-effector, joint values (Q-pose), and action chunks (jchunk) per task[43][44][45]. A hybrid architecture can be designed that prioritizes low-level policies for complex contact dynamics like opening drawers, and LLM reasoning for simple manipulations[46][47].
  • Data Generation Pipeline: Slow LLMs like Argon can be run offline to pre-generate VLA training datasets within simulations for fast model learning[48][49]. However, since it remains uncertain whether desired task levels can be achieved without teleoperation data, initial validation could start with teleoperation-assisted data[50][51].

World Model / World Action Model

  • Reducing Sim-to-Real Gap: Build a system identification module where AI iteratively estimates physical properties such as gain, damping, and friction coefficients in Real-to-Sim[52][53], and apply a workflow to verify discrepancies between simulation results and real-world movements[54].
  • Utilizing Policy Correction Tools: Prototype implementations can be developed to pass fast inference results from WAMs like Dream-1 to LLMs for correction, or to control drift using VLA[55]. Experiments combining LLM and VLA, similar to speculative decoding, to improve robot control efficiency are also possible[56].

General Robotics

  • Cloud-Based Swarm Control: Build a “dark factory” prototype where a single cloud inference server distributes tasks among multiple robots in a factory, and compare latency caused by repeated LLM calls/movements with control trajectory quality[57][58][59].
  • Heterogeneous Sensor Integration: Define an interface that injects manuals and few-shot samples of hardware with different dimensions, counts, and formats (like vision-based vs. pressure-based tactile sensors) into prompts, and accumulate success/failure cases of agents interpreting sensor values[60][61].

Further Reading

  • Practical Significance of Benchmark Scores: Further verification is needed on how well scores from BenchCAD or the Artificial Analysis Index correlate with actual spatial understanding or robot manipulation capabilities. Specifically, how to correct for the “benchmark maxing” effect, where models released after the benchmark becomes public gain an advantage, requires additional investigation[62][63].
  • Concrete Implementation of Tactile Sensor Integration: The claim that LLMs interpret tactile data is based on providing manuals and few-shot learning[64], but latency and compatibility issues in processing heterogeneous sensor data streams within real-time control cycles were not sufficiently addressed in the video.
  • Verifiability in RL Environments: It is unclear whether Argon’s performance improvement stems from pre-training or RL[65]. Building a verifiable self-improvement environment was mentioned as a key bottleneck for RL[66]. While possessing an in-house simulator was noted as advantageous[67], no specific methodology or success cases for actually implementing this were presented.
