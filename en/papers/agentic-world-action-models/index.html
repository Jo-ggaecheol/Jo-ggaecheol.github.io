Agentic World Action Models

AW-0 is an agentic world action model that jointly denoises skill programs, future video, and robot actions within a mixture-of-transformers architecture. An automated curation pipeline annotates robot and human demonstrations with reusable skill programs, improving bimanual manipulation performance over VLA and WAM baselines.

TL;DR

Existing World Action Models (WAMs) provide visual predictions but lack an explicit mechanism for compositionally combining reusable skills, while agentic robotic systems offer reusable skills but lack predictive grounding in physical dynamics. AW-0 integrates these two approaches into a single generative process by simultaneously denoising code, video, and actions within a Mixture-of-Transformers (MoT) architecture. On RoboTwin 2.0 and real-world bimanual manipulation tasks, AW-0 demonstrates improved results in task performance, language following, semantic reasoning, and robustness compared to VLA and WAM baselines.

Problem Definition

Learning-based robotic manipulation has evolved from small-scale, task-specific visuomotor policies to broadly supervised foundation models that connect cognition, language, and action. WAMs combine visual prediction with visuomotor policies to provide physical grounding for control. However, predicted videos and action chunks alone do not specify long-horizon task decomposition. They do not explicitly state which reusable skills to invoke, how to parameterize them, or how to compose them across subtasks. Furthermore, world and/or action prediction can be computationally expensive, making it difficult to set limits on the degrees of freedom that need to be modeled by the world model.

In contrast, agentic robotic systems provide a programmatic harness for selecting reusable skills and tools, binding them to the current scene, tracking progress, and replanning when observations change. This programmatic representation explicitly structures multi-step tasks. However, agentic robotic systems often lack predictive grounding in actual physical dynamics and do not leverage learned models of how the world changes as the robot executes actions.

Core Idea

AW-0 is based on the perspective that code serves two complementary roles. First, code structures multi-step prediction and control within a WAM. Second, code represents skills as reusable programs for subsequent agentic execution. To integrate these two roles into a single generative process, AW-0 simultaneously denoises a code token sequence C0C_0C0​, VAE-encoded video latent variables Z0Z_0Z0​, and action chunks A0A_0A0​ using a conditional generative model pθ(C0,Z0,A0∣Ct)p_\theta(C_0, Z_0, A_0 \mid \mathcal{C}_t)pθ​(C0​,Z0​,A0​∣Ct​) within the MoT architecture. Mixture-of-Transformers Architecture

AW-0 adopts an MoT architecture consisting of three experts: skill planning, future visual prediction, and continuous control. Each expert has its own attention projections (WQ,WK,WV,WO)(W_Q, W_K, W_V, W_O)(WQ​,WK​,WV​,WO​), layer normalization, and feed-forward network (FFN), communicating via masked joint attention across all transformer layers. The attention mask structure is bidirectional within each expert and blockwise causal in the order code → video → action between experts.

The Code Expert augments the SDAR-1.7B backbone, using a frozen Qwen3-VL Vision Transformer (ViT) to encode current multi-view observations into visual tokens placed before the instruction and program tokens. It adopts LLaDA-style masked-token diffusion. The Video Expert uses a video Diffusion Transformer (DiT) initialized from Cosmos-Predict2.5-2B, conditioned on observation frames to model VAE-encoded future frames. The Action Expert generates continuous action chunks using a separate Action DiT initialized from scratch. Both experts receive language embeddings via cross-attention, and the Action Expert additionally receives robot state conditioning. All experts have 28 transformer layers, with queries, keys, and values projected into a common 2,048-dimensional attention space.

Automatic Annotation Pipeline

We propose a three-stage pipeline to annotate training data with skill planning code. First, one episode is sampled from each task, and Gemini 3.1 Pro writes subtask-level skill programs against a pre-defined declaration-only API, while Claude Code (Claude Opus 4.8) acts as a coordinator to extract iterative and task-agnostic skills. Second, the skill library is frozen, and sampled episodes are re-annotated with the finalized vocabulary to form a cache of reusable subtask-program mappings. Third, when annotating the remaining corpus, cached programs are reused if the contact and motion patterns of a subtask match existing entries; otherwise, the coding agent generates new annotations and adds them to the cache.

Memory Cache and Hybrid Action

Since a single observation is often insufficient to reveal task progress, the Code Expert receives a compressed cache of slices generated so far. History slices are compressed into KKK learnable memory slots and read as prefix tokens before the prompt in the code stream.

During inference, we explore a hybrid action mode. Decoded code slices are executed against a library of perception and control primitives in the style of Code-as-Policies (CaP), and the executed actions are integrated with direct actions from the Action Expert. At deployment, the two channels are coordinated at each replanning point; the decoded slice is only adopted for the current step if it passes validity and progress checks. Otherwise, the action chunk from the same forward pass drives the robot until the next replanning point.

Experimental Results

AW-0 is evaluated on the RoboTwin 2.0 benchmark and real-world bimanual manipulation tasks. The pre-training corpus is the union of YAM (73,101 episodes, 279 tasks, 1,919.3 hours) and egocentric human data (175,541 episodes, 327 tasks, 993.9 hours), totaling 248,642 episodes and 2,913.2 hours. The YAM skill library is frozen with 23 skills, and the egocentric human skill library is frozen with 27 skills.

On RoboTwin 2.0 and real-world tasks, AW-0 demonstrates improved results in task performance, language following, semantic reasoning, and robustness compared to standard VLA and WAM baselines.

Limitations

The authors specify the following limitations.

First, program grounding and skill coverage: Since the code stream is trained on automatically annotated demonstrations and a curated skill library, planning quality depends on annotation accuracy and skill coverage. Generated programs may include incorrect arguments even if they select appropriate skills, and syntactic validity alone does not guarantee correct execution.

Second, predictive robustness and hybrid execution: While structured planning improves WAM performance, it does not eliminate sensitivity to visual distribution shifts. Hybrid execution improves robustness under RoboTwin randomization but decreases performance in clean settings. This reflects the reliability of basic primitives and the limitation of selecting code based solely on validity without estimating superiority over action chunks.

Third, towards persistent agentic learning: Real-world hybrid evaluation is limited to the YAM platform due to the absence of a code-policy system for dexterous hands. The current system does not learn online from its own interactions.

Critical Review

Strengths

  • Clear formulation integrating a Code Expert into WAM — Combines code-based planning with video-action prediction in World Action Models (WAMs) into a single Mixture-of-Transformers (MoT) generative process, defining conditional generation and joint denoising mathematically to make the contribution concrete (Evidence: Sec 3.1 Eq.1-2, Sec 3.2, Appendix A.1).
  • Procedurally detailed skill library and annotation pipeline — Presents declaration-only APIs, annotator/coordinator prompts, frozen skill libraries, cached reuse, and skill examples together, demonstrating the procedure for extracting reusable skills (Evidence: Sec 3.4, Appendix K.1-K.2, Table 8-9, Figure 9-18).
  • Pre-training data scale and skill structure reported numerically — Organizes episode counts, hours, and skill numbers for YAM and egocentric human data, and visualizes per-skill distributions in embedding space to provide qualitative evidence that skill labels can distinguish motion (Evidence: Sec B.1 Table 7, Sec B.5 Figure 18-19).
  • Transparent presentation of hybrid execution tradeoffs — Reports step shares for code execution and direct action by clean/random success/failure, acknowledging performance drops in clean settings and validity-only arbitration limitations to prevent over-generalization of conclusions (Evidence: Table 12, Sec L.2).

Weaknesses & Questions

  • Quantitative evidence for core performance improvement claims is not confirmed in the provided excerpts — The Abstract and Introduction claim improvements in task performance, language following, semantic reasoning, and robustness compared to VLA/WAMs, but Table 1 body text, baseline implementation details, and statistical significance values from repeated runs are not provided (Evidence: Abstract, Sec 2.5, Appendix C exists only as a table of contents, Table 1 is referenced only).
  • No separate ablation visible showing whether the Code Expert actually improves action prediction — While it is described that the code stream supplies planning context to video/action denoising, component-wise performance comparisons such as removing the Code Expert, varying skill library size, or removing hybrid arbitration are absent from the provided excerpts, leaving causal effects unclear (Evidence: Sec 3.3, no ablation evidence in provided excerpts; Appendix F/G/H exist only as table of contents).
  • Impact of annotation accuracy and skill coverage is not quantified — Programs are generated using Gemini/Claude-based annotators and static validation, but annotation error rates, examples of insufficient skill coverage, and their relationship to downstream failures are not reported numerically, limiting confidence in planning quality (Evidence: Sec 3.4, Appendix K.2, Sec L.1).
  • Generalization scope may be read broader than evaluated embodiments/tasks — Pre-training uses two sources (YAM and egocentric human), and real-world hybrid evaluation is limited to the YAM platform due to the absence of code-as-policy for dexterous hands; however, the Introduction’s claim of compositionality across distinct environments/tasks is not sufficiently supported by the provided results alone (Evidence: Sec B.1, Sec A.8, Sec L.3, Sec 2.5) (interpretation).
  • Benefits of hybrid execution are conditional and the code channel share is small — Code execution is only 8.5% in Clean/All and 5.6% in Random/All, and it is acknowledged that hybrid reduces performance in clean settings; thus, the conclusion of improved robustness can be interpreted as limited to successful episodes under randomization (Evidence: Table 12, Sec L.2) (interpretation).

Reproducibility

  • The provided excerpts do not specify whether code, data, or checkpoints are publicly available, and key information necessary for reproduction is missing, including baseline implementations (Appendix C), real-world setups (D/E), hybrid algorithms (I), and annotation details (K). Deterministic reproduction conditions for the LLM annotator and skill library generation process are unclear (Evidence: no availability info in provided excerpts; Appendix CONTENTS, K.2) (interpretation).
