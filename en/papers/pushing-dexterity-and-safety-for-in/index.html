Pushing Dexterity and Safety for In-Hand Object Pose Reaching That Works Remarkably Well

We present a sim-to-real recipe for training in-hand object pose reaching policies on a multi-fingered hand at arbitrary wrist orientations and transferring them zero-shot to the real hand. A learned residual safety filter is added to tune performance-safety trade-offs and substantially reduce object drops, with extensive real-robot evaluation.

Ian Chuang, Hiya Shah, Vamsi Chilamkur, Iman Soltani, Claire Tomlin, arXiv, 2025

TL;DR

  • We addressed the problem of continuously moving an in-hand object from an arbitrary wrist orientation to unverified goal poses while minimizing drops.
  • We combined privileged observation learning in simulation, DAgger distillation, adaptive curriculum, and a ResSafe residual safety filter to achieve zero-shot transfer to a real LEAP hand.
  • In evaluations on 4,800 goals with the real robot, the state policy achieved coarse success rates in the mid-90s%, and the safety filter reduced drops by 75%.

Problem Definition

Existing research on in-hand object manipulation has largely been limited to single wrist orientations, particularly palm-up poses. Furthermore, it has focused primarily on simple rotations or repetitive motions and has not sufficiently addressed safety, specifically drop prevention, which is critical for real robots. This paper addresses the problem of executing continuous goal sequences that move an object to nearly any position and orientation within the finger reach range, regardless of the wrist orientation.

General objects target a full SE(3)SE(3)SE(3) pose (p∗,R∗)(p^*, R^*)(p∗,R∗). Rotationally symmetric objects like lightbulbs or wineglasses specify only the position p∗p^*p∗ and the target axis direction z∗z^*z∗. The errors are defined as follows:

Core Idea

The core intuition is to “learn using only realistically graspable grips, distill into a deployable policy, and apply a safety filter that makes small corrections only when there is danger.” Instead of sampling goals uniformly across the entire SE(3)SE(3)SE(3) space, we extract initial states and goals from an offline-generated grasp dataset to improve learning efficiency. In simulation, we train a teacher policy with privileged information using PPO, then distill it into a state student (for real-world deployment) and a depth student (which sees only the depth camera) via DAgger. Subsequently, we add a ResSafe residual safety filter on top of the frozen task policy to restrictively correct the nominal action when drop risk increases. This structure bundles sim-to-real transfer, visual input diversity, and the safety-performance trade-off into a single pipeline.

Methodology

Robot System and Simulation

The hardware uses a LEAP hand and a UR5 arm. We redesigned the palm mount to stabilize the thumb base joint of the LEAP hand. The actuators are 16 Dynamixel XC330 servo motors, using internal position controllers to send joint position targets at 20 Hz. The fingertips have a layer of high-friction 3M grip tape attached to hard 3D-printed plastic, while the rest is low-friction plastic. The UR5 sets and measures the wrist orientation (i.e., gravity direction), but the policy controls only the hand, not the arm.

There are two types of visual inputs. The state policy tracks the object’s 6D pose and hand markers using OptiTrack motion capture. The depth policy uses an Orbbec Gemini 305 stereo camera mounted on the wrist, computing depth at 30 Hz with Fast FoundationStereo and downsampling to 160×120160 \times 120160×120.

For sim-to-real transfer, we performed system identification. Instead of simple PD control, we used the BAM (Voltage-driven DC Motor Model) for the actuator model. We fitted parameters using data from a single servo pendulum test bench and applied them to all 16 actuators. Latency was also measured and corrected by replaying identical joint trajectories on both the real hand and in simulation. Using the identified models and latency, joint positions and depth images in simulation closely match those of the real robot.

The simulator runs with GPU acceleration using mjlab-based MuJoCo Warp. The physics engine operates at 120 Hz, while the policy runs at 20 Hz. The arm is not simulated; the hand is fixed in free space, and a random wrist orientation is used for each episode. Collision meshes are created by decomposing each object into convex parts using CoACD.

Goal/Initial State Generation and Learning Environment

Goals and initial states are sampled from a generated grasp dataset rather than uniform SE(3)SE(3)SE(3) sampling. We generate 100,000 grasps per instance using LightningGrasp, expand them to 500,000 using DexterityGen’s RRT method, and then remove collision-penetrating grips. Finally, 422k–453k grasps remain per object. During reset, a random grasp is selected from the dataset, and the wrist orientation is sampled from a uniform SO(3)SO(3)SO(3) distribution. Episodes end upon a 20-second timeout or if the object falls more than 0.5 m from the hand.

The goal completion condition during learning requires that position/pose error and rotational velocity (twist) error are within tolerance, and that the hold counter reaches the required value. Rotational velocity is smoothed with a low-pass filter.

Task Policy Learning Pipeline (A1–A4)

The task policy is learned in four stages, from A1 to A4.

  • A1: Train a teacher policy with privileged observations using PPO. The critic has an asymmetric structure using additional information such as friction coefficients, goal state, and hold progress.
  • A2: Distill into a deployable state student πs\pi^sπs using DAgger. This policy uses observations available in the real world without privileged information.
  • A3: Fine-tune the A2 state student with PPO.
  • A4: Distill into a depth student πd\pi^dπd that sees only the depth camera using DAgger. The depth encoder combines CNN, spatial softmax keypoints, and channel averaging, and is trained with an auxiliary object-pose head loss.

Safety Filter (B1–B2)

The safety filter is added while keeping the task policy frozen.

  • B1: Train a ResSafe residual safety filter on top of the A3 state policy. It takes the nominal action and correction penalty weight www as inputs, using an L2 correction penalty by default. Noise is added to the nominal action during training to prevent the filter from becoming overly conservative.
  • B2: Distill the state-based safety filter into a filter that sees only the depth camera. This step connects to the A4 depth policy, allowing the task policy and safety filter to be used with either motion capture or the wrist camera alone.

Experimental Results

The main real robot evaluation used four configurations: combinations of state/depth policies with and without the ResSafe safety filter (w=0.5w=0.5w=0.5). The objects were a lightbulb, rubber duck, knife, and wineglass, with six wrist orientations. There were 96 runs in total, each executing 50 consecutive goals in a 10-second window, evaluating a total of 4,800 goals over approximately 13.3 hours. All configurations attempted the same sequence from the same held-out 100,000 grasp dataset. The state policy was provided with object pose inputs, while the depth policy used only the wrist camera. In the main evaluation, the lightbulb twist command was fixed at 0.

Here, coarse success means reaching within 2 cm and 0.4 rad, while precise success is calculated with stricter tolerances. Applying the safety filter to the state policy reduces the coarse success rate from 95.2% to 91.5% and the precise success rate from 75.6% to 67.2%, but drops decrease from 16 to 4, and the time to the first drop increases. For the depth policy, the filter also reduces drops at the cost of some performance. Excluding the wineglass, drops for the depth policy decrease from 37 to 6.

Per-object results for the depth policy differed from simulation. The lightbulb and rubber duck had coarse success rates of approximately 95% and 88%, respectively, similar to simulation. However, large gaps appeared for the knife (real 54% vs. sim 90%) and wineglass (real 50% vs. sim 84%). The wineglass experienced 51 drops out of 300 goals. This gap is explained by long tails in the depth-based auxiliary pose estimation error.

In additional comparisons, the real robot success rates for the knife, lightbulb, and rubber duck were higher than in simulation, while the wineglass was approximately 89% in both. Drop rates were lower in reality (0.7–2.3%) compared to simulation (3.7–9.1%). The paper attributes this difference to the use of random wrist orientations, goals within the learning distribution, and strong domain randomization in simulation versus limited wrist orientations and unverified goals in real evaluation.

In out-of-distribution (OOD) high-difficulty goal experiments, grasps were generated inside a box 1.5 times larger than the original. For palm-down orientation with the state policy, coarse success rates ranged from 56% to 84% per object (28–42 out of 50). With the filter, it was 19–39. Drops occurred only for the wineglass, with 2 instances regardless of filter usage. This shows that the nominal policy operates relatively safely even on OOD goals and that the safety filter is advantageous for correcting sudden drops.

The lightbulb spinning test was performed with the depth policy, axis goals, and twist commands of ±1\pm 1±1 rad/s. Fifty goals each were evaluated for palm-up and palm-down orientations. Without the filter, coarse reaches were 46 (up) and 44 (down), with average spins of 1.24 and 0.63 turns, respectively. With the filter, reaches were 43 and 41, and average spins decreased to 0.74 and 0.36 turns, but there were no drops. Palm-down was significantly harder, which is interpreted as a potential hardware limitation.

In the large arm movement rotation experiment, the UR5 wrist tracked a sinusoidal trajectory with max ±85∘\pm 85^\circ±85∘ and peak 2.75 rad/s while rotating the lightbulb and rubber duck for 30 seconds. Without the filter, 32 out of 40 were maintained; with the filter, 38 were maintained. However, in high lightbulb goals, the filter stopped rotation in 3 out of 10 cases.

Downstream tasks using only the wrist camera without motion capture were also evaluated. Wineglass flipping, lightbulb lighting, and rubber duck standing were performed with hardcoded arm movements, using a filter with w=1.5w=1.5w=1.5. Results decreased compared to no filter: wineglass 7/10 → 6/10, lightbulb 4/5 → 3/5, rubber duck 7/10 → 3/10. The paper analyzes this as being contributed to by out-of-distribution learning and script failures.

In ablations, the curriculum had a significant impact on A1 learning. The friction curriculum increased goals per episode by 15–64% for the lightbulb and rubber duck, and the goal+friction curriculum was top-performing for three objects. The wineglass was an exception, with 2.74 goals/episode without curriculum versus 2.20 with it. Privileged actor observations were also important. In knife A1 learning, privileged actor observations were essential for performance improvement compared to an actor seeing only the student’s noise/latency observations.

In ResSafe penalty ablations, the default L2 had a coarse success rate of 80.4% and a drop rate of 3.8%. L1 reduced the drop rate to 1.3% but sharply decreased the coarse success rate to 21.7%. L2 without nominal action noise was similar to the default at 78.6% and 2.5%. During B1 training, all three variants had similar unsafe episode rates, but L1 excessively suppressed the task, reducing the number of completed goals.

Limitations

  • Policies are learned per object. Multi-object generalization, where a single policy handles multiple objects simultaneously, is not yet resolved.
  • A depth-based sim-to-real visual gap remains for the knife and wineglass. Long tails in auxiliary pose estimation error are cited as the cause, requiring more accurate depth sensing system identification or stronger visual augmentation/domain randomization.
  • 100% success rate was not achieved. Future goals include developing multi-object policies and generalized safety filter recipes.

Critical Review

Strengths

  • Sufficiently large and controlled real robot evaluation — Comparing zero-shot transfer and safety claims is supported by 4 objects, 6 wrist orientations, 96 runs, 50 goals per run, and a total of 4,800 held-out goals using identical sequences (Evidence: Section VI-B, Table II, Fig. 7).
  • Quantifies both benefits and costs of the safety filter — Applying the ResSafe residual safety filter reduces state policy drops from 16 to 4 while coarse success only drops from 95.2% to 91.5%; depth policy drops also decrease from 88 to 46 (Evidence: Table II).
  • Tracks sim-to-real gap via system identification and visual error analysis — Shows that simulation/real joint/depth images match after BAM actuator model and latency correction, and separately explains long tails in depth pose errors for knife/wineglass (Evidence: Appendix B, Fig. 16, Appendix K.1/Fig. 26).

Weaknesses & Questions

  • Lack of external baseline comparisons makes contribution magnitude unclear — The provided notes only include ResSafe on/off and HJ filter sweeps, with no direct comparison evidence against other in-hand manipulation or safety filter methods (Evidence: Table II, Table IX; no external baseline reports in provided notes) (Interpretation).
  • Limited information on statistical significance and repeated runs — Deployment policies are reported as single-run results, ablations are limited to 3 seeds for some and 1 seed for others, and variance/significance tests for the 96 real robot experiments are not in the notes (Evidence: Appendix H, Table II).
  • “Arbitrary wrist orientation” generalization claim is broader than actual evaluation scope — Learning/simulation uses uniform SO(3)SO(3)SO(3) wrist orientations, but main real robot results are limited to 6 wrist orientations, and OOD goal tests are reported primarily for palm-down state policy (Evidence: Section VI-B, Fig. 7, Table X) (Interpretation).
  • Safety filter does not always improve both performance and safety — In downstream tasks, duck success drops from 7/10 to 3/10 with the filter, and in high lightbulb goals during large arm movements, the filter stops rotation in 3 out of 10 reported cases (Evidence: Table XIV, Table XIII).
  • Generalization evidence for depth policy is weak for knife/wineglass — Depth policy coarse success is 71.8% and precise success is 38.3%; for knife/wineglass, long tails in auxiliary pose estimation error widen the sim-to-real gap, making conclusions prone to being centered on lightbulb/duck (Evidence: Table II, Fig. 26, Appendix K.1) (Interpretation).

Reproducibility

  • The provided notes do not specify code/data availability. While hyperparameters (Table VII/VIII), training time (Appendix H), and hardware/depth pipeline (Appendix A/B) are detailed, it is difficult to guarantee full reproducibility based solely on the single seed of deployment policies and the actual availability of the held-out 100k grasp dataset.
