Vision-Language-Action or World-Action? Just Action Models

We propose Just Action Model (JAM), which separates backbone initialization, future-observation objectives, and inference modules, using an action loss plus a foresight loss that predicts frozen future representations without visual generation. JAM matches or outperforms FastWAM/ImageWAM on LIBERO/LIBERO-Plus/RoboTwin and reduces estimated online training FLOPs by 73% for FastWAM with cached targets.

Yonghao Yu, Runyi Li, Lang Huang, Toshihiko Yamasaki, arXiv, 2026

TL;DR

  • Just Action Model (JAM) disentangles three distinct choices that distinguish Vision-Language-Action (VLA) models from World-Action Models (WAM): backbone initialization, the objective function applied to future observations, and the inference module.
  • It introduces a foresight loss using a training-only frozen future anchor to enable current features to predict future representations, discarding this branch during inference.
  • Under identical conditions, JAM improves LIBERO-Plus performance by up to 14.7%p compared to WAMs and reduces online FLOPs by up to 73% when using cached targets.

Problem Definition

The VLA and WAM communities have debated whether the source of pre-trained knowledge for robotic control policies should be vision-language models or visual generators. However, existing discussions compress three actually independent choices into a single dichotomy.

First, backbone initialization. Second, the objective function applied to recorded future observations. Third, the machinery retained at inference. VLAs typically use only an action flow matching loss, while WAMs add a visual generation loss. Some WAMs also feed generated future observations back into the action expert.

The problem this paper addresses is evaluating these three choices separately. JAM investigates whether future observation information can improve policy representations without visual generation, and whether this improvement persists without increasing inference costs.

Core Idea

JAM’s intuition is to “train features to predict the future without generating it.” During training, recorded future observations are encoded as a frozen future anchor, and a small prediction head is attached so that policy features derived from current observations can predict these future representations. This supervision uses a cosine-similarity-based foresight loss in representation space, rather than a generative loss that reconstructs visual pixels.

The core objective function is as follows:

LJAM=Lact+λFLF\mathcal{L}_{\mathrm{JAM}} = \mathcal{L}_{\mathrm{act}} + \lambda_{\mathrm{F}} \mathcal{L}_{\mathrm{F}}LJAM​=Lact​+λF​LF​

Here, Lact\mathcal{L}_{\mathrm{act}}Lact​ is the action generation loss, and LF\mathcal{L}_{\mathrm{F}}LF​ is the foresight loss. After training concludes, the future anchor branch and prediction head are removed, leaving only the backbone and action expert for deployment.

Methodology

Problem Formulation

A data sample consists of the current observation f0f_0f0​, robot state s0s_0s0​, instruction ccc, action chunk a1:Ha_{1:H}a1:H​, and recorded future observations f1:Tf_{1:T}f1:T​. The deployment interface predicts a1:Ha_{1:H}a1:H​ from f0,s0,cf_0, s_0, cf0​,s0​,c.

The difference between VLAs and WAMs can be summarized by the objective function regarding future observations. VLAs use only the action loss, while WAMs add a visual generation loss. JAM uses a foresight loss instead of both, performing no visual generation during either training or inference.

Foresight Supervision

The visual backbone encodes f0f_0f0​, and if text conditioning is supported, it also utilizes ccc. The action expert takes as input the visual context, ccc, s0s_0s0​, and the noised action chunk a~1:H\widetilde{a}_{1:H}a1:H​.

Let the current observation tokens from the ℓ\ellℓ-th block of the backbone be denoted as h(ℓ)∈RN×D\mathbf{h}^{(\ell)} \in \mathbb{R}^{N \times D}h(ℓ)∈RN×D. The frozen future anchor EφE_{\varphi}Eφ​ processes the recorded future f1:Tf_{1:T}f1:T​ and produces target features gk∈RN×Dg\mathbf{g}_k \in \mathbb{R}^{N \times D_g}gk​∈RN×Dg​ corresponding to readout offset kkk. A learnable prediction head ppp maps policy tokens h(ℓ)\mathbf{h}^{(\ell)}h(ℓ) to the target space, generating g^k\hat{\mathbf{g}}_kg^​k​.

The foresight loss is defined as:

LF=1∣K∣∑k∈KEn[1−cos⁡(g^k,n,sg⁡[gk,n])]\mathcal{L}_{\mathrm{F}} = \frac {1}{| \mathcal {K} |} \sum_ {k \in \mathcal {K}} \mathbb {E} _ {n} \left[ 1 - \cos \left(\hat {\mathbf{g} } _ {k, n}, \operatorname{sg} [ \mathbf{g} _ {k, n} ]\right) \right]LF​=∣K∣1​k∈K∑​En​[1−cos(g^​k,n​,sg[gk,n​])]

Here, K\mathcal{K}K is the set of supervised offsets, nnn is the spatial token index, and sg⁡\operatorname{sg}sg denotes stop gradient. Gradients are not propagated to the target features.

Offset [0] refers to the current position, while [1] and above refer to future positions. In FastWAM-style models, four environment steps are grouped into a single VAE latent position, so [1] corresponds to steps 4–16, and [2] corresponds to steps 20–32. Other backbones typically use a single frame 16 steps ahead as [1].

Implementation by Pre-training Family

  • Generator-based: Can utilize Wan2.2-5B, Yak18/Ovis-U1, or FLUX.2 families. In JAM, the backbone sees only clean current frames, and the future anchor can be replaced with a pre-trained VAE or a randomly initialized backbone.
  • Self-supervised: DINOv2-B/L does not use language inputs or generation heads. The action expert mirrors the backbone transformer blocks, and a separate text encoder provides instruction features.
  • Vision-Language Model (VLM): Qwen3.5-2B processes images and text simultaneously. The action expert mirrors backbone blocks and uses causal token mixing for image, text, and action tokens.

Training Cost and Deployment

After training, the anchor branch and prediction head are removed. During deployment, the backbone encodes f0f_0f0​ and ccc once, and the action expert reuses this context during flow matching sampling steps.

Caching foresight targets reduces online training computation. Specific reductions are detailed in the experimental results.

Experimental Results

Benchmarks include LIBERO (Spatial, Object, Goal, Long), LIBERO-Plus, and RoboTwin 2.0. LIBERO involves 40 tasks with 50 rollouts each. LIBERO-Plus follows ImageWAM’s 15% subset protocol, fixing seeds per suite to evaluate 1,506 perturbed task manifests once each. RoboTwin 2.0 uses 50 bimanual manipulation tasks in clean/randomized settings. Compared policies share data, policy architecture, optimizer, training budget, and evaluator.

For LIBERO, FastWAM recipe (20k updates, batch size 128) and ImageWAM recipe (21.7k updates, batch size 128) are used. For RoboTwin 2.0, FastWAM (5 epochs, 29,355 updates, batch size 1,024) and ImageWAM recipe (69,900 updates, batch size 384) are used.

Critical Review

Strengths

  • Conceptual clarification separating VLA/WAM into three independent variables — Distinguishes backbone initialization, future observation objective function, and inference-retained modules, presenting JAM as a common framework to reduce confusion in existing debates (Evidence: Figure 1, Section 2.1).
  • Controlled comparisons and extensive ablations — Compares FastWAM/ImageWAM baselines with JAM under identical data, policy architecture, and training budgets, verifying anchor initialization, readout depth, loss weight, prediction-head capacity, action-only control, shared weights, and training budget (Evidence: Section 3.2, Appendix C Table 10–16).
  • Statistical significance and inter-run variance reporting for key results — Reports JAM superiority on LIBERO/LIBERO-Plus using bootstrap confidence intervals and McNemar tests, providing mean ± standard deviation for three independent runs (Evidence: Appendix D Table 20, Table 21).
  • Quantification of training cost reduction — Measures FLOPs and GPU time compared to baselines when using cached foresight targets, supporting efficiency claims with numerical data (Evidence: Appendix B Table 9).

Weaknesses & Questions

  • Limited real-world/open-world generalization — Experiments focus on LIBERO, LIBERO-Plus, and RoboTwin 2.0 simulations; scalability to physical robots or more diverse tasks/environments is not confirmed in the provided notes (Evidence: Section 3.1, Table 4–6) (Interpretation).
  • Lack of direct comparison with alternative VLA/WAM methods — While comparing FastWAM/ImageWAM recipes, no table directly compares other representative policies like π0\pi_0π0​/π0.5\pi_{0.5}π0.5​ or V-JEPA 2-AC mentioned in Appendix E under identical conditions is present in the provided notes (Evidence: Appendix E, Table 4–6) (Interpretation).
  • Inconsistent gains across all backbones/perturbation categories — Category-wise analysis of LIBERO-Plus shows baseline superiority in some areas like Background/Robot-state, and improvement margins are small in some RoboTwin 2.0 comparisons (Evidence: Section 4.4, Figure 6, Table 4) (Interpretation).
  • Balance of ablations across backbones — Depth, loss weight, and prediction-head capacity ablations are primarily based on Wan, while action-only/shared-weight analyses focus on Qwen3.5-2B/DINOv2-L, making it difficult to confirm if sensitivity is identical across all backbones (Evidence: Appendix C Table 10–15) (Interpretation).
  • LIBERO-Plus evaluation frequency — LIBERO-Plus evaluates each perturbed manifest once; caution is needed in interpreting variance of single-rollout-based results even with bootstrap CIs provided (Evidence: Section 3.1, Appendix D Table 20) (Interpretation).
  • Unclear code/data availability — Hyperparameters and cost analysis are detailed, but availability of code repositories, dataset access, checkpoints, seeds/evaluation scripts required for reproduction is not confirmed in the provided notes (Evidence: Appendix A–B; no mention of code release in provided notes) (Interpretation).

Reproducibility

  • Learning rate, optimizer, batch size, number of updates, readout location, λF\lambda_{\mathrm{F}}λF​, prediction-head structure, and FLOPs measurement method are detailed, but availability of code/data/checkpoints and LIBERO-Plus 15% subset manifest generation scripts/seed settings are not confirmed in the provided notes (Evidence: Appendix A–B; no mention of code release in provided notes) (Interpretation).

Related Work

  • FastWAM, ImageWAM: WAM baselines addressing test-time future imagination and image editing/video generation problems, respectively.
  • π0\pi_0π0​ / π0.5\pi_{0.5}π0.5​: VLA flow model family research for open-world generalization.
  • V-JEPA 2(-AC): Research on self-supervised video models, latent prediction, and planning/MPC.
  • Motus: Unified latent action world model.
  • DINOv2, Wan, Qwen3.5, FLUX.2: Backbone families used in JAM implementation.
  • LIBERO / LIBERO-Plus, RoboTwin 2.0: Robot manipulation benchmarks used for evaluation.
  • REPA, AGRA, Video-Mirai: Research addressing visual generation and representation alignment simultaneously.
  • FLARE, FRAPPE, VLAFlow: Predictive representation research combining future/state/action tokens or LoRA streams within action policies.
  • VPP, Seer: Video-based policy family connecting predictive visual features to control.
  • Burda et al., Sarnthein et al., Bojanowski & Joulin, Grill et al.: Prior work on frozen/adaptive targets such as random encoders, noise targets, and EMA encoders.
