01RL Problem Formulation: The Interaction Loop

At each time step t, the agent and environment exchange states, actions, and rewards.

The goal is to find a policy that maximizes the expected value of the cumulative reward (return).

maxπ Eπ[ Gt ],    Gt = Rt+1 + γRt+2 + γ²Rt+3 + ⋯
The environment's dynamics p are assumed to be unknown. This is the point where it diverges from classical control theory, which starts with knowledge of p.

02How is it different from supervised learning: Three axes

AxisSupervised LearningRL
① Type of feedbackinstructive: provides the correct label yevaluative: only provides the score for the chosen action. It is unknown what would have happened with other actions
② Data distributioni.i.d., fixedThe policy changes the data distribution. Where you go determines what you learn
③ Temporal structureSamples are independentReward arrives late. An action 100 steps prior may be the cause → credit assignment

03🤖 From a Robot's Perspective

  • Observation vs state: What is seen via cameras and sensors is only part of the state, making it strictly a POMDP (covered in 02).
  • Step = control cycle: At 50Hz, a 10-second episode consists of 500 steps, making ③ credit assignment severe.
  • Sparse reward vs shaping: Sparse rewards provide almost no learning signal, while shaping can lead to reward hacking (e.g., receiving distance reward just by vibrating near the object).
  • Exploration cost: Simulation is free, but real robots break → sim-to-real.
  • Consequence of ②: When the policy changes, the distribution of visited states changes. The compounding error in imitation learning is also due to this (10).

04What is a Multi-armed Bandit

The nickname for a casino slot machine is "one-armed bandit". It has one lever (arm) and it takes your money, so it's a bandit. If there are multiple such machines, it's a multi-armed bandit.

  • k machines. Pulling machine a yields reward R ~ νa. The true mean q*(a) = E[R | A=a] is unknown.
  • In each round, you choose one to pull, aiming to maximize cumulative reward over T rounds.
  • You only see the result of the machine you chose. This creates a dilemma: keep using what looks good (exploitation) or learn about less-tried options (exploration).

Real-world examples: A/B testing, clinical trial assignment, ad/recommendation selection, 🤖 grasp candidate selection, controller hyperparameter selection.

ML Perspective

If you take one SGD step on L(Q) = ½(R − Q)², you get Q ← Q + α(R − Q). In other words, it is equivalent to performing MSE regression with the target as the label using SGD. The point where the expected update becomes 0 is Q = E[R] = q*.

Fixed Step Size and Convergence Conditions

Qn+1 = (1−α)n Q1 + Σi α(1−α)n−i RiThe older the reward, the more exponentially its weight decreases (exponential recency-weighted average)
  • Robbins–Monro conditions: Σαn = ∞ (moves enough to go anywhere from the initial value), Σαn² < ∞ (step size decreases and noise disappears).
  • 1/n satisfies both. Fixed α violates the second one, so it does not fully converge, but thanks to that, it follows changes. 🤖 A robot whose dynamics change due to wear.

What Changes Going Forward is Only the Target

Algorithmtarget
BanditR (the reward just received)
Monte Carlo (04)G_t (the sum of rewards actually received until the end of the episode)
TD (05)R + γ·V(s') (one step of reward + estimate of the next state)
Q-learning / DQN (05, 07)R + γ·max Q(s', ·)
From TD onwards, my estimate is included in the target, so if I move, the target moves with me. This is why DQN needs a target network.

06Performance Metric: Regret

Regret(T) = Tμ* − E[ Σt Rt ] = Σa Δa · E[NT(a)] μ* = average of the optimal machine · gap Δa = μ* − q*(a) (loss when choosing incorrectly once) · NT(a) = number of times machine a was chosen

The value obtained by subtracting the "expected reward actually received" from the "expected reward that would have been received if the optimal machine had been known from the start," literally regret. Using ΣN(a) = T, it becomes Tμ* − ΣN(a)q*(a) = ΣN(a)(μ* − q*(a)).

Why multiply by gap: The loss per mistake varies

Regret is a report card

  • It can only be calculated if the correct answer μ* is known. Therefore, the agent itself cannot calculate it, whether during execution or after completion. It is not a learning signal. It occupies the position of test loss in ML.
  • Uses: ① Before execution Theoretical guarantees (e.g., UCB has regret ≤ C·log T) ② During/After execution An experimenter who knows the correct answer evaluates via curves in simulation ③ In actual deployment Cannot be calculated → use proxy metrics like cumulative reward.
  • The reward curve is "how well it is doing now", while cumulative regret is "how much loss was incurred until it became good (learning cost)". Even if final performance is the same, reaching it later results in higher regret.
  • Lai–Robbins lower bound: No reasonable algorithm can be smaller than Ω(log T). → O(log T) is optimal in terms of order.
🤖 Robotics Connection · In simulation learning, final performance is primarily important. For real robots, where mistakes during learning incur actual costs (damage, time), the regret perspective becomes important. Sample efficiency in Deep RL follows the same logic.

07Simple Strategies: Greedy, ε-greedy, Optimistic init

StrategyMethodProblem
GreedyAlways argmax QIf the optimal arm happens to have a low value early on, it is never chosen again → Linear regret
ε-greedyRandom with probability ε, greedy otherwiseEven after identifying the optimal arm, bad arms are still chosen at a rate of ε/k → Linear regret (Logarithmic is possible with an ε decay schedule, but tuning matched to the gap is required)
Optimistic initSet Q0 highAll arms are tried once in the beginning, but exploration only occurs early on
Fundamental limitation of ε-greedy: It explores randomly without distinguishing between "unknown" and "bad". Good exploration should be done based on uncertainty → UCB, Thompson sampling.

08UCB: If You Don't Know, Assume It's Good

Principle: optimism in the face of uncertainty. Calculate each machine's "maximum potential" (how good it could possibly be) and select the one with the highest value.

UCBt(a) = Q(a) + c · √( ln t / N(a) ) Current estimate (Exploitation) + Uncertainty bonus (Exploration)
  • N(a)↑ → Bonus↓: If you've pulled it many times, "you know enough now."
  • ln t↑ → Bonus slowly↑: Machines not selected for a long time will see their potential rise even without being pulled, eventually getting re-evaluated.
  • If N(a) = 0, the formula is undefined, so pull every arm once first (UCB = ∞).
  • High UCB means one of two things: It's actually good (high Q), or we don't know yet (large bonus). Low UCB = seen enough but still low = confirmed bad.

A0.60800.340.94

Derivation: From Hoeffding's Inequality to c = √2

P( q* > Q + u ) ≤ exp(−2Nu²) = δ ⟹ u = √( ln(1/δ) / 2N ) When reward ∈ [0,1]. "q* is below Q + u with probability 1−δ" = Upper Confidence Bound
δ = t⁻⁴ ⟹ u = √( 4 ln t / 2N ) = √( 2 ln t / N ) ⟹ c = √2 (UCB1)
  • Why t⁻⁴: Not because it's optimal, but for the proof. The probability of the confidence interval being wrong must sum to a finite constant over all (t, N) (union bound) for the regret proof to hold.
  • If the reward range is [a, b], scale the bonus by (b−a). In practice, c is tuned, and using values smaller than √2 generally works well.
  • If it were √(t/N): The bonus would grow too fast, leading to over-exploration → regret grows polynomially. The slow growth of ln t creates "only log-scale verification."

09Thompson Sampling: Sampling from Beliefs

If UCB carries a single number (an upper bound) for each machine, Thompson sampling carries the entire distribution of "what the true probability likely is."

  1. Randomly sample one value from each machine's belief distribution.
  2. Pull the machine with the highest sampled value.
  3. Update that machine's belief distribution based on the outcome.

Beta Distribution (When Rewards are 0/1)

  • Beta(α, β): Roughly α − 1 = number of wins, β − 1 = number of losses. Mean is α/(α+β).
  • Starts at Beta(1, 1) = uniform distribution ("knowing nothing").
  • Update: Win → α += 1, Loss → β += 1. Since it's a Beta–Bernoulli conjugate pair, it ends with just counting.
  • As observations accumulate, the distribution becomes sharper (uncertainty decreases).

Comparison with UCB

UCBThompson sampling
Uncertainty representationConfidence interval (Frequentist)Posterior distribution (Bayesian)
Selection methodDeterministic argmax by calculating the upper boundProbabilistic argmax by sampling from the distribution
Exploration principleIf unknown, the upper bound is highIf unknown, the distribution is wide, so it occasionally samples high values
TuningcPrior distribution (usually Beta(1,1))
TheoryO(log T)O(log T), matches the Lai–Robbins lower bound even in constants
PracticeGoodUsually better or similar to UCB (Chapelle & Li, 2011)

Commonality: The more uncertain, the more it explores. UCB implements this with a bonus term, while Thompson does so with the width of the distribution.

  • Pros: No c to tune / Easy to extend to continuous rewards (Gaussian) and context (Bayesian linear regression) / Robust to delayed/batch feedback due to randomness.
  • Cons: Must be able to compute the posterior distribution. Approximation is needed for neural networks.

Connection to Later Topics

  • Deep RL exploration: Pick one from a network ensemble to act (Bootstrapped DQN, 07)

GP posterior + UCB/Thompson = Bayesian optimization, which is actually used to find parameters on real robots with few trials. PETS in Model-based robot learning (10) also samples from a dynamics model ensemble to plan.

Three Key Takeaways
  1. The incremental update Q ← Q + α(target − Q) is the backbone that repeats until the end. Only the target changes.
  2. Good exploration = Exploration based on uncertainty. This keeps coming back as the same problem in MDPs, Deep RL, and robot learning.
  3. Bandits have no state transitions. The moment an action changes the next state, it becomes an MDP → 02 MDP & Bellman Equation

?Review Questions

Try to recall the answer first, then expand.

Question 1When ε = 0.1 and k = 10, what is the average per-step regret that remains even after perfectly identifying the optimal arm?

Selecting randomly among k arms with probability ε → Per-step regret = ε · (1/k)ΣaΔa = 0.1 · Δ̄ (where Δ̄ is the average gap of the k arms, including the optimal arm). Since it is constant, it accumulates linearly over T steps.

Question 2In a fixed α update, what is the weight of the i-th reward? Why are the Robbins–Monro conditions necessary?

The weight is α(1−α)n−i, decreasing exponentially as it gets older. Σα = ∞ ensures that the influence of initial values is erased and allows convergence to any point, while Σα² < ∞ ensures that the step size decreases so noise vanishes. A fixed α violates the second condition and does not converge, but it tracks nonstationary environments (Figure 5).

Question 3In UCB, what do you do if N(a) = 0? What happens if you change the bonus to √(t/N)?

Pull every arm once first. With √(t/N), the bonus grows too quickly, leading to over-exploration → regret grows polynomially instead of logarithmically.

Question 4How do you use UCB1 for a robot problem where the reward range is [−100, 0]?

Due to Hoeffding's range term, either scale the bonus by the range width (100) or normalize the rewards to [0, 1].

Question 5Model one robot problem as a bandit and explain where the "no state" assumption breaks down.

Example: Choosing from 5 grasp candidates. If the object's position and orientation change every time, context arises, making it a contextual bandit; if a previous grasp failure pushes the object and changes the next situation, it becomes an MDP.

Q&AQuestions & Answers

Questions I asked myself while studying. Try to recall the answer first, then expand.

Q1I don't really understand what a bandit is.04 · What is a Bandit
  • The name comes from the nickname for slot machines, "one-armed bandit." If there are multiple arms, it's a multi-armed bandit.
  • Setup: k slot machines with unknown reward distributions. Each round, you pick one to pull and receive a reward. Maximize cumulative reward over T rounds.
  • Core challenge: You only see the result of the machine you chose → Do you keep using what looks good (exploitation), or try less-explored options to learn (exploration)?
  • Real-world examples: A/B testing, clinical trial assignment, advertising/recommendations, robot grasp candidate selection, controller hyperparameter selection.
Q2Do I have to study Markov chains?04 · What is a Bandit
  • Yes. In section 02, we build up in the order: Markov chain → MRP → MDP.
  • A bandit is a special case of an MDP with only one state, so there are no state transitions and no need to worry about the Markov property. That's why we treat the exploration problem separately first.
Q3Please explain incremental updates more. What is the target? Is it the goal point we're trying to reach?05 · Incremental Updates
  • The true goal point is q*(a) = E[R|a]. It is unknown.
  • The target is the Rn observed in this step. It's a noisy sample of q* and a "shaky target" with an expected value of q*. In this update, we pull Q slightly toward it. → Figure 5
  • Rearranging the sample mean formula yields exactly this: Qn+1 = Qn + (1/n)(Rn − Qn).
  • SGD perspective: Gradient descent on L = ½(R − Q)². The point where the expected update is zero is Q = q*.
  • In later sections, only the target changes: MC uses Gt, TD uses R + γV(s'), and Q-learning uses R + γ max Q(s',·).
Q4Is regret like "regret"? Why is the gap multiplied by the number of bad choices?06 · Regret
  • Yes. It's "Expected reward if we had known the optimal arm from the start − Expected reward actually received."
  • The cost of each mistake varies. Since the loss per wrong choice is Δa, count × gap = total loss. → Figure 6
  • Example: If optimal is 0.70, choosing B(0.69) 100 times → loss 1.0; choosing C(0.10) 10 times → loss 6.0. Just counting occurrences leads to wrong conclusions.
  • Why calculate with expected value q*: To not credit luck as skill.
Q5Does pulling an arm determine the next state in a Markov chain?04 · bandit vs MDP
  • No. In a bandit, pulling an arm only determines the reward. The next round is the same machine with the same distribution.
  • In an MDP, an action changes both the reward and the next state p(s'|s,a). → Figure 4
  • Hierarchy: Markov chain (state transitions only) → MRP (+reward) → MDP (+action). A bandit is an MDP with one state where all actions return to the same state.
Q6So averaging gives us probabilities, and each algorithm has a different target and update formula? Regret helps us discard bad machines quickly? And in an MDP, actions and rewards change the next state, so the slot machine's probabilities change?Comprehension Check
  • The first part is correct. However, bandit algorithms are divided into ① estimation (Q update, target) and ② selection rule. In bandits, ① is mostly the same (target = R), but ② differs. The target changes starting from MDPs.
  • Regret is not a tool used by the algorithm, but a scorecard for evaluation. Since μ* is unknown, the algorithm cannot calculate it. "Discarding bad machines quickly and filtering out luck" is what UCB/TS does by quantifying uncertainty, and algorithms that do this have lower regret.
  • MDP: What changes the next state is not the reward, but (current state, action). It's more accurate to say "my action moves me to a different room, and each room has different machines and probabilities" than "probabilities change."
SituationName
Probabilities change over time independently of my actions (wear)nonstationary bandit
The room changes, but not because of my action (different situation for each customer)contextual bandit
The room changes because of my actionMDP
Q7Is regret like a post-hoc evaluation after reinforcement learning is finished? Doesn't it require knowing the correct answer (result)?06 · Regret
  • Yes. Since you need to know the correct μ*, the agent itself can never calculate it.
  • However, it's not "only after finishing." An experimenter who knows the answer records cumulative regret at every step during simulation and plots a curve. The shape of the curve (linear vs log) reveals the algorithm's properties. → Figure 12
  • Uses: ① Theoretical guarantees before execution ② Evaluation in simulation experiments ③ Cannot be calculated in real deployment → proxy metric.
  • Deep RL experiments usually report return curves, and regret is mainly used in theoretical papers.
Q8So an MDP feels like: act from a state to get a reward, accumulate it, move to the next room (a new choice), and act again?04 · bandit vs MDP
  • The flow is correct: State → Action → (Reward, Next State) → Repeat. The discounted sum of rewards G is what gets maximized.
  • Correction ①: Rooms are revisited. You return to the same cell in the same pose, and episodes repeat. That's why you can use what you learned in room s when you come back, making learning possible.
  • Correction ②: The levers (action set) are usually the same in any room, but the outcomes (reward, next room) differ by room.
  • Correction ③: Cumulative reward just accumulates on the scoreboard; it doesn't change the next room. The next room is determined only by (s, a).
  • 🤖 In a robot's continuous state space, you rarely see exactly the same state again → generalization ("similar rooms are similar," function approximation, 06) is needed.
Q9Is there a theoretical reason why the exploration strength c is √2?08 · UCB
  • In the Hoeffding confidence interval u = √(ln(1/δ)/2N), if we set δ = t⁻⁴, then u = √(2 ln t / N) → c = √2.
  • t⁻⁴ is not optimal; it's for proof purposes. The probability that the confidence interval is wrong must sum to a finite constant over all (t, N) (union bound) for the regret proof to hold.
  • This assumes reward range [0,1]. For [a,b], multiply by (b−a). In practice, c is tuned, and using values smaller than √2 generally works well.
Q10So UCB is a cumulative metric for judging if something is really good or bad? High ones have potential so we check them, and low ones mean no potential?08 · UCB
  • Almost correct. UCB = "How good it could be if we take the maximum," i.e., an optimistic upper bound, or potential.
  • Note: The reason UCB is high is either it's really good, or we don't know yet. Being low means we've seen enough and it's still low, i.e., confirmed to be bad.
  • Q and N accumulate, but ln t grows every step. Machines not chosen for a long time will have their UCB slowly rise even if left alone. It's a score recalculated every step. → Figure 8
Q11Following up on regret, what was the gap again? I can't connect the size of the gap with UCB and log regret well.08 · UCB · Regret
  • Gap Δa = μ* − q*(a): The loss incurred each time machine a is chosen. Since it's defined by true values, the algorithm doesn't know it.
  • Connection: For UCB to discard machine a, a's upper bound must drop below μ* → bonus < Δa → N > 2 ln t / Δa². The smaller the gap, the narrower the confidence interval needs to be, so we pull more. → Figure 9
  • Regret contribution = Δ × N ≈ ln T / Δ → Total regret = Σ ln T / Δa = O(log T).
  • Meaning: Even if T increases 1000-fold, ln T only doubles. Loss per step goes to 0. Fixed ε-greedy has mistakes proportional to T.
Q12So regret is an evaluation metric after running the entire RL process? Like looking at the reward sum curve and saying "it converges here"?06 · Regret
  • Yes. It's a metric where the experimenter plots the entire learning process as a curve to evaluate.
  • It's just looking at the same information as the reward curve differently. Per-step regret = height between the optimal line and the reward curve; cumulative regret = that area. → Figure 7
  • The reward curve shows "how well it's doing now," while cumulative regret shows "how much loss was incurred until it got good (learning cost)." Even if final performance is the same, an algorithm that arrives late has higher regret.
  • 🤖 For real robots where mistakes during learning have actual costs, the regret perspective is important.

✓Concepts That Were Confusing

  • bandit: Choosing among multiple slot machines with unknown reward distributions. Only the outcome of the chosen one is observed. Q1
  • target vs 목표 (goal): The goal is the true average q*, while the target is that noisy sample, a wobbling bullseye. Q3
  • Two components of an algorithm: Estimation (target) + selection rule. In bandits, the selection rule is what makes the difference. Q6
  • regret = report card: Only an outside observer who knows the correct answer can calculate it. It is not a learning signal. Cumulative regret = the area between the optimal line and the reward curve. Q6 · Q7 · Q12
  • gap: The loss incurred when making one wrong choice. regret = Σ count × gap. Q4 · Q11
  • bandit vs MDP: What changes the next state is not the reward but the action. Rooms are revisited. Q5 · Q6 · Q8
  • UCB = potential: The reason for high values is "good or unknown." Pull until the bonus < gap → logarithmic regret. Q10 · Q11
  • c = √2: A value derived from Hoeffding + δ = t⁻⁴ for proof purposes. In practice, it is tuned. Q9
