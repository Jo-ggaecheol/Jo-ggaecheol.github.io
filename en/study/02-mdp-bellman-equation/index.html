01The Big Picture: Building Layer by Layer

Section 02 follows a flow of stacking components one by one. Each layer contains the previous layer as-is.

02Markov chain

P( St+1 = s' | St, St−1, …, S0 ) = P( St+1 = s' | St ) Markov property: Given the present, the past provides no additional help in predicting the future (all relevant past information is already contained in the present)

If transition probabilities are time-independent (time-homogeneous, "yesterday's rules = today's rules"), they can be written as a single matrix Pss', where each row sums to 1. The fixed part is the rule P, while the state distribution μt can continue to change.

Example: Robot 2-state chain

Current \ NextWork (W)Charge (C)
Work (W)0.90.1
Charge (C)0.50.5
μt+1 = μt P ⇒ μt = μ0 Pt, μ* = μ* P Temporal evolution of the distribution · Stationary distribution = a distribution that remains unchanged after one more transition (left eigenvector with eigenvalue 1)

In the stationary distribution, inflow = outflow. In this example, 0.1·μW = 0.5·μC → μ* = (5/6, 1/6). The robot spends 83% of its time working in the long run.

When does it exist, is unique, and converge (finite states)

ConditionMeaningGuarantee
irreducibleAll states are mutually reachableUnique stationary distribution
+ aperiodicReturns do not occur only at exact periodic intervalsμt → μ* from any μ0
  • If both hold, the chain is ergodic: "time average = distribution average". You can estimate μ* by following a single trajectory for a long time. This is the basis for why MC/TD methods can estimate expectations from trajectories.
  • Flows do not need to be equal for every pair (detailed balance is a stronger condition). A chain that only cycles 1→2→3→1 also has a stationary distribution of (⅓, ⅓, ⅓).

Isn't reality non-time-homogeneous?

RealityModel
The rules themselves change over timeTime-inhomogeneous chain Pt, nonstationary MDP
Dwell times are irregularSemi-Markov, continuous-time Markov chain
Sensors reveal only part of the statePOMDP (Chapter 10)
Hidden parameters (friction, mass)Hidden-parameter MDP, meta-RL
Non-stationarity is usually due to variables missing from the state. If you include motor temperature, battery level, and wear in the state, it becomes "same state implies same rules" again.

03🤖 Markov is a property of state representation

  • Robot arm: Joint angles θ alone are not Markov, but (θ, θ̇) is Markov under second-order dynamics (F = ma).
  • Principle: State = sufficient statistic of the past needed to predict the future. By appending the past to the state (state augmentation), anything can be made Markov.
  • This is why DQN stacks 4 Atari frames and why robot policies receive observation history. If sensors reveal only part of the state, it becomes a POMDP (Chapter 10).

04Episodes and Terminal States

Episode: A single trajectory from the initial state S0 ~ μ0 until reaching a terminal state (time T, random variable). Once finished, reset and start the next episode. If there is termination, it is an episodic task; if not, it is a continuing task(making the sum finite with γ < 1).

TermIn this task
stepOne control cycle
stateJoint angles/velocities, gripper, object pose
actionJoint target values or torques
terminalSuccess (z ≥ 30cm), Failure (drop, collision, joint limits)
truncationForced cut because it couldn't finish within 200 steps
truncation ≠ termination. This is why gymnasium provides terminated/truncated separately. Setting the value of a state cut off by time limit to 0 breaks learning (revisited in 05, 07).

A bandit can be viewed as "one pull = an episode of length 1." The state returns to itself with probability 1, and randomness exists only in the reward.

05MRP: Return, Discount Rate, and Value Function

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ⋯ = Σk γk Rt+k+1,    Gt = Rt+1 + γ Gt+1 MRP = (S, P, R, γ) · Return is the discounted sum of future rewards · The Bellman equation emerges from this recursive structure

Discount Rate γ: How Far into the Future to Look

Reasons for using γ < 1: ① Ensures |G| ≤ Rmax/(1−γ) remains finite even in infinite-horizon tasks ② The distant future is uncertain ③ Creates pressure to "finish quickly" (see Exercise 3).

Value Function and Bellman Equation

V(s) = E[ Gt | St = s ] = R(s) + γ Σs' Pss' V(s') Current value = immediate reward + γ × average value of the next state · The Markov property is used to establish that E[Gt+1 | St+1 = s'] = V(s')
V = R + γPV ⇒ V = (I − γP)−1 R Always invertible because the magnitude of all eigenvalues of γP is at most γ · Cost O(n³); use iteration for large state spaces (Chapter 9)

Numerical Example: Applying work reward 1, charging reward 0, and γ = 0.9 to the chain in Figure 2 yields VW ≈ 8.59 and VC ≈ 7.03. Even while charging, the value is not zero because it reflects the expected future return from returning to work. V is an evaluation that includes the future. It is also consistent with the connection to the stationary distribution: multiplying the average reward per step μ*W = 5/6 by a horizon of 10 steps gives a value near 8.3.

The Big Picture: From Future Rewards to Present Decisions

① Evaluation : Pull future rewards back to form the current state score V(s)      ← MRP (Current)
② Selection : Compare the "score of the state reached after each action"          ← Q(s,a) in MDP (Chapter 7)
③ Improvement : Update the policy to choose the better option                  ← 03 DP
   ↺ If the policy changes, the scores change → Back to ① = GPI
The right-hand side R + γV(s') is the target in 05 TD. It is the same "target" mentioned in 01, but this time it includes its own estimate V(s') (bootstrapping). The discussion of instability in 05 and 06 begins here.

06Reward Design: Shaping and Hacking

Reward shaping: Adding guidance rewards

If the reward is "success +1, otherwise 0" (sparse), a random robot will see only zeros forever and learn nothing. We add hint rewards at intermediate stages.

StageHint Reward
Hand approaches object+ (distance reduction)
Grasp success+0.5
Object height increases+ (amount of rise)
Reaches 30cm+10 (actual goal)
F(s, s') = γΦ(s') − Φ(s) ⇒ G' = G − Φ(s0) potential-based shaping (Ng et al., 1999): telescoping cancellation leaves only a constant → policy ranking is invariant

Reward hacking: Maximizing the number, not the intent

  • Object uprighting: If z is measured as the object's center-of-mass height, simply standing a long object up increases it.
  • CoastRunners (OpenAI, 2016): The boat circled the item respawn zone instead of finishing.
  • Simulator bug: Bouncing due to physics engine collision errors counts as "forward progress."
  • RLHF: Exploits the reward model's preferences (long answers, flattery) (10).
Keep rewards simple, termination/failure conditions clear, and always verify learned behavior via video. Looking only at return numbers is misleading.

Infinite reward, exponential reward?

AttemptProblem
Success reward ∞If success probability is not 0, V = ∞ for all policies → policies cannot be compared. Numerically inf/NaN
Very large finite valueMultiplying the entire reward by c leaves the optimal policy unchanged. What matters is the ratio. If too large, shaping is buried and it becomes equivalent to sparse; return variance increases causing instability → in practice, use reward scaling / clipping (DQN [−1, 1])
exp(z)Signal near the floor is nearly 0 so early learning fails, and per-step reward near the top becomes large, worsening hovering hacking
exp(−‖error‖²/σ)Good exponential. Bounded in (0, 1], equals 1 at the goal. Standard in walking robot velocity tracking rewards, etc.

07MDP: Policy, Vπ, Qπ

MDP = (S, A, p, R, γ), p(s' | s, a), π(a | s) = P(At = a | St = s) Now the next state and reward depend on the action · The policy can be stochastic or deterministic (a = π(s))

Fixing a Policy Turns an MDP into an MRP

Pπ(s' | s) = Σa π(a|s) p(s'|s,a), Rπ(s) = Σa π(a|s) R(s,a)
⇒ Vπ = (I − γPπ)−1 Rπ
  • The state and dynamics p are determined by the environment. What we choose is the policy. Choosing a policy = choosing which Markov chain to create. A good policy creates a chain that stays in high-reward states for longer.
  • "Convergence" has two meanings: ① Convergence of learning (policy stops changing → chain fixed → learning curve flattens) ② Convergence of the distribution under a fixed policy (μt → dπ). A flat curve does not guarantee optimality.

Vπ and Qπ

QuestionAnalogy
Vπ(s) = Eπ[Gt | St=s]How much will I earn from this state if I follow π going forwardThe score of this square
Qπ(s,a) = Eπ[Gt | St=s, At=a]If I take action a first from this state and then follow πThe score for exiting this square through this door

If you only have V, you need p(s'|s,a) to compare actions. Q directly holds scores for each action, so it can be chosen without a model → Q-learning (05), DQN (07).

Vπ(s) = Σa π(a|s) Qπ(s,a), Qπ(s,a) = R(s,a) + γ Σs' p(s'|s,a) Vπ(s') Substituting into each other yields the Bellman expectation equation · The average over my choices and the average over environmental randomness alternate

Aπ(s,a) = Qπ(s,a) − Vπ(s) advantage: How much better this action is than usual · At S1, A(→) = +0.089, A(←) = −0.089 · Used in 08 policy gradient and PPO's GAE
  • PPO (Schulman et al., 2017): Increases the probability of actions with positive advantage and decreases it for negative ones, but clips the new/old policy probability ratio to [1−ε, 1+ε] to prevent large changes at once. Standard for robot locomotion and RLHF (09).
  • POMDP: MDP where you only see observations instead of the true state (Chapter 10).
🤖 Robotics Connection · p(s'|s,a) is the physical law, and the simulator is exactly this p. π(a|s) is a policy neural network that outputs the distribution of joint commands (Gaussian). Vπ(s) answers "how likely is success given this posture and grasp state," while Qπ(s,a) compares options like "pulling up now vs. opening the gripper." Because actions are continuous, we cannot compute an entire Q table and select the maximum → 08, 09.

08Optimality: V*, Q*, Bellman optimality

V*(s) = maxπ Vπ(s), Q*(s,a) = maxπ Qπ(s,a), π*(s) = argmaxa Q*(s,a) In a finite MDP, there always exists a deterministic policy π* that is simultaneously optimal in every state · Knowing only Q*, you can choose by looking just one step ahead

Principle of Optimality: The latter part of an optimal path is itself optimal. If the shortest path from Seoul to Busan passes through Daejeon, the segment from Daejeon to Busan within it must also be the shortest. Hence "current best = this move + best at destination".

Why can't we solve it with a single matrix operation?

max is nonlinear. Which action is best depends on V*, and V* in turn depends on which action is best. So we solve by iteration: value iteration, policy iteration (03), LP.

Verification: Corridor V* = (0.729, 0.81, 0.9, 1). At S1, max(0.9 × 0.729 = 0.656, 0.9 × 0.9 = 0.81) = 0.81 ✓. The random policy's Vπ(S1) = 0.336 is an average, not a maximum, so it does not satisfy this equation. It serves as a criterion to filter out non-optimal policies.

🤖 Robotics connection · The continuous time/continuous state version is the HJB equation of optimal control. For linear systems + quadratic cost, V* falls neatly into a quadratic form → LQR (03). And optimal is "optimal with respect to the given reward". If you make hovering beneficial (Figure 7), the optimal policy is exactly hovering.

09Contraction: Why Repetition Always Converges

(T*V)(s) = maxa [ R(s,a) + γ Σs' p(s'|s,a) V(s') ], V* = T*V*, Vπ = TπVπ Bellman operator = a "machine" that takes a score table and outputs the updated score table after one step · Bellman equation = the fixed point of the machine
‖TV − TU‖∞ ≤ γ ‖V − U‖∞, ‖V‖∞ = maxs |V(s)| Each time the machine is passed through, the distance between two guesses shrinks by a factor of γ or less

Proof

  • Tπ: |(TπV − TπU)(s)| = γ|Σs' Pπss'(V − U)(s')| ≤ γ‖V − U‖∞. R cancels out upon subtraction, and since the rows of P are weighted averages, they cannot exceed the maximum value.
  • T*: Additionally, |max f − max g| ≤ max |f − g|. max is nonlinear but does not break contraction.

k ≈ ln(1/ε) / (1 − γ) Number of iterations to reduce error by a factor of ε · γ = 0.9 → ~46 · 0.99 → ~460 · 0.999 → ~4600 · Same number as the effective horizon 1/(1−γ)

The further into the future you look, the slower it gets. It takes that much time for information to spread from the distant future to the present. If γ = 1, contraction is not guaranteed (separate conditions are needed, such as for episodes that must terminate).

Continuous States and Actions

POMDP: Sensors Don't Reveal the Full State

The agent only sees observation o ~ O(o|s) instead of state s. This includes occlusion by hands, sensor noise, unknown mass/friction, and contact states like slipping.

b'(s') ∝ O(o | s') Σs p(s' | s, a) b(s) Belief state b(s) = P(s | observations and actions so far) · Predict via dynamics → Correct via observation · The Kalman filter is the exact solution for linear-Gaussian cases.

If we treat b as the state, it becomes an MDP again (belief MDP). However, since the distribution itself is the state, solving it exactly is difficult. A memoryless policy can perform better with a stochastic policy than with a deterministic one (a phenomenon not present in fully observable MDPs).

Control Cycle and γ

H초 ≈ Δt / (1 − γ),    γnew = γoldΔtnew / Δtold 1 step in MDP = control cycle Δt · γ ultimately determines "how many seconds ahead to look" · Changing the cycle requires changing γ as well.
  • Faster cycles increase steps in the same time, making credit assignment harder, and γ → 1 slows convergence (Chapter 9).
  • In practice, use a hierarchical structure: RL policy at ~50Hz for joint targets, with PD controllers below at ~1kHz for torque. Frame skipping in game RL is based on the same idea.

Three Key Takeaways

  1. Bellman equation = current value = reward + γ × next value. It compresses the distant future into a score for the current state, turning long-term planning into single-step choices.
  2. If the policy is fixed, an MDP becomes an MRP (linear); choosing the best action introduces max, making it nonlinear. However, both are γ-contractions, so iterating leads to a unique solution.
  3. Markov is a property of state representation. State design, reward design, and the choice of γ and control cycle are all part of problem definition.
→ 03 Dynamic Programming: Assuming p is known, we actually solve it using policy iteration / value iteration. Bellman ↔ HJB, LQR.

?Check Questions

Try to recall the answer first, then expand.

Question 1In the chain from Figure 2, if the charging→working probability is changed from 0.5 to 0.1, what are μ* and |λ2|?

μ* = (½, ½), λ2 = 0.8. The chain becomes "sticky," staying in one state for a long time, so the mixing speed slows down (the "sticky chain" button in Figure 2). Estimating the long-term average with short trajectories results in large errors.

Question 2If the state of an autonomous vehicle is defined as "one current camera image," is it Markov?

No. Speed and occluded objects cannot be known. You need to add multiple frames, speed/IMU data, or a belief representation like an RNN.

Question 3In the 5-state chain example, if γ = 0, what are VW and VC? In the lifting task, if "success +1, others 0, γ = 1," what problem arises?

V = R = (1, 0). The value of charging leading to future work disappears. For the second part: since G = 1 regardless of when success occurs, there is no incentive to act quickly. If γ < 1, the value of success at step k is γk, so finishing earlier is better (or use a per-step time penalty).

Question 4If the policy is deterministic, what is the relationship between Vπ(s) and Qπ(s, π(s))? If only V is learned, what else is needed to choose actions?

They are equal. With only V, you need the environment model p(s'|s,a) (planning: 03, 10). Without a model, you learn Q directly (05, 07).

Question 5In the corridor with γ = 1, what are V* and the optimal policy? If Q*(s, a₁) = Q*(s, a₂), is the optimal policy unique?

V* = 1 in all cells. A policy that wanders before arriving also becomes optimal, removing the incentive to go quickly. Second part: there can be multiple optimal policies (including mixed stochastic policies), but V* is unique (Chapter 9).

Question 6In Figure 10, why does V0 = 0 terminate exactly after 4 iterations?

The transitions are deterministic and the path length is finite with a maximum of 4. k iterations = the optimal value up to k steps ahead is calculated exactly. With stochastic transitions or cycles, it converges asymptotically.

Question 7If a policy working well at 100Hz with γ = 0.98 is lowered to 25Hz, what should γ be? In lifting with unknown mass, which is more advantageous: a policy looking only at current observations or one looking at 1 second of history?

γ = 0.98⁴ ≈ 0.922; the horizon is 0.5 seconds for both (verify with Figure 12). History side: you can infer mass by how much the object rises with the same force (acting as a belief). This is the idea behind meta-RL and RMA.

Questions I asked myself while studying. Try to recall the answer first, then expand.

Q1Does "transition probabilities are time-independent" mean that the transition probability from yesterday to today is the same?02 · Markov chain
  • Yes. P(St+1=s'|St=s) does not depend on t. If you start from the same state, the next state is always drawn according to the same rules.
  • Note: This does not mean "the state distribution μt is the same every day." The rule P is fixed, but the distribution can continue to change. → Figure 2
Q2This seems like an idealized assumption; the real physical world probably doesn't work that way. Are there models that reflect this?02 · Markov chain
  • Yes. Time-inhomogeneous chains (Pt), nonstationary MDP, semi-Markov, continuous-time Markov chain, POMDP, hidden-parameter MDP / meta-RL.
  • Key perspective: Non-stationarity is usually due to variables missing from the state. If you include motor temperature, battery level, or wear in the state, it becomes time-homogeneous again. You can also include time t in the state.
  • 🤖 In practice, we deal with this using domain randomization (policies robust to multiple P), online adaptation, and inputting observation history instead of an exact model.
Q3Does "temporal evolution of the distribution" mean that any Markov chain converges? Does it imply there are convergence conditions?02 · Markov chain
  • Temporal evolution simply means the fact that the distribution changes at each step via μt+1 = μtP. Convergence requires separate conditions.
  • Finite state: If it is irreducible + aperiodic, it converges to a unique μ* from any μ0.
  • Counterexamples ① Periodic P = [[0,1],[1,0]]: Oscillates forever. ② Two absorbing states: It converges, but the destination depends on the starting point. → Buttons in Figure 2
Q4Since a stationary distribution doesn't change even after another transition, does that mean the outflow and inflow are equal?02 · Stationary Distribution
  • Yes (global balance). For every state, total inflow = total outflow. It is μ* = μ*P written out for each state.
  • They don't need to be equal for every pair (detailed balance is a stronger condition). A cyclic chain 1→2→3→1 also has a uniform stationary distribution.
Q5The explanation that "Markov is a property of state representation" is difficult. Please explain it more simply.03 · Markov Property
  • A single photo of a thrown ball (position only) doesn't tell you if it's going up or down. Previous photos help → Not Markov.
  • If you capture (position, velocity), previous photos provide no additional information → Markov. → Figure 3
  • It's the same world, but depending on the state definition, it can be Markov or not. That's why state design is part of RL problem formulation. If information is lacking, attach past observations (frame stacking, RNN).
Q6RL is learning to create a policy. Is that policy essentially finding the states and transition probabilities of a Markov chain? Does reward convergence mean the chain structure no longer changes?07 · MDP Preview
  • Half correct. States and dynamics p(s'|s,a) are determined by the environment (model-based RL estimates these).
  • Once a policy is set, a chain Pπ(s'|s) = Σa π(a|s)p(s'|s,a) is formed. Policy selection = choosing the chain to be created. A good policy creates a chain that stays in high-reward states for longer.
  • Convergence has two meanings: ① Convergence of learning (policy fixed → chain fixed → curve flattens) ② Convergence of distribution under a fixed policy (μt → dπ). Even if the curve is flat, optimality is not guaranteed.
Q7What is the exact definition of an episode?04 · Episode
  • A single trajectory from initial state S0 ~ μ0 until reaching a terminal (absorbing) state (time T, random variable). It resets after finishing.
  • If there is termination, it's an episodic task; if not, it's a continuing task (γ < 1).
  • Pitfall: Being cut off by a time limit (truncation) is not termination. Distinction between terminated/truncated in gymnasium. If truncated, do not set V(sT) to 0.
Q8So a bandit has one state and returns to itself probabilistically?04 · Episode
  • One state is correct. However, it always returns to itself with probability 1 (P = [1]). There is no randomness in the transition.
  • Randomness exists only in the reward. Actions only change the reward, not the next state. It can be viewed as "one pull = an episode of length 1."
Q9Does one episode end when it completes a task and reaches the completion (absorbing) state? When a robot lifts an object, if the height doesn't change, is that an absorbing state and thus the end?04 · Episode
  • The big picture is correct: Reset → Attempt → Termination condition = 1 episode. → Figure 4
  • Correction: "Height not changing" is not termination. Holding it still is still an ordinary state where movement is possible. Termination is defined by the designer: Success (z ≥ 30cm), Failure (dropping, collision).
  • An absorbing state is a mathematical device (only goes to itself after termination, reward 0). Time limits are truncation.
  • Pitfall: If there is z reward every step + termination on success, hovering just below the goal might be beneficial (reward hacking). → Figure 7
Q10What are reward shaping and reward hacking?06 · Reward Design
  • Shaping: Adding intermediate rewards (approach, grasp, height) to guide the path because sparse rewards alone don't allow learning. If it diverges from the goal, the optimal policy changes. A safe form is potential-based F = γΦ(s') − Φ(s) (policy ranking invariant).
  • Hacking: Agents maximize numbers, not intentions. Examples: Hovering at 29cm, standing up objects, spinning boats in CoastRunners, simulation physics bugs, RLHF sycophancy.
  • Countermeasures: Keep rewards simple, clarify termination conditions, verify learned behavior with video.
Q11Does the discount rate determine how far into the future (steps) to consider?05 · Discount Rate
  • Yes. However, it doesn't cut off sharply but decreases smoothly by γk. If γ = 0.9, it's 0.35 after 10 steps and 0.1 after 22 steps. It roughly looks ahead to 1/(1−γ) steps. → Figure 5
  • Half-life = ln 0.5 / ln γ (0.9 → 6.6 steps, 0.99 → 69 steps).
Q12Does the reward obtained in the future get reflected in the current state? Is it about changing the policy? Or is it about deciding which action to take? Please explain with a large-scale example.05 · Big Picture
  • All three are correct, and there is an order. ① Evaluation: Pull future rewards into V(s) (Bellman). ② Selection: Compare the scores of states reachable by each action (Q). ③ Improvement: Modify the policy accordingly → back to ① (GPI).
  • Corridor example: +1 upon reaching G, γ = 0.9, "always right" → V = 0.729, 0.81, 0.9, 1. The reward propagates backward, creating an uphill terrain. At S1, left (0.729) vs. right (0.9) → choose right. → Figure 6
  • If γ = 0.5, the values are 0.125, 0.25, 0.5, 1 → from far away, the goal is barely felt.
  • 🤖 A robot compresses the future "reach 30cm +10" into V(s) and simply chooses the direction where the score increases at each moment.
Q13What if we give an infinite score upon reaching 30cm, or give a reward exponentially based on height?06 · Reward Design
  • Infinite: As long as the probability of success is not 0, V = ∞ for all policies → incomparable. Numerically results in inf/NaN.
  • Very large finite value: Scaling the entire reward by a factor c does not change the optimal policy. What matters is the ratio. If it's too large, shaping gets buried and variance increases, leading to instability → use reward scaling, clipping.
  • exp(z): The signal near the bottom is weak, slowing early learning, and "hovering" hacking becomes severe near the peak.
  • Good exponential: Error kernel exp(−‖error‖²/σ) ∈ (0, 1]. Standard in walking robot velocity tracking rewards, etc.
  • Preventing hovering: Terminate + bonus on success, time penalty per step, potential-based shaping.
Q14What are PPO and POMDP? (Terms only)07 · Terminology
  • PPO (Proximal Policy Optimization, 2017): A policy gradient family method. It increases the probability of actions with positive advantage and decreases it for negative advantage, but clips the probability ratio to [1−ε, 1+ε] to prevent changes from being too large at once. Standard in robot locomotion and RLHF (09).
  • POMDP: An MDP where you only see observations o ~ O(o|s) instead of the true state. Camera occlusion, sensor noise, invisible mass/friction. If replaced with belief state b(s), it becomes an MDP again. In practice, use history, RNN. → Figure 11
Q15You said "if you know Q*, you know everything." What do Q and Q* (Q prime?) each mean? With a large-scale example.08 · Optimality
  • Notation: Q* is "Q star" = optimal. Q′ (prime) is a separate notation referring to the Q of the next state or the target network.
  • Qπ(s,a): Take action a now, then follow current habits. Q*(s,a): Take action a now, then act optimally.
  • Commute: Habit π always takes the city route (20 min) at intersection B. At A, highway (10 min) vs. national road (25 min). Qπ(highway) = −30 < Qπ(national road) = −25, so the national road looks better, but Q*(highway) = −18 is the correct answer. → Figure 9
  • Qπ can lead to misjudging even the first choice due to subsequent habits. Since Q* assumes optimal future actions, just taking argmax is sufficient.
  • If you correct B's habit using Qπ (detour −8 > city −20) and re-evaluate, A's judgment also changes → Q*.
Q16So the meaning of the symbols Q and Q* is the difference between "normal score" vs. "score when taking optimal actions"?08 · Optimality
  • Correct. It is accurate to distinguish them into three: Qπ = the true score when following policy π, Q* = the true score when acting optimally (= Qπ*), Q = the algorithm's estimate (table, neural network).
  • Always Qπ ≤ Q*. In papers/code, Q without a superscript usually refers to "the current learning estimate." The Q(a) in 01 was also an estimate of q*(a).

✓Concepts That Were Confusing

  • Time Homogeneity: Transition rule P is fixed. The distribution μt may change. Q1
  • Non-stationarity = Missing State Variables: Including temperature, wear, and time in the state restores homogeneity. Q2
  • Convergence is Conditional: Requires irreducibility + aperiodicity. Periodic chains oscillate; reducible chains depend on the starting point. Q3
  • Stationary Distribution = Flow Balance: Inflow equals outflow. Q4
  • Markov is a Property of State Representation: A single photo vs. (position, velocity). Q5
  • Policy Selection = Chain Selection: Dynamics are the environment's; the policy is mine. Pπ = Σ π p. Q6
  • Episodes and Termination: Termination is defined by the designer. Truncation ≠ termination. No change in height does not imply termination. Q7 · Q9
  • Bandit Transitions Stay Put with Probability 1: Randomness exists only in rewards. Q8
  • Shaping vs. Hacking: Guiding the path vs. exploiting numerical loopholes. Potential-based shaping is safe. Q10
  • γ = Soft Horizon: Weights γk, horizon ≈ 1/(1−γ). Q11
  • Evaluation → Selection → Improvement: Future rewards propagate to V, are selected via Q, and the policy is updated. Q12
  • Rewards: Ratio and Shape Matter More Than Magnitude: Infinity is not allowed; use a bounded kernel exp(−error²). Q13
  • Qπ / Q* / Q: True score of the current habit / True optimal score / My estimate. Q′ is separate. Q15 · Q16
