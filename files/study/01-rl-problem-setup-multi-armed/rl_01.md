## 1. RL 문제 설정: 상호작용 루프

매 시점 t마다 에이전트와 환경이 이렇게 주고받는다.

```
S_t  →  [agent] A_t ~ π(·|S_t)  →  [env] (R_{t+1}, S_{t+1}) ~ p(·,·|S_t, A_t)  →  ...
```

- **상태 S_t**: 지금 상황
- **행동 A_t**: 정책 π가 고른 행동
- **보상 R_{t+1}**: 행동의 결과로 받는 점수
- **다음 상태 S_{t+1}**: 환경의 동역학 p가 정한다

목표는 누적 보상(return)의 기댓값을 최대화하는 정책을 찾는 것이다.

$$\max_\pi \; \mathbb{E}_\pi[G_t], \qquad G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots$$

환경의 동역학 p는 **모른다고 가정**한다. 경험으로만 배워야 한다. 이 점이 p를 알고 시작하는 고전 제어 이론과 갈라지는 지점이다.

## 2. 지도학습과 뭐가 다른가: 세 가지 축

| 축 | 지도학습 | RL |
|---|---|---|
| ① 피드백 종류 | instructive: 정답 라벨 y를 준다 | **evaluative**: 고른 행동의 점수만 준다. 다른 행동을 했으면 어땠을지는 모른다 |
| ② 데이터 분포 | i.i.d., 고정 | **정책이 데이터 분포를 바꾼다**. 어디를 가보느냐가 무엇을 배우느냐를 결정한다 |
| ③ 시간 구조 | 샘플끼리 독립 | **보상이 늦게 온다**. 100스텝 전 행동이 원인일 수 있다 → credit assignment 문제 |

이 축으로 문제들을 계층으로 정리할 수 있다.

| 문제 | 가진 축 | 예 |
|---|---|---|
| Multi-armed bandit | ① | 슬롯머신, A/B 테스트 |
| Contextual bandit | ① + 상태(내 행동과 무관하게 바뀜) | 추천 시스템 |
| MDP (full RL) | ① + ② + ③ | 게임, 로봇 제어 |

bandit부터 하는 이유: **탐험 문제만 따로 떼서** 볼 수 있기 때문이다.

## 3. 🤖 로봇에서 보면

| 요소 | 예: 로봇팔로 물체 집기 |
|---|---|
| State | 관절 각도·각속도, 그리퍼 상태, 물체 pose. 실제로는 카메라·센서 **observation**이라 엄밀히는 POMDP (02에서 다룸) |
| Action | 관절 토크, 관절 위치 목표값(PD 제어기가 추종), end-effector 델타. **action space 선택이 학습 난이도를 크게 좌우한다** |
| Reward | dense: `-‖x_ee − x_obj‖ − c‖a‖² + bonus·grasped` / sparse: 성공 1, 실패 0 |
| Step | 제어 주기. 50Hz면 10초 에피소드가 500스텝 → ③ credit assignment가 심각해진다 |

- **Sparse reward vs reward shaping**: sparse는 학습 신호가 거의 없다. shaping을 하면 **reward hacking**이 생긴다(예: 물체 근처에서 떨기만 해도 distance 보상을 받음).
- **탐험 비용**: 시뮬레이션은 공짜지만 실제 로봇은 부서진다. 그래서 시뮬레이션에서 학습하고 옮기는 sim-to-real이 주류다.
- **②의 귀결**: 정책이 바뀌면 방문하는 상태 분포도 바뀐다. imitation learning이 실패하는 이유(compounding error)도 이것이다 (10에서 다룸).

## 4. Multi-armed Bandit이란

카지노 슬롯머신의 별명이 **"one-armed bandit"(외팔이 강도)**이다. 레버가 팔 하나고, 돈을 뺏어가서 강도다. 그 기계가 여러 대면 **multi-armed bandit**이다.

**설정**
- 기계 k대. 기계 a를 당기면 보상 R ~ ν_a. 진짜 평균 **q\*(a) = E[R | A=a]**는 모른다.
- 예: 기계 A, B, C의 당첨 확률이 실제로는 0.3, 0.5, 0.7이지만 우리는 모른다.
- 매 라운드 하나를 골라 당기고, T번 동안 누적 보상을 최대화한다.

**어려운 점**: 고른 기계의 결과만 보인다.
- 초반에 A가 운 좋게 3연속 당첨되면, A만 당기다가 C가 더 좋다는 걸 영영 모를 수 있다.
- 반대로 골고루 계속 당기면, 좋은 기계를 알고도 나쁜 기계에 기회를 낭비한다.
- → **exploration(알아보기) vs exploitation(아는 걸 써먹기)** 딜레마.

**bandit과 MDP의 결정적 차이**: bandit에서 팔을 당기면 **보상만** 결정된다. 다음 라운드에도 같은 기계, 같은 확률이다. MDP에서는 행동이 **다음 상태(방)까지** 바꾼다.

```
Bandit:  [상태 1개] --a--> 보상 r --> [같은 상태] --a--> 보상 r --> ...
MDP:     s₀ --a₀--> (r₁, s₁) --a₁--> (r₂, s₂) --> ...   ← p(s'|s,a): 행동이 다음 상태를 바꿈
```

| | 상태 전이 | 보상 | 행동 |
|---|---|---|---|
| Markov chain | ✅ | ❌ | ❌ |
| MRP | ✅ | ✅ | ❌ |
| MDP | ✅ | ✅ | ✅ |
| Bandit | ❌ (상태 1개) | ✅ | ✅ |

**bandit = 상태가 1개뿐이라 모든 행동이 제자리로 돌아오는 MDP.**

## 5. 가치 추정과 증분 업데이트

### target vs 진짜 목표
- **진짜 목표 점**: q\*(a). 기계의 진짜 평균. 알 수 없고 직접 관측할 수도 없다.
- **target**: 이번에 관측한 보상 R_n. q\*의 **noisy한 샘플**. 매번 흔들리는 과녁이다.
- 흔들리는 과녁 쪽으로 조금씩 끌려가다 보면, 흔들림이 평균으로 상쇄되어 q\*에 수렴한다.

### 식의 유도: 표본평균을 다시 쓴 것

```
Q_{n+1} = (R_1 + ... + R_n) / n
        = ( R_n + (n−1)·Q_n ) / n
        = Q_n + (1/n)·(R_n − Q_n)
          ───   ───   ────────────
          옛 값  보폭   오차 = (target − 옛 값)
```

**새 추정 = 옛 추정 + 보폭 × (target − 옛 추정)**

### 숫자 예 (보상 1, 0, 1, 1)

| n | R_n (target) | 보폭 1/n | 업데이트 | Q |
|---|---|---|---|---|
| 1 | 1 | 1 | 0 + 1·(1−0) | 1.0 |
| 2 | 0 | 1/2 | 1 + ½·(0−1) | 0.5 |
| 3 | 1 | 1/3 | 0.5 + ⅓·(1−0.5) | 0.667 |
| 4 | 1 | 1/4 | 0.667 + ¼·(1−0.667) | 0.75 = (1+0+1+1)/4 |

### ML 관점
L(Q) = ½(R − Q)²에 SGD 한 스텝을 하면 Q ← Q + α(R − Q). **target을 라벨로 놓은 MSE regression을 SGD로 하는 것**과 같다.

### 고정 보폭 α
1/n 대신 고정 α를 쓰면 다음과 같이 된다.

$$Q_{n+1} = (1-\alpha)^n Q_1 + \sum_{i=1}^{n} \alpha(1-\alpha)^{n-i} R_i$$

오래된 보상일수록 가중치가 지수적으로 줄어든다(exponential recency-weighted average). 보상 분포가 시간에 따라 변하는 **nonstationary** 환경을 따라갈 수 있다 (🤖 마모로 동역학이 변하는 로봇).

수렴 조건(Robbins–Monro): **Σα_n = ∞** (초기값에서 어디로든 갈 만큼 충분히 움직임), **Σα_n² < ∞** (보폭이 줄어서 노이즈가 사라짐). 1/n은 둘 다 만족한다. 고정 α는 두 번째를 어겨서 완전히 수렴하지 않지만, 그 덕분에 변화를 따라간다.

### 앞으로 바뀌는 건 target뿐

| 알고리즘 | target |
|---|---|
| Bandit | R (방금 받은 보상) |
| Monte Carlo (04) | G_t (에피소드 끝까지 실제로 받은 보상 합) |
| TD (05) | R + γ·V(s') (보상 한 스텝 + 다음 상태의 **추정치**) |
| Q-learning / DQN (05, 07) | R + γ·max Q(s', ·) |

TD부터는 target 안에 내 추정치가 들어가서, 내가 움직이면 과녁도 같이 움직인다. DQN에 target network가 필요한 이유다.

## 6. 성능 척도: Regret

**regret = "처음부터 최적 기계를 알았다면 받았을 기대 보상" − "실제로 받은 기대 보상"**

μ\* = max_a q\*(a), **gap Δ_a = μ\* − q\*(a)** (기계 a를 한 번 잘못 고를 때마다 생기는 손해)라 하면 다음과 같다.

$$\text{Regret}(T) = T\mu^* - \mathbb{E}\Big[\sum_{t=1}^T R_t\Big] = \sum_a \Delta_a \cdot \mathbb{E}[N_T(a)]$$

(ΣN(a) = T를 이용: Tμ\* − ΣN(a)q\*(a) = ΣN(a)(μ\* − q\*(a)))

### 왜 gap을 곱하나: 실수마다 손해 크기가 다르다
최적 0.70, B 0.69 (gap 0.01), C 0.10 (gap 0.60)일 때:

| 상황 | 틀린 횟수 | 실제 손해 |
|---|---|---|
| B를 100번 | 100 | 100 × 0.01 = **1.0** |
| C를 10번 | 10 | 10 × 0.60 = **6.0** |

횟수만 세면 B 쪽이 나빠 보이지만, 실제 손해는 C 쪽이 6배다.

### regret은 성적표다
- **정답 μ\*를 알아야 계산된다** → 에이전트 자신은 실행 중이든 끝난 뒤든 계산할 수 없다. 학습 신호가 아니다.
- 쓰임:
  - **실행 전**: 이론적 보장 (예: UCB는 regret ≤ C·log T)
  - **실행 중/후**: 정답을 아는 실험자(시뮬레이션)가 매 스텝 누적 regret을 곡선으로 그려 평가
  - **실제 배포**: 계산 불가 → 누적 보상 같은 대리 지표 사용
- ML의 **test loss**와 같은 위치다.

### 보상 곡선과의 관계
- 스텝별 regret = μ\* − E[R_t] = 최적선과 보상 곡선 사이의 **높이**
- 누적 regret = 그 사이의 **넓이**
- 보상 곡선은 **"지금 얼마나 잘하나"**, 누적 regret은 **"잘하게 될 때까지 얼마나 손해 봤나(학습 비용)"**. 최종 성능이 같아도 늦게 도달하면 regret이 크다.
- 🤖 실로봇처럼 학습 중 실수가 실제 비용이면 regret 관점이 중요하다. 딥RL의 sample efficiency도 같은 생각이다.

### 좋은 알고리즘의 기준
**Lai–Robbins 하한**: 어떤 합리적인 알고리즘도 regret이 Ω(log T)보다 작을 수 없다(나쁜 팔도 log T번 정도는 확인해야 함). → **O(log T) regret이면 차수로 최적**이다.

## 7. 단순한 전략

| 전략 | 방법 | 문제 |
|---|---|---|
| **Greedy** | 항상 argmax Q | 초반에 최적 팔이 운 나쁘게 낮게 나오면 다시 안 고름 → **선형 regret** |
| **ε-greedy** | 확률 ε로 무작위, 나머지는 greedy | 최적 팔을 알아낸 뒤에도 ε/k 비율로 나쁜 팔을 계속 고름 → **선형 regret** (ε을 줄이는 스케줄이면 로그 가능하지만 gap에 맞춰 튜닝 필요) |
| **Optimistic init** | Q_0를 크게 잡음 | 모든 팔이 초반에 한 번씩 시도되지만, 탐험이 초반에만 일어남 |

ε-greedy의 근본 한계: **"모르는 것"과 "나쁜 것"을 구분하지 않고** 똑같이 무작위로 탐험한다. 좋은 탐험은 **불확실성에 따라** 해야 한다 → UCB, Thompson sampling.

## 8. UCB: 모르면 좋게 봐준다

원칙: **optimism in the face of uncertainty**. 각 기계의 "최대로 잡으면 이 정도까지 좋을 수 있다(포텐)"를 계산해서 가장 높은 기계를 고른다.

```
UCB_t(a) =    Q(a)     +   c · √( ln t / N(a) )
            ─────────      ──────────────────────
            지금 추정치     불확실성 보너스
            (활용)          (탐험)
```

- **N(a)↑ → 보너스↓**: 많이 당겨봤으면 "이제 충분히 안다".
- **ln t↑ → 보너스 서서히↑**: 오래 안 고른 기계는 가만히 있어도 포텐이 올라가 언젠가 다시 확인받는다.
- 초기: N(a) = 0이면 식이 정의되지 않으므로 **모든 팔을 한 번씩 먼저 당긴다**(UCB = ∞로 취급).

**UCB가 높은 이유는 둘 중 하나다**: 진짜 좋거나(Q 높음), 아직 몰라서(보너스 큼). UCB가 낮다 = 충분히 봤는데도 낮다 = 나쁘다고 확인됐다.

### 숫자 예 (t = 100, c = √2)

| 기계 | Q | N | 보너스 √(2·ln100 / N) | UCB |
|---|---|---|---|---|
| A | 0.60 | 80 | 0.34 | 0.94 |
| B | 0.40 | 5 | 1.36 | **1.76 ← 선택** |
| C | 0.55 | 15 | 0.78 | 1.33 |

B는 평균이 제일 낮지만, 5번만 당겨봐서 0.4가 운인지 실력인지 모른다 → 확인한다. 더 당겨서 여전히 낮으면 보너스가 줄어 자연스럽게 버려진다.

### 유도: Hoeffding 부등식
보상 ∈ [0, 1]이면 다음이 성립한다.

$$P(q^* > Q + u) \le e^{-2Nu^2}$$

우변을 δ로 놓고 풀면 u = √(ln(1/δ) / 2N), 즉 "q\*는 확률 1−δ로 Q + u 이하"라는 **신뢰구간 상한(Upper Confidence Bound)**이 나온다.

δ = t⁻⁴로 시간에 따라 줄이면 u = √(4 ln t / 2N) = **√(2 ln t / N)** → UCB1 (Auer et al., 2002), **c = √2**.

- **왜 t⁻⁴인가**: 최적이라서가 아니라 증명용이다. 신뢰구간이 틀릴 확률을 모든 (t, N)에 대해 더해도(union bound) 유한한 상수가 되어야 regret 증명이 된다.
- **보상 범위가 [a, b]면** 보너스를 (b − a)배로 키운다. 실전에서는 c를 튜닝하며, √2보다 작게 써도 대체로 잘 된다.
- **보너스가 √(t/N)이면?** 보너스가 너무 빨리 커져서 과하게 탐험한다 → regret이 T의 다항식으로 커진다. ln t의 느린 증가가 "log만큼만 확인"을 만든다.

### gap과 로그 regret의 연결
UCB가 기계 a를 버리려면 a의 포텐이 최적값 아래로 내려가야 한다.

```
q*(a) + 보너스 < μ*  →  보너스 < Δ_a  →  √(2 ln t / N) < Δ_a  →  N > 2 ln t / Δ_a²
```

**보너스(불확실성 폭)가 gap보다 작아질 때까지 당긴다.**
- 0.70 vs 0.10 (gap 큼): 신뢰구간 ±0.5로도 구분 → 몇 번이면 끝
- 0.70 vs 0.69 (gap 작음): ±0.01보다 좁아야 구분 → 아주 많이 당김

| gap Δ | 당김 횟수 ∝ 1/Δ² | 손해 = Δ × 횟수 ∝ 1/Δ |
|---|---|---|
| 0.6 | 2.8 × ln T | 1.7 × ln T |
| 0.2 | 25 × ln T | 5 × ln T |
| 0.01 | 10000 × ln T | 100 × ln T |

$$\text{Regret}(T) \lesssim \sum_a \Delta_a \cdot \frac{8\ln T}{\Delta_a^2} = \sum_a \frac{8 \ln T}{\Delta_a} = O(\log T)$$

(증명에서는 상수가 8이 된다.)

**로그 regret의 의미**

| T | ln T | 고정 ε-greedy 실수 횟수 (∝ T) |
|---|---|---|
| 1,000 | 6.9 | ~100 |
| 1,000,000 | 13.8 | ~100,000 |

T가 1000배 늘어도 UCB의 실수는 2배만 는다. 스텝당 손해가 0으로 간다.

### 연결
- MDP: 방문 횟수 N(s, a)에 보너스 → **count-based exploration**, 연속 상태에서는 **curiosity / RND**
- AlphaGo/AlphaZero의 트리 탐색 **PUCT** = UCB의 변형
- 🤖 낙관주의는 실로봇에서 **위험**하다(안 해본 큰 토크 시도). safe RL, **offline RL(10)**은 반대로 **비관주의**를 쓴다.

## 9. Thompson Sampling: 믿음에서 뽑는다

UCB가 기계마다 숫자 하나(상한)를 들고 다닌다면, Thompson sampling은 **"진짜 확률이 이쯤일 것 같다"는 분포 전체**를 들고 다닌다.

**알고리즘**
1. 각 기계의 믿음 분포에서 값을 하나씩 **무작위로 뽑는다**.
2. 뽑은 값이 가장 큰 기계를 당긴다.
3. 결과로 그 기계의 믿음 분포를 업데이트한다.

**Beta 분포** (보상이 0/1일 때)
- Beta(α, β): 대략 α − 1 = 당첨 수, β − 1 = 꽝 수
- 시작: Beta(1, 1) = 균등분포 ("아무것도 모름")
- 업데이트: 당첨 → α += 1, 꽝 → β += 1 (Beta–Bernoulli 켤레라서 카운트 더하기로 끝남)
- 평균 α/(α+β). 관측이 쌓일수록 분포가 뾰족해진다.

### 숫자 예

| 기계 | 기록 | 믿음 | 평균 | 90% 범위 |
|---|---|---|---|---|
| A | 8승 2패 | Beta(9, 3) | 0.75 | 0.53 ~ 0.92 |
| B | 1승 1패 | Beta(2, 2) | 0.50 | 0.14 ~ 0.86 |

대부분 A의 샘플이 더 크지만, B는 분포가 넓어서 **약 18% 확률로 B의 샘플이 A를 이긴다** → 그때 B를 탐험한다. B가 진짜 0.5면 분포가 뾰족해지며 버려지고, 사실 0.9였다면 발견된다.

→ 각 기계를 **"그 기계가 최적일 확률"만큼** 고르는 셈이다 (**probability matching**).

### UCB와 비교

| | UCB | Thompson sampling |
|---|---|---|
| 불확실성 표현 | 신뢰구간 (빈도주의) | 사후 분포 (베이지안) |
| 고르는 방식 | 상한을 계산해 결정론적으로 argmax | 분포에서 샘플을 뽑아 확률적으로 argmax |
| 탐험의 원리 | 모르면 상한이 높다 | 모르면 분포가 넓어 가끔 높게 뽑힌다 |
| 튜닝 | c | 사전분포 (보통 Beta(1,1)) |
| 이론 | O(log T) | O(log T), 상수까지 Lai–Robbins 하한에 맞음 |
| 실전 | 좋음 | 보통 UCB보다 좋거나 비슷 (Chapelle & Li, 2011) |

공통점: **불확실할수록 더 탐험한다.** UCB는 보너스 항으로, Thompson은 분포의 폭으로 구현한다.

**장점**: 튜닝할 c가 없다 / 연속 보상(Gaussian), context(Bayesian 선형회귀)로 확장이 쉽다 / 무작위성 덕분에 지연·배치 피드백에 강하다.
**단점**: 사후분포를 계산할 수 있어야 한다. 신경망에서는 근사가 필요하다.

### 연결
- 딥RL 탐험: 네트워크 **앙상블**에서 하나를 뽑아 행동 (Bootstrapped DQN, 07)
- 🤖 제어기 게인/보행 파라미터 튜닝 = **팔이 연속인 bandit** → GP 사후분포 + UCB/Thompson = **Bayesian optimization**. 실로봇에서 적은 시도로 파라미터를 찾을 때 실제로 쓴다.
- 🤖 Model-based 로봇 학습(10): PETS는 동역학 모델 앙상블에서 샘플해서 계획한다.

## 10. 전체 정리 & 다음 섹션 연결

| 전략 | 탐험 방식 | regret | 한 줄 |
|---|---|---|---|
| Greedy | 없음 | 선형 | 초반 운에 갇힘 |
| ε-greedy | 무작위 (방향 없음) | 선형 (고정 ε) | 간단하지만 나쁜 걸 알아도 계속 고름 |
| UCB | 불확실성 보너스 (낙관) | O(log T) | 포텐 상한이 제일 높은 놈 |
| Thompson | 사후분포 샘플링 | O(log T) | 최적일 확률만큼 고르기 |

**비교 실험** (lecture.html 그림 12에서 브라우저로 직접 계산: 기계 10대, 당첨 확률 0.05~0.95 랜덤, T = 5000, 100회 평균, 시드 2026)

| 알고리즘 | 평균 누적 regret (T = 5000) | 곡선 모양 |
|---|---|---|
| Greedy | 169 | 직선 |
| ε-greedy (ε = 0.1) | 227 | 직선 |
| UCB (c = 0.5, 튜닝) | 62 | 로그 |
| UCB1 (c = √2, 이론값) | 279 | 로그지만 초반 과탐험으로 상수가 큼 |
| Thompson (Beta(1,1)) | 54 | 로그 |

→ 이론값 c = √2는 "어떤 bandit에서도 성립하는 보장"용이라 넉넉하게 잡혀 있어서, 이 정도 T에서는 오히려 greedy보다 손해가 크다. 실전에서는 c를 튜닝한다 (Q9). Thompson은 튜닝 없이도 가장 좋다.

**꼭 가져갈 세 가지**
1. 증분 업데이트 `Q ← Q + α(target − Q)`는 끝까지 반복되는 뼈대다. 바뀌는 건 target뿐이다.
2. 좋은 탐험 = 불확실성에 따른 탐험. MDP, 딥RL, 로봇 학습까지 계속 같은 문제로 돌아온다.
3. bandit에는 상태 전이가 없다. 행동이 다음 상태를 바꾸는 순간 MDP가 된다 → **02 MDP & Bellman 방정식**

## 11. 확인 문제

**문제 1.** ε = 0.1, k = 10일 때, 최적 팔을 완벽히 알아낸 뒤에도 스텝당 평균 regret은?
> 확률 ε로 k개 팔 중 무작위 → 스텝당 regret = ε · (1/k)Σ_a Δ_a = 0.1 · Δ̄ (Δ̄: 최적 팔 포함 k개 팔의 평균 gap). 상수이므로 T번이면 선형으로 쌓인다.

**문제 2.** 고정 α 업데이트에서 i번째 보상의 가중치는? 왜 Robbins–Monro 조건이 필요한가?
> 가중치 α(1−α)^{n−i}, 오래될수록 지수적으로 감소. Σα = ∞는 초기값의 영향을 지우고 어디로든 갈 수 있게, Σα² < ∞는 보폭이 줄어 노이즈가 사라지게 한다. 고정 α는 두 번째를 어겨 수렴하지 않지만 nonstationary를 따라간다.

**문제 3.** UCB에서 N(a) = 0이면 어떻게 하나? 보너스를 √(t/N)으로 바꾸면?
> 모든 팔을 한 번씩 먼저 당긴다. √(t/N)은 보너스가 너무 빨리 커져 과탐험 → regret이 log가 아니라 다항식으로 커진다.

**문제 4.** 보상 범위가 [−100, 0]인 로봇 문제에 UCB1을 쓰려면?
> Hoeffding의 범위 항 때문에 보너스를 100배(범위 폭) 키우거나, 보상을 [0, 1]로 정규화한다.

**문제 5.** 로봇 문제 하나를 bandit으로 모델링하고, "상태가 없다"는 가정이 어디서 깨지는지 말해보라.
> 예: grasp 후보 5개 중 선택. 물체 위치·자세가 매번 바뀌면 상황(context)이 생겨 contextual bandit이 되고, 이전 grasp 실패가 물체를 밀어 다음 상황을 바꾸면 MDP가 된다.

## 12. 질문 & 답변

### Q1. (bandit) bandit이 뭔지 잘 모르겠어.
- 이름은 슬롯머신의 별명 "one-armed bandit(외팔이 강도)"에서 왔다. 팔이 여러 개면 multi-armed bandit.
- 설정: 보상 분포를 모르는 슬롯머신 k대. 매 라운드 하나를 골라 당기고 보상을 받는다. T라운드 동안 누적 보상을 최대화한다.
- 핵심 난점: 고른 기계의 결과만 보인다 → 좋아 보이는 걸 계속 쓸지(exploitation), 덜 해본 걸 알아볼지(exploration).
- 실제 예: A/B 테스트, 임상시험 배정, 광고/추천, 로봇 grasp 후보 선택, 제어기 하이퍼파라미터 선택.

### Q2. (bandit) 마르코프 체인 같은 내용은 안 해도 돼?
- 한다. 02에서 Markov chain → MRP → MDP 순서로 쌓는다.
- bandit은 상태가 하나뿐인 특수한 MDP라 상태 전이가 없고, Markov 성질을 따질 필요가 없다. 그래서 탐험 문제만 따로 보려고 먼저 다룬다.

### Q3. (증분 업데이트) target이 뭐야? 도달하려는 목표 점이야?
- 진짜 목표 점은 q\*(a) = E[R|a]. 알 수 없다.
- target은 이번 스텝에 관측한 R_n. q\*의 noisy 샘플이자 기댓값이 q\*인 "흔들리는 과녁"이다. 이번 업데이트에서 Q를 그쪽으로 조금 끌어당긴다.
- 표본평균을 정리하면 그대로 나온다: Q_{n+1} = Q_n + (1/n)(R_n − Q_n).
- SGD 관점: L = ½(R − Q)²의 경사하강. 기대 업데이트가 0인 점이 Q = q\*.
- 이후 섹션에서는 target만 바뀐다: MC는 G_t, TD는 R + γV(s'), Q-learning은 R + γ max Q(s',·).

### Q4. (regret) regret은 후회 같은 거야? 나쁜 선택 횟수에 gap은 왜 곱해?
- 그렇다. "처음부터 최적 팔을 알았다면 받았을 기대 보상 − 실제로 받은 기대 보상".
- 실수마다 손해 크기가 다르다. 한 번 잘못 고를 때 손해가 Δ_a이니 횟수 × gap = 총 손해.
- 예: 최적 0.70일 때 B(0.69)를 100번 → 손해 1.0, C(0.10)를 10번 → 손해 6.0. 횟수만 세면 잘못된 결론이 나온다.
- 기댓값 q\*로 계산하는 이유: 운을 실력으로 치지 않기 위해서.

### Q5. (bandit vs MDP) 팔을 당긴다는 게 마르코프 체인에서 다음 state를 결정하는 거야?
- 아니다. bandit에서 팔을 당기면 보상만 결정된다. 다음 라운드도 같은 기계, 같은 분포다.
- MDP에서는 행동이 보상과 다음 상태 p(s'|s,a)를 함께 바꾼다.
- 계층: Markov chain(상태 전이만) → MRP(+보상) → MDP(+행동). bandit은 상태가 1개이고 모든 행동이 제자리로 돌아오는 MDP다.

### Q6. (이해 확인) 평균을 내면 확률을 알게 되고, 알고리즘마다 target과 당기는 식이 다른 거지? regret은 썩은 머신을 빨리 버리게 해주는 거고? MDP는 행동과 보상이 다음 상태를 바꾸니 밴딧머신의 확률이 바뀌는 거야?
- 첫 번째는 맞다. 다만 bandit 알고리즘은 ① 추정(Q 갱신, target)과 ② 선택 규칙으로 나뉜다. bandit에서는 ①이 거의 같고(target = R) ②가 다르다. target이 달라지는 건 MDP부터다.
- regret은 알고리즘이 쓰는 도구가 아니라 **채점하는 성적표**다. μ\*를 모르니 알고리즘은 계산할 수 없다. "썩은 머신을 빨리 버리고 운빨을 가려내는" 건 UCB/TS가 불확실성을 정량화해서 하는 일이고, 그렇게 하는 알고리즘의 regret이 낮게 나온다.
- MDP: 다음 상태를 바꾸는 건 보상이 아니라 (현재 상태, 행동)이다. "확률이 바뀐다"보다 **"내 행동 때문에 다른 방으로 이동하고, 방마다 기계와 확률이 다르다"**가 정확하다.
  - 확률이 내 행동과 무관하게 시간에 따라 변함 → nonstationary bandit
  - 방이 바뀌지만 내 행동 때문이 아님 → contextual bandit
  - 방이 내 행동 때문에 바뀜 → MDP

### Q7. (regret) regret은 다 끝난 뒤의 사후평가야? 정답을 알아야 하는 거 아냐?
- 맞다. 정답 μ\*를 알아야 하므로 에이전트 자신은 절대 계산할 수 없다.
- 다만 "끝난 뒤에만"은 아니다. 정답을 아는 실험자는 시뮬레이션 중 매 스텝 누적 regret을 기록해 곡선으로 그린다. 곡선 모양(직선 vs 로그)이 알고리즘의 성질을 보여준다.
- 쓰임: ① 실행 전 이론적 보장(regret bound) ② 시뮬레이션 실험 평가 ③ 실제 배포에서는 계산 불가 → 대리 지표.
- 딥RL 실험은 보통 return 곡선을 보고하고, regret은 주로 이론 논문에서 쓴다.

### Q8. (MDP) 상태에서 행동하면 보상을 받고, 누적하면서 다음 방(처음 보는 선택지)으로 가서 또 행동하는 느낌이야?
- 흐름은 맞다: 상태 → 행동 → (보상, 다음 상태) → 반복. 할인된 보상 합 G가 최대화 대상이다.
- 수정 ①: 방은 **다시 방문**된다. 같은 칸, 같은 자세로 돌아오고 에피소드도 반복한다. 그래서 방 s에서 배운 걸 다시 왔을 때 쓸 수 있고, 학습이 가능하다.
- 수정 ②: 레버(행동 집합)는 보통 어느 방이나 같고, 결과(보상, 다음 방)가 방마다 다르다.
- 수정 ③: 누적 보상은 점수판에 쌓일 뿐 다음 방을 바꾸지 않는다. 다음 방은 (s, a)로만 정해진다.
- 🤖 로봇의 연속 상태 공간에서는 정확히 같은 상태를 다시 볼 일이 거의 없다 → "비슷한 방은 비슷하다"는 일반화(함수 근사, 06)가 필요하다.

### Q9. (UCB) 탐험 강도 c가 이론적으로 √2인 이유가 있어?
- Hoeffding 신뢰구간 u = √(ln(1/δ)/2N)에서 δ = t⁻⁴로 잡으면 u = √(2 ln t / N) → c = √2.
- t⁻⁴는 최적이라서가 아니라 증명용이다. 신뢰구간이 틀릴 확률을 모든 (t, N)에 대해 합해도(union bound) 유한한 상수여야 regret 증명이 된다.
- 보상 범위 [0,1] 가정이다. [a,b]면 (b−a)배. 실전에서는 c를 튜닝하고, √2보다 작게 써도 대체로 잘 된다.

### Q10. (UCB) UCB는 진짜 좋은지 구린지 판단하는 누적 지표네? 높은 놈은 포텐이 있으니 까보고, 낮은 놈은 포텐이 없다는 느낌?
- 거의 맞다. UCB = "최대로 잡으면 이만큼 좋을 수 있다"는 낙관적 상한, 즉 포텐이다.
- 주의: UCB가 높은 이유는 **진짜 좋거나, 아직 몰라서** 둘 중 하나다. 낮다는 건 충분히 봤는데도 낮다, 즉 나쁘다고 확인됐다는 뜻이다.
- Q, N은 누적되지만 ln t는 매 스텝 커진다. 오래 안 고른 기계는 가만히 있어도 UCB가 서서히 올라간다. 매 스텝 다시 계산하는 점수다.

### Q11. (UCB · regret) gap이 뭐였지? gap의 크기와 UCB, 로그 regret이 잘 연결이 안 돼.
- gap Δ_a = μ\* − q\*(a): 기계 a를 한 번 고를 때마다 생기는 손해. 진짜 값으로 정의되므로 알고리즘은 모른다.
- 연결: UCB가 기계 a를 버리려면 a의 상한이 μ\* 아래로 내려가야 한다 → 보너스 < Δ_a → N > 2 ln t / Δ_a². gap이 작을수록 구분하려면 신뢰구간이 좁아야 하니 많이 당긴다.
- regret 기여 = Δ × N ≈ ln T / Δ → 총 regret = Σ ln T / Δ_a = O(log T).
- 의미: T가 1000배 늘어도 ln T는 2배만 는다. 스텝당 손해가 0으로 간다. 고정 ε-greedy는 실수가 T에 비례한다.

### Q12. (regret) regret은 RL 전체를 돌린 후의 평가 지표야? 리워드 곡선 보고 "여기서 수렴하네" 하는 것처럼?
- 맞다. 실험자가 학습 과정 전체를 곡선으로 그려 평가하는 지표다.
- 보상 곡선과 같은 정보를 다르게 본 것이다. 스텝별 regret = 최적선과 보상 곡선 사이의 높이, 누적 regret = 그 넓이. 보상 곡선이 μ\*에 붙으면 누적 regret 곡선이 평평해진다.
- 보상 곡선은 "지금 얼마나 잘하나", 누적 regret은 "잘하게 될 때까지 얼마나 손해 봤나(학습 비용)". 최종 성능이 같아도 늦게 도달한 알고리즘은 regret이 크다.
- 🤖 시뮬레이션에서는 최종 성능이 주로 중요하지만, 실로봇처럼 학습 중 실수가 실제 비용이면 regret 관점이 중요하다.

## 13. 헷갈렸던 개념 체크리스트

- [x] **bandit**: 보상 분포를 모르는 슬롯머신 여러 대에서 고르기. 고른 것의 결과만 보인다 (Q1)
- [x] **target vs 목표**: 목표는 진짜 평균 q\*, target은 그 noisy 샘플인 흔들리는 과녁 (Q3)
- [x] **알고리즘의 두 부품**: 추정(target) + 선택 규칙. bandit에서는 선택 규칙이 차이 (Q6)
- [x] **regret = 성적표**: 정답을 아는 바깥 사람만 계산. 에이전트의 학습 신호가 아님. 누적 regret = 최적선과 보상 곡선 사이 넓이 (Q6, Q7, Q12)
- [x] **gap**: 한 번 잘못 고를 때의 손해. regret = Σ 횟수 × gap (Q4, Q11)
- [x] **bandit vs MDP**: 다음 상태를 바꾸는 건 보상이 아니라 행동. 방은 재방문된다 (Q5, Q6, Q8)
- [x] **UCB = 포텐**: 높은 이유는 "좋거나 모르거나". 보너스 < gap이 될 때까지 당김 → 로그 regret (Q10, Q11)
- [x] **c = √2**: Hoeffding + δ = t⁻⁴에서 나온 증명용 값. 실전은 튜닝 (Q9)
