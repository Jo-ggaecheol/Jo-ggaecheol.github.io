## 1. 왜 트랜스포머가 나왔나

언어를 이해한다는 건 **어떤 단어가 어떤 단어와 관련 있는지 아는 것**이다.

> "**그 동물**은 길을 건너지 않았다. 왜냐하면 **그것**이 너무 피곤했기 때문이다."

"그것"을 이해하려면 앞의 "그 동물"과 연결해야 한다.

**예전 방식: RNN.** 문장을 한 단어씩 순서대로 읽으면서 메모장 한 장에 요약을 덧쓴다.
- 문장이 길어지면 **앞 내용을 잊어버린다.**
- 앞 단어를 다 처리해야 다음으로 넘어갈 수 있어서 **병렬 처리가 어렵고 느리다.**

**트랜스포머의 아이디어 (2017, "Attention Is All You Need")**: 순서대로 읽지 말고, **모든 단어가 다른 모든 단어를 한 번에 직접 보게 하자.** 어디에 얼마나 집중할지 정하는 것이 **어텐션**이다.

| | RNN | 트랜스포머 |
|---|---|---|
| 읽는 방식 | 한 단어씩 순서대로 | 전체를 한 번에 |
| 먼 단어와의 관계 | 점점 잊음 | 어텐션으로 바로 연결 |
| 속도 | 병렬 처리 어려움 | 병렬 처리 가능 (GPU에 적합) |

## 2. 토큰과 임베딩

컴퓨터는 숫자만 계산할 수 있으니 문장을 숫자로 바꿔야 한다.

```
"나는 고양이를 좋아해"
  ↓ 토큰화          ["나", "는", "고양이", "를", "좋아", "해"]
  ↓ 토큰 ID         [312, 45, 8821, 67, 1590, 23]
  ↓ 임베딩          [[0.2, -1.3, 0.8, ...], ...]   (토큰마다 768개 숫자)
```

- **토큰**: 모델이 다루는 글자 조각. 자주 나오는 건 크게, 드문 건 잘게 자른다(BPE 등). 사전 크기는 보통 수만~십수만 개.
- **토큰 ID**: 사물함 번호일 뿐, 의미가 없다.
- **임베딩**: 토큰을 의미를 담은 벡터로 바꾼 것. **의미가 비슷하면 벡터도 비슷하다.** 각 숫자의 의미는 사람이 정하지 않고 **학습으로 정해진다.**
- 구현은 `(토큰 수 × 768)` 크기의 표 하나. ID번째 줄을 꺼내면 그 토큰의 벡터다.

한계: "배가 고프다"의 배와 "배를 타다"의 배가 **같은 벡터**다. → 3단계에서 해결한다.

## 3. 셀프 어텐션 (Q, K, V)

각 단어가 문장 속 다른 단어들을 보고 **자기 벡터를 문맥에 맞게 고치는 과정**이다.

| 역할 | 비유 | 의미 |
|---|---|---|
| **Query (Q)** | 검색어 | 나는 이런 정보가 필요해 |
| **Key (K)** | 책 표지 키워드 | 나는 이런 정보를 갖고 있어 |
| **Value (V)** | 책 내용 | 나를 고르면 이걸 줄게 |

계산 과정 ("배를 타고 바다로 갔다"의 "배"):
1. 임베딩에 학습된 행렬 W_Q, W_K, W_V를 곱해 Q, K, V를 만든다.
2. "배"의 Q와 모든 단어의 K를 **내적**한다 → **어텐션 점수**. 클수록 관련이 높다.
3. √d_k로 나누고 **softmax** → 합이 1인 **어텐션 가중치** (배 0.15, 를 0.02, 타고 0.45, 바다로 0.33, 갔다 0.05).
4. 가중치대로 V를 섞는다 → 문맥이 반영된 새 "배" 벡터 (탈것 쪽으로 이동).

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

- "셀프"인 이유: Q, K, V가 모두 **같은 문장**에서 나온다.
- 모든 단어가 이 계산을 **동시에** 한다(행렬 곱 한 번) → 병렬 처리.

## 4. 멀티헤드 어텐션

"**철수가** 어제 공원에서 산 빨간 **공을** 던졌다"에서 "던졌다"는 누가(철수), 무엇을(공), 언제(어제)를 동시에 알고 싶다. 어텐션 한 번이면 이 관계들이 평균내져 흐려진다.

→ 어텐션을 **여러 개(헤드) 병렬로** 돌린다. 헤드마다 자기만의 W_Q, W_K, W_V를 가져서 다른 종류의 관계를 잡는다. 역할 분담은 **학습으로 저절로** 생긴다.

```
입력 (768)
 ├─ 헤드 1 (64) ─┐
 ├─ 헤드 2 (64) ─┤
 ├─ ...          ├─ 이어 붙이기 (12 × 64 = 768) → W_O 곱하기 → 출력 (768)
 └─ 헤드 12 (64)─┘
```

- 768을 12개가 64씩 나눠 쓰므로 전체 계산량은 어텐션 한 번과 비슷하다.
- 입력과 출력 크기가 같아서 여러 층으로 쌓을 수 있다.

## 5. 위치 인코딩

어텐션은 모든 단어를 한 번에 보기 때문에 **순서를 모른다.** "Dog bites man"과 "Man bites dog"를 구분하지 못한다.

→ **최종 입력 = 토큰 임베딩 + 위치 인코딩** (둘 다 768 크기라 더할 수 있다)

- 1, 2, 3 같은 숫자를 그대로 넣으면 값이 커져서 단어 의미를 덮어버린다.
- 원 논문은 **여러 속도의 sin/cos 파동**을 쓴다. 시계의 초침·분침·시침처럼, 여러 파동을 같이 보면 위치가 하나로 정해진다. 값이 -1~1이라 의미를 덮지 않고, 상대 거리를 계산하기 쉽다.

| 방식 | 설명 | 쓰는 모델 |
|---|---|---|
| sin/cos (고정) | 공식으로 계산 | 원 논문 |
| 학습형 위치 임베딩 | 위치별 벡터를 학습 | BERT, GPT-2 |
| RoPE | Q, K를 위치만큼 회전 | LLaMA 등 요즘 LLM |

## 6. 트랜스포머 블록

```
입력 x
 ├──────────────┐
 ▼              │
멀티헤드 어텐션   │ 잔차 연결
 ▼              │
 + ◄────────────┘   출력 = x + 어텐션(x)
LayerNorm
 ├──────────────┐
 ▼              │
FFN             │ 잔차 연결
 ▼              │
 + ◄────────────┘   출력 = x + FFN(x)
LayerNorm
 ▼
출력 → 다음 블록
```

| 부품 | 하는 일 | 비유 |
|---|---|---|
| 멀티헤드 어텐션 | 단어 **사이**의 정보 교환 | 회의 |
| FFN | 단어 **각자** 정보 가공 (768 → 3072 → 768, 활성화 함수로 비선형성 추가). 파라미터의 약 2/3 | 각자 자리에서 정리 |
| 잔차 연결 | 원래 입력 x를 결과에 더함. 층은 "변화량"만 학습. 깊어져도 정보와 학습 신호가 잘 전달됨 | 원본에 수정 메모 붙이기 |
| LayerNorm | 벡터 값을 평균 0, 크기 1 근처로 맞춤 | 점수 표준화 |

- 원 논문은 더한 뒤 정규화(Post-LN), 요즘 LLM은 넣기 전에 정규화(Pre-LN).
- 블록을 **N개 쌓는다** = "N번 반복". 블록마다 **서로 다른 가중치**를 가진다.

| 모델 | 블록 수 |
|---|---|
| 원 논문 | 인코더 6 + 디코더 6 |
| BERT-base, GPT-2 small | 12 |
| LLaMA-7B | 32 |
| GPT-3 | 96 |

## 7. 인코더, 디코더, 마스킹

원 논문은 번역기였다. 원문을 읽고 이해하는 **인코더**, 번역문을 한 단어씩 쓰는 **디코더**로 이루어진다.

- **인코더**: 모든 단어가 앞뒤를 다 본다.
- **디코더**는 두 가지가 다르다.
  1. **마스크 셀프 어텐션**: 각 단어는 자기와 **앞 단어만** 본다. 미래(정답)를 훔쳐보지 못하게 하려는 것이다. 어텐션 점수의 미래 자리를 **-∞**로 바꾸면 softmax 후 0이 된다. 삼각형 모양이라 causal mask라고 한다.
  2. **크로스 어텐션**: Q는 디코더(쓰는 중인 문장)에서, K·V는 인코더(원문)에서 가져온다.

```
             볼 수 있는 단어 →
              나는  고양이를  좋아해
  나는     [  ✅      ❌       ❌  ]
  고양이를  [  ✅      ✅       ❌  ]
  좋아해    [  ✅      ✅       ✅  ]
```

| 종류 | 잘하는 일 | 대표 모델 |
|---|---|---|
| 인코더만 | 이해·분류 | BERT |
| **디코더만** | 생성 | **GPT, LLaMA, Claude** 등 대부분의 LLM |
| 인코더 + 디코더 | 변환 (번역, 요약) | T5, BART |

## 8. 학습과 생성

### 출력: 벡터 → 다음 토큰
마지막 위치의 벡터(768) → 출력 행렬(768 → 사전 크기) → 토큰별 점수(logit) → softmax → 확률 → 하나 고르기. 임베딩의 반대 방향이다.

### 생성: 자기회귀
한 번에 한 토큰만 예측한다. 뽑은 토큰을 입력에 붙여 다시 돌린다.
```
"나는"                → "고양이를"
"나는 고양이를"        → "좋아해"
"나는 고양이를 좋아해"  → "."  → ... <끝>
```
- **greedy**: 항상 1등. 안정적이지만 반복하기 쉽다.
- **sampling**: 확률대로 뽑는다.
- **temperature**: 낮추면 1등에 몰리고(정확·딱딱), 높이면 고르게 퍼진다(창의·엉뚱).

### "반복"의 세 가지 의미
| 반복 | 어디서 | 내용 |
|---|---|---|
| 층 N개 | 모델 안 | 블록 1 → 블록 2 → … |
| 생성 루프 | 모델 밖 | 토큰 뽑고 → 붙이고 → 다시 실행 |
| 학습 스텝 | 학습할 때 | 예측 → 오차 → 가중치 수정 |

### 학습: 다음 토큰 예측
1. 모든 가중치(임베딩, 모든 층의 W_Q/W_K/W_V/W_O, FFN, 출력 행렬)가 **랜덤**으로 시작한다.
2. 사람이 쓴 대량의 텍스트가 **문제이자 정답**이다. 따로 정답을 달 필요가 없다.
3. 마스크 덕분에 문장 하나로 **모든 위치를 동시에** 예측한다.
4. 정답 토큰에 준 확률이 낮을수록 오차가 크다(크로스 엔트로피).
5. 역전파로 오차를 출력층 → 블록 N → … → 임베딩까지 거꾸로 보내고 **모든 가중치를 동시에** 조금씩 고친다.
6. 수십만~수백만 번 반복한다 → 임베딩 의미, 어텐션 관계, 헤드 역할, 층별 역할이 **저절로** 생긴다.
7. 이후 파인튜닝(SFT), RLHF 등으로 대화형 비서로 다듬는다. 구조는 그대로이고 가중치만 바뀐다.

결과물은 **가중치 파일**(예: `model.safetensors`)이다. 모델을 다운로드한다는 건 이 파일을 받는 것이다.

## 9. 전체 흐름 한 장 정리

```
"나는 고양이를"
   ▼ ① 토큰화                              (2단계)
[312, 8821, 67]
   ▼ ② 임베딩 + 위치 인코딩                  (2, 5단계)
벡터들 (각 768)
   ▼ ③ 트랜스포머 블록 × N                   (3, 4, 6, 7단계)
   │    마스크 멀티헤드 어텐션 → 잔차+정규화 → FFN → 잔차+정규화
   ▼
문맥이 담긴 벡터들
   ▼ ④ 출력 행렬 + softmax                  (8단계)
다음 토큰 확률 → "좋아해"
   ▼ ⑤ 붙여서 다시 ①로                      (8단계)
```

## 10. 질문 & 답변

### Q1. (2단계) 임베딩 차원 768은 특별한 이유가 있나?
- 수학적으로 특별한 의미는 없다. 사람이 정하는 **하이퍼파라미터(d_model)** 다.
- BERT-base, GPT-2 small이 써서 유명해졌다.
- 크면 표현력이 좋아지지만 계산량과 메모리가 늘어나는 트레이드오프가 있다.
- 실용적인 이유: 헤드 수로 나누어 떨어져야 한다(12헤드 × 64 = 768). 64·128의 배수가 GPU 연산에 효율적이다.
- 다른 모델: BERT-large 1024, LLaMA-7B 4096, GPT-3 12288.

### Q2. (3단계) W_Q, W_K, W_V 같은 행렬은 미리 큰 모델이 학습해둔 건가? 사람이 만든 텍스트로?
- 다른 모델이 만들어 주는 게 아니다. 이 행렬들은 **트랜스포머 자기 자신의 파라미터**다.
- 처음엔 랜덤이다. 사람이 쓴 대량의 텍스트로 "다음 토큰 맞히기"를 반복하며 역전파로 고쳐진다 → **사전학습**.
- 임베딩 표, W_Q/W_K/W_V, 이후 층들까지 **모두 함께** 학습된다(end-to-end).
- 학습이 끝나면 값이 고정되고, 모델을 쓸 때(추론)는 계산만 한다.

### Q3. (3단계) Q·K 값을 어텐션이라고 부르나?
- 일부만 맞다. 단계마다 이름이 다르다.
  - Q·Kᵀ / √d_k → **어텐션 점수** (관련도 원점수)
  - softmax 후 → **어텐션 가중치** (합이 1인 비율). "어텐션 맵"은 보통 이것을 그린 것이다.
  - 가중치 × V까지 전부 → **어텐션** (연산 전체, 결과는 문맥이 반영된 벡터)

### Q4. (4단계) "어텐션을 N번 반복한다(for문)"는 게 헤드가 병렬로 처리하는 것, 즉 같은 어텐션이 반복하며 자리를 찾아가는 것인가?
- 아니다. 두 개념이 섞였다.
  - **헤드**: 같은 층 안에서 **옆으로 나란히(병렬)** 돈다. 서로 독립적이다.
  - **N번 반복**: **층(블록)을 위로 N개 쌓은 것**이다. 1층 출력이 2층 입력이 되는 **순차** 구조라 for문으로 쓴다.
- 층마다 **서로 다른 가중치**를 가진다. 수렴할 때까지 도는 게 아니라 정해진 수만큼 통과한다.
- "점점 자리를 찾아간다"는 감각은 층에 대해서는 맞다. 아래층은 문법·인접 관계, 위층은 의미·지시 관계를 잡는 경향이 있다.

```python
x = embed(tokens)
for layer in layers:   # ← "N번 반복" (층)
    x = layer(x)       #   안에서 헤드들은 동시에 계산
```

### Q5. (Q2 재질문) 층마다 각자 W_Q 등을 가진다면, 그 값들은 어디서 학습된 건가?
- 사전학습 **한 번에 모든 층이 동시에** 학습된다. 층별로 따로 학습하지 않는다.
- 학습 1스텝: 순전파(1층 → … → N층 → 예측) → 오차 계산 → 역전파(N층 → … → 1층) → **모든 층의 가중치를 동시에** 수정.
- 층마다 값이 다른 이유: 처음 랜덤 값이 다르고, 받는 입력과 위치가 달라 맡는 일이 달라진다.
- 누가: 모델을 만드는 회사·연구팀이 GPU 수천 장으로 몇 주~몇 달 학습한다. 결과물은 가중치 파일이다.

### Q6. (6단계) 잔차 연결은 residual을 더하는, 즉 원본 어텐션을 더해주는 부분인가?
- 큰 그림은 맞지만 **원본과 residual이 반대**다.
- `출력 = x + 어텐션(x)`
  - **x** = 블록에 들어온 **원래 입력**. 우회로로 와서 더해지는 원본이다.
  - **어텐션(x)** = 층이 계산한 **변화량 = residual(잔차)**.
- 잔차 = "출력 − 입력"의 차이. 층은 결과 전체가 아니라 **얼마나 바꿀지만** 학습한다.
- FFN 뒤도 `x + FFN(x)`로 똑같다. skip connection, shortcut이라고도 하고 ResNet(2015)에서 유명해졌다.
