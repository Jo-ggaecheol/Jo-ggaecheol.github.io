핵심 요지

  • COSMOS-3는 추론, 월드/비디오 생성, 액션 생성을 하나의 옴니모델로 묶은 MoT 기반 모델이다[1][2].
  • 앞부분 Reasoner는 언어·비전을 이해하고, 뒷부분 Generator는 디퓨전 트랜스포머로 비디오·오디오·액션을 만든다[3][4].
  • 액션은 카메라 기준 엔드이펙터 3D 포즈와 6D 회전으로 통일해 크로스 임바디먼트 학습을 겨냥한다[5][6].

요약

옴니모델의 기준과 COSMOS-3의 위치

COSMOS-3는 입력과 출력 모두 멀티모달을 다루는 옴니모델로 제시된다[7]. 여기서 ‘네이티브’는 사후 결합이 아니라 프리트레이닝 단계에서 여러 모달리티를 함께 학습했다는 뜻에 가깝다[8]. 공개된 규모는 Edge 4B, Nano 16B, Super 64B이다[9]. 입력은 이미지·텍스트·오디오·액션이고, 출력은 비디오·언어·오디오·액션이다[10].

LLM에 비해 보통 14B 수준으로 파라미터가 작고, 실시간 처리 요구와 연결 지을 수 있다[11]. 옴니모델의 기준은 계속 올라오고 있다[12]. 기존 옴니모달 연구와 비교하면 액션과 오디오 모달리티가 함께 들어간 점이 특히 눈에 띈다[13]. 오픈소스 공개도 다양한 응용 개발에 기여할 것으로 예상된다[14]. 즉 이해만 하는 VLM이나 언어 중심 LLM이 아니라, 액션 생성까지 포함한 옴니모델로 보면 된다.

Reasoner와 Generator를 나눈 MoT 구조

아키텍처는 Reasoner와 Generator로 나뉜다[15]. Reasoner는 비전 인코더와 언어 토크나이저를 거쳐 오토레그레시브 VLM처럼 동작한다[16]. Generator는 디퓨전 트랜스포머가 Reasoner 피처를 조건으로 받아 비디오·오디오·액션을 생성한다[17]. 기존 VLA와 유사하게 앞부분은 인과적 셀프 어텐션, 뒷부분은 풀 어텐션이 작동한다[18].

모든 토큰을 하나의 스트림에서 순차 생성하는 GPT-4식 구조와는 다르다[19]. 모달리티별로 WQ/WK/WV, MLP 같은 파라미터를 분리하고, 어텐션 단계에서 정보만 공유하는 MoT가 핵심이다[20]. 출력에서는 오토레그레시브와 디퓨전 모드가 병행될 수 있다[21]. 언어 모델을 고정해 두면서 KV 캐시를 공유하는 방식도 논의된다[22].

COSMOS-3가 완전히 스크래치 학습이 아니라 Llama 3(확인 필요)에서 출발했다는 설명도 함께 나온다[23]. Llama 3 VL을 각각 다르게 튜닝해 비전-언어 모델로 시작하는 것은 좋은 프리오리를 활용하는 것이라 나쁜 방법은 아니라는 설명도 있다[24].

월드·액션 모델로서의 기능과 통합 액션 스페이스

월드 액션 모델은 관측을 받아 다음 프레임과 액션을 함께 내는 기능을 의미한다[25]. 액션을 입력으로 미래 프레임을 예측하는 포워드 다이내믹스도 하나의 기능으로 볼 수 있다[26]. 비디오에서 해당 동작에 맞는 액션을 역추적하는 인버스 다이내믹스도 같은 모델로 정의할 수 있다[27].

디퓨전의 노이즈 처리 방식을 조절하면 여러 태스크를 하나의 모델로 묶을 수 있다는 설명이다[28]. 영상은 이 모델을 정책 그 자체보다 데이터셋 생성기로 보는 시각도 제시한다[29]. 옴니모달 특성상 원하는 입력으로 데이터셋을 만들거나 액션 폴리싱에 활용할 수 있다[30]. 자율주행차 이동 경로를 액션으로 정의하는 방식도 있다[31].

액션 표현은 SE(3)/SO(3) 계열, 특히 카메라 기준 엔드이펙터의 3D 포즈와 6D 회전으로 통일되는 추세다[32]. 크로스 임바디먼트 액션 스페이스는 거의 표준화되고 있다[33]. 이렇게 하면 특정 로봇 형태에 덜 의존하고, 인버스 키네마틱스로 각 모터 명령을 다시 계산할 수 있다[34]. 사람 손 영상에서도 핸드포즈와 6D 회전을 추정해 로봇 손과 코트레이닝하는 근거가 된다[35].

옴니모달의 계보: Chameleon, Transfusion, MoT

초기 옴니모달은 LLM의 next token prediction에 이미지를 VQ 계열로 토큰화해 넣는 Chameleon식 접근에서 출발했다[36]. 텍스트와 이미지를 같은 이산 토큰 공간으로 다루려는 시도였다[37]. 하지만 이미지는 연속적이라 디스크리트 토큰으로 만들면 미세한 변화가 다른 토큰으로 끊기거나 같은 토큰에 묶이는 문제가 있었다[38].

그래서 텍스트는 오토레그레시브, 이미지는 디퓨전/플로우 매칭으로 처리하는 Transfusion가 등장했다[39]. 이미지 토큰 구간에서는 노이즈를 입력해 풀 어텐션으로 패치를 생성하고, VQ-GAN 대신 연속 임베딩을 만드는 VA를 쓰는 방식이 이어졌다[40]. 모달리티마다 벡터 공간과 파라미터를 분리해야 한다는 문제의식이 MoT로 연결된다[41].

이해와 생성의 비대칭, 그리고 월드 모델 논쟁

Flow matching은 velocity prediction을 수행한다[42]. 이해와 생성에 인코더 웨이트를 다르게 쓰는 것이 성능적으로 유리하다는 관찰이 반복된다[43]. 인코더 통합 문제가 완전히 해결되지 않은 모델도 언급된다[44]. 즉 언더스탠딩과 제너레이션을 하나의 인코더로 통합하는 것은 목표일 수 있지만, 현재는 분리 방식이 더 효과적이라는 것이다[45].

텍스트는 이미 인간의 사고를 추상화한 매개체라 학습 효율이 높다는 분석이 나온다[46]. 빅테크 업계 추세는 텍스트 리즈닝으로 지능을 올리는 것이 가장 효율적이라는 분석도 있다[47]. 이미지는 픽셀 나열로 구조화가 되어 있지 않아 어떤 비전 신호를 선별해 학습할지가 난제다[48].

다음 비디오 프레임 예측만으로는 비주얼 인텔리전스가 쉽게 나오지 않는다는 지적도 있다[49]. 그래서 별도 인코더 없이 네이티브 JEPA식 월드 모델이 당장 성공하기는 어렵다는 부정적 전망까지 나온다[50]. 다만 LLM 초기 예측이 ChatGPT 이후 빠르게 뒤집힌 사례처럼 기술 변화 속도를 감안해야 한다는 언급도 있다[51].

활용 관점

아래는 영상 내용을 바탕으로 한 활용 관점 분석(추론)이며, 영상에서 직접 말한 내용이 아니다.

VLA 정책 구조와 액션 표현

  • Reasoner/Generator 분리와 모달리티별 파라미터 분리[52] → 언어·비전 이해는 기존 LLM/VLM을 고정하거나 공유하고, 액션 생성만 디퓨전/플로우 헤드로 붙이는 VLA를 설계해 볼 수 있다. 이때 KV 캐시를 공유하면서 LM 웨이트는 동결하는 학습 규칙을 정할 수 있다[53].
  • 카메라 기준 엔드이펙터 3D 포즈와 6D 회전 액션[54] → 로봇 암 데이터와 사람 손 영상 데이터를 같은 액션 공간으로 모아 코트레이닝할 수 있다. 실제 제어 전에는 인버스 키네마틱스로 관절 명령을 변환하는 파이프라인이 필요하다[55].

World model / world action model

  • 관측에서 다음 프레임과 액션을 함께 출력하는 구조[56] → 후보 액션을 넣으면 미래 프레임을 생성하고, 그 결과로 정책의 성공 여부나 보상을 추정하는 평가 루프를 만들 수 있다.
  • 디퓨전 노이즈 조절로 포워드/인버스 다이내믹스를 하나의 모델로 정의[57] → 로봇 데이터가 부족할 때 인간 영상에서 액션 라벨을 역추적해 학습 데이터를 보강하거나, 생성된 롤아웃으로 학습 후보를 선별해 볼 수 있다.
  • 현재 로봇별 주파수를 통일한 뒤 인터폴레이션/스무딩으로 처리하고, FPS를 시간 해상도로 확장하자는 논의[58][59] → 로봇마다 제어 주파수가 다르면 고정 Hz로 데이터를 자르는 대신, FPS를 연속 변수처럼 학습하고 추론 시 목표 주파수에 맞춰 보간/스무딩하는 파이프라인을 결정할 수 있다. 다양한 해상도와 시간 해상도를 지원하는 것이 디퓨전 모델이 오토레그레시브 모델보다 유리한 점이다[60].

로봇 핸드와 크로스 임바디먼트

  • 사람 손에서 3D 포즈/6D 회전 추정[61] → 에고센트릭 손 조작 영상을 수집해 핸드포즈를 추정하고, 로봇 핸드의 엔드이펙터 포즈로 리타게팅한 뒤 같은 액션 공간에서 학습할 수 있다.
  • 카메라 움직임인 에고 포즈 역추적[62] → 손 동작뿐 아니라 머리/카메라 이동도 조건이나 액션으로 넣어, 조작 데이터에 시점 이동을 함께 표현해 볼 수 있다.

더 볼 것

  • ‘월드 모델’이라는 이름값을 실제로 하는지, 다음 상태 예측의 정밀도가 얼마나 검증되었는지 확인이 필요하다[63].
  • 기존 언어 모델 기반 초기화[64]가 가져올 코너 케이스와 배포 제약은 실제 도입 전에 확인해야 한다.
  • 통합 액션 스페이스를 실기에 적용할 때 인버스 키네마틱스 역산[65]과 로봇별 주파수 통일[66]이 제어 품질에 어떤 영향을 주는지 살펴봐야 한다.
  • 다양한 FPS/시간 해상도 지원이 실제 학습 데이터와 추론 파이프라인에서 어떻게 구현되는지, 고정 제어 주기와의 정합성을 확인해야 한다[67].
  • 액션 모델의 인풋으로 V/VL을 받아 스칼라 가치를 내는 유니버설 리워드/밸류 모델이 실제로 모든 태스크를 평가할 수 있을지, 평가 기준과 데이터 편향을 점검해 볼 필요가 있다[68][69].
  • 텍스트 추상화의 우위와 JEPA식 월드 모델에 대한 부정적 전망이 경험적으로 얼마나 검증되었는지, 다음 프레임 예측 실험의 한계를 더 확인해야 한다[70][71].
