Agentic World Action Models

AW-0는 코드 기반 계획과 월드 액션 모델을 결합해 스킬 프로그램, 미래 영상, 로봇 동작을 mixture-of-transformers 구조에서 함께 디노이즈하는 에이전틱 프레임워크다. 자동화된 커레이션 파이프라인으로 로봇·인간 데모에 프로그램 주석을 붙여 재사용 스킬 라이브러리를 만들고, RoboTwin 2.0과 물리 양팔 조작에서 VLA/WAM 대비 성능을 높인다.

TL;DR

기존 world action model(WAM)은 시각적 예측을 제공하지만 재사용 스킬을 구성적으로 조합하는 명시적 메커니즘이 부족하고, 에이전틱 로봇 시스템은 재사용 스킬을 제공하지만 물리 동역학에 대한 예측적 근거가 부족하다. AW-0는 Mixture-of-Transformers(MoT) 아키텍처 안에서 코드, 영상, 액션을 동시에 디노이징하여 이 두 가지 접근을 하나의 생성 과정으로 통합한다. RoboTwin 2.0과 실세계 양팔 조작 태스크에서 VLA 및 WAM 베이스라인 대비 태스크 성능, 언어 추종, 의미론적 추론, 강건성에서 향상된 결과를 보인다.

문제 정의

학습 기반 로봇 조작은 과거 소규모 태스크 특화 시소모터 정책에서 인지, 언어, 액션을 연결하는 광범위하게 감독된 파운데이션 모델로 발전했다. WAM은 시각 예측을 시소모터 정책과 결합하여 제어의 물리적 근거를 제공한다. 그러나 예측된 영상과 액션 청크만으로는 장기 태스크 분해를 지정하지 못한다. 어떤 재사용 스킬을 호출할지, 어떻게 매개변수화할지, 서브태스크에 걸쳐 어떻게 구성할지를 명시하지 않는다. 또한 세계와/또는 액션 예측은 일반적으로 비용이 높을 수 있으며, 몇 개의 자유도를 세계 모델링해야 하는지에 대한 한계를 설정하기 어렵다.

반면 에이전틱 로봇 시스템은 재사용 스킬과 도구를 선택하는 프로그래매틱 하네스, 현재 장면과의 바인딩, 진행 추적, 관측이 변할 때의 재계획을 제공한다. 이 프로그래매틱 표현은 다단계 태스크의 구조를 명시적으로 만든다. 그러나 에이전틱 로봇 시스템은 실제 물리 동역학에 대한 예측적 근거가 자주 부족하며, 로봇이 액션을 수행하면서 세계가 어떻게 변하는지에 대한 학습된 모델을 활용하지 않는다.

핵심 아이디어

AW-0는 코드가 두 가지 보완적 역할을 수행한다는 관점에 기반한다. 첫째, 코드는 WAM 안에서 다단계 예측과 제어를 구조화한다. 둘째, 코드는 후속 에이전틱 실행을 위한 재사용 프로그램으로서 스킬을 표현한다. 이 두 역할을 하나의 생성 과정으로 통합하기 위해 AW-0는 MoT 아키텍처 안에서 코드 토큰 시퀀스 C0C_0C0​, 변분 오토인코더(VAE) 인코딩된 영상 잠재 변수 Z0Z_0Z0​, 액션 청크 A0A_0A0​를 조건부 생성 모델 pθ(C0,Z0,A0∣Ct)p_\theta(C_0, Z_0, A_0 \mid \mathcal{C}_t)pθ​(C0​,Z0​,A0​∣Ct​)로 동시에 디노이징한다. 여기서 Ct\mathcal{C}_tCt​는 현재 다중 뷰 관측, 언어 지시, 로봇 상태, 이전 프로그램 슬라이스의 압축 메모리로 구성된 조건부 컨텍스트이다.

방법론

통합 조건부 생성 모델

AW-0는 코드, 영상, 액션에 대한 통합 조건부 생성 모델로 정의된다. 스킬 프로그램은 이산 토큰 시퀀스 C0=(c1,…,cNc)C_0 = (c_1, \ldots, c_{N_c})C0​=(c1​,…,cNc​​)로 표현되고, 미래 관측은 사전 학습된 VAE로 인코딩된 연속 영상 잠재 변수 Z0Z_0Z0​이다. 로봇 운동은 지평선 HHH 스텝에 대한 액션 청크 A0=(at,…,at+H−1)A_0 = (a_t, \dots, a_{t+H-1})A0​=(at​,…,at+H−1​)이다. 모델은 조건부 컨텍스트 Ct={Ot,L,St,Mt}\mathcal{C}_t = \{\mathcal{O}_t, L, S_t, M_t\}Ct​={Ot​,L,St​,Mt​}를 받아 세 모달리티를 동시에 디노이징한다.

Mixture-of-Transformers 아키텍처

AW-0는 스킬 계획, 미래 시각 예측, 연속 제어라는 세 개의 전문가(expert)로 구성된 MoT 아키텍처를 채택한다. 각 전문가는 자체적인 어텐션 투영 (WQ,WK,WV,WO)(W_Q, W_K, W_V, W_O)(WQ​,WK​,WV​,WO​), 레이어 정규화, 피드포워드 네트워크(FFN)를 가지며, 모든 트랜스포머 레이어에서 마스크 합동 어텐션으로 통신한다. 어텐션 마스크 구조는 전문가 내부에서는 양방향(bidirectional), 전문가 간에는 코드 → 영상 → 액션 순서의 블록형 인과(blockwise causal)이다.

코드 전문가는 SDAR-1.7B 백본을 증강하며, 동결된 Qwen3-VL 비전 트랜스포머(ViT)를 사용하여 현재 다중 뷰 관측을 시각 토큰으로 인코딩하여 지시와 프로그램 토큰 앞에 배치한다. LLaDA 스타일 마스크 토큰 확산(masked-token diffusion)을 채택한다. 영상 전문가는 Cosmos-Predict2.5-2B에서 초기화된 영상 확산 트랜스포머(DiT)를 사용하며, 관측 프레임에 조건부되어 VAE 인코딩된 미래 프레임을 모델링한다. 액션 전문가는 처음부터(from scratch) 초기화된 별도 액션 DiT가 연속 액션 청크를 생성한다. 두 전문가 모두 언어 임베딩을 크로스 어텐션으로 받으며, 액션 전문가는 추가로 로봇 상태 조건부를 받는다. 모든 전문가는 28개 트랜스포머 레이어를 가지며, 쿼리·키·값은 공통 2,048차원 어텐션 공간으로 투영된다.

합동 디노이징 생성

각 디노이징 스텝에서 MoT는 코드 로짓과 연속 속도를 동시에 예측한다. 영상과 액션 생성은 연속 플로우 매칭(flow matching)을 사용하며, 노이즈 입력은 Xσmm=(1−σm)X0m+σmϵmX_{\sigma_m}^m = (1-\sigma_m)X_0^m + \sigma_m\epsilon_mXσm​m​=(1−σm​)X0m​+σm​ϵm​으로 구성된다. 여기서 σm=ϕγm(um)=γmum1+(γm−1)um\sigma_m = \phi_{\gamma_m}(u_m) = \frac{\gamma_m u_m}{1+(\gamma_m-1)u_m}σm​=ϕγm​​(um​)=1+(γm​−1)um​γm​um​​이고, 영상과 액션 모두 시프트 γm=5\gamma_m = 5γm​=5를 사용한다. 코드는 이산 흡수 마스크(absorbing-mask) 부식을 사용하며, 각 토큰은 베르누이 분포 Bernoulli(r)\text{Bernoulli}(r)Bernoulli(r)로 독립적으로 마스킹된다.

예측적 안내를 위해 고노이즈 사전 학습 분포에 균일 성분을 추가한다: uv∼q(u)=αppre(u)+(1−α)pref(u)u_v \sim q(u) = \alpha p_{\mathrm{pre}}(u) + (1-\alpha)p_{\mathrm{ref}}(u)uv​∼q(u)=αppre​(u)+(1−α)pref​(u), 여기서 α=0.5\alpha = 0.5α=0.5, pref=U(0,1)p_{\mathrm{ref}} = U(0,1)pref​=U(0,1)이다. 목적별 중요도 가중치가 영상 학습과 예측적 안내를 균형시킨다:

자동 어노테이션 파이프라인

훈련 데이터를 스킬 계획 코드로 어노테이트하는 세 단계 파이프라인을 제안한다. 첫째, 각 태스크에서 한 에피소드를 샘플링하고 Gemini 3.1 Pro가 사전 정의된 선언 전용 API에 대해 서브태스크 레벨 스킬 프로그램을 작성하며, Claude Code(Claude Opus 4.8)가 코디네이터로 작용하여 반복적이고 태스크 범용적인 스킬을 추출한다. 둘째, 스킬 라이브러리를 동결하고 확정된 어휘로 샘플링된 에피소드를 재어노테이트하여 재사용 가능한 서브태스크-프로그램 매핑 캐시를 형성한다. 셋째, 나머지 코퍼스를 어노테이트할 때 서브태스크의 접촉과 운동 패턴이 기존 항목과 일치하면 캐시된 프로그램을 재사용하고, 그렇지 않으면 코딩 에이전트가 새로운 어노테이션을 생성하여 캐시에 추가한다.

메모리 캐시와 하이브리드 액션

단일 관측만으로는 태스크 진행을 드러내기 자주 부족하므로, 코드 전문가는 지금까지 생성된 슬라이스의 압축 캐시를 받는다. 히스토리 슬라이스는 KKK개의 학습 가능 메모리 슬롯으로 압축되어 코드 스트림에서 프롬프트 앞에 접두 토큰으로 읽혀진다.

추론 시에는 하이브리드 액션 모드를 탐색한다. 디코딩된 코드 슬라이스가 Code-as-Policies(CaP) 방식대로 지각과 제어 원시 연산 라이브러리에 대해 실행되고, 실행된 액션이 액션 전문가의 직접 액션과 통합된다. 배포 시 두 채널은 각 재계획점에서 조정되며, 디코딩된 슬라이스는 유효성과 진행 검사를 통과할 때만 현재 단계를 인수한다. 그렇지 않으면 같은 포워드 패스의 액션 청크가 다음 재계획까지 로봇을 구동한다.

Figure 해설

그림 1: AW-0 개요. AW-0은 스킬 프로그램, 미래 영상, 제어 궤적을 함께 디노이징함으로써 코드 기반 계획과 월드 액션 모델링을 통합한 에이전틱 월드 액션 모델이다. 에이전틱 파이프라인은 재사용 가능한 스킬을 발견하고, 사전학습과 다운스트림 미세조정에 모두 사용할 수 있도록 로봇 및 인간 데모스트레이션을 프로그램으로 주석한다. 이를 통해 얻은 정책은 평행 그립퍼와 다기능 손 태스크 모두에서 뛰어난 성능을 달성한다. (출처: 원 논문)

AW-0의 전체 개요를 보여준다. 에이전틱 파이프라인이 재사용 스킬을 발견하고 로봇 및 인간 데모네이션에 프로그램을 어노테이트하여 사전 학습과 다운스트림 미세 조정 모두에 사용한다. 결과 정책은 병렬 그립퍼와 민첩 손 태스크 모두에서 강력한 성능을 달성한다.

그림 2: AW-0 프레임워크. AW-0은 코드, 영상, 액션을 각각 생성하는 세 개의 전문가를 가진 Mixture-of-Transformers 백본을 포함하며, 이들은 함께 디노이징된다. 여기서 영상과 액션은 연속 flow matching으로, 코드는 이산 masked diffusion으로 처리된다. (출처: 원 논문)

AW-0 프레임워크를 보여준다. 코드, 영상, 액션을 각각 생성하는 세 전문가로 구성된 MoT 백본이 합동 디노이징을 수행하며, 영상과 액션은 연속 플로우 매칭, 코드는 이산 마스크 확산으로 디노이징된다.

그림 3: 자동 주석 파이프라인. 코딩 에이전트는 사전 정의된 원시 API와 사용 가능한 스킬을 사용하여 서브태스크 수준의 프로그램을 생성하고, 조정자는 반복적으로 나타나는 패턴을 태스크 전반에 걸쳐 재사용 가능한 스킬 라이브러리로 정제한다. 라이브러리가 고정된 상태에서, 접촉 및 운동 증거가 일치하면 캐시된 코드를 재사용하고 그렇지 않으면 새로운 라벨을 생성하여 코퍼스를 주석한다. (출처: 원 논문)

실험 결과

AW-0는 RoboTwin 2.0 벤치마크와 실세계 양팔 조작 태스크에서 평가된다. 사전 학습 코퍼스는 YAM(73,101 에피소드, 279 태스크, 1,919.3시간)과 에고센트릭 인간 데이터(175,541 에피소드, 327 태스크, 993.9시간)의 합집합으로, 총 248,642 에피소드, 2,913.2시간을 구성한다. YAM 스킬 라이브러리는 23개 스킬, 에고센트릭 인간 스킬 라이브러리는 27개 스킬로 동결된다.

RoboTwin 2.0과 실세계 태스크에서 AW-0는 표준 VLA 및 WAM 베이스라인 대비 태스크 성능, 언어 추종, 의미론적 추론, 강건성에서 향상된 결과를 보인다.

한계

저자는 다음 한계를 명시한다.

첫째, 프로그램 근거와 스킬 커버리지: 코드 스트림은 자동 어노테이션된 데모네이션과 큐레이션된 스킬 라이브러리로 학습하므로, 계획 품질은 어노테이션 정확도와 스킬 커버리지에 의존한다. 생성된 프로그램은 적절한 스킬을 선택하더라도 잘못된 인자를 포함할 수 있으며, 문법적 유효성만으로는 올바른 실행이 보장되지 않는다.

둘째, 예측적 강건성과 하이브리드 실행: 구조화된 계획은 WAM 성능을 개선하지만 시각 분포 이동에 대한 민감도를 제거하지는 않는다. 하이브리드 실행은 RoboTwin 랜덤화 하에서 강건성을 개선하지만 클린 설정에서의 성능은 감소한다. 이는 기본 원시 연산의 신뢰성과, 액션 청크에 대한 우위를 추정하지 않고 유효성만으로 코드를 선택하는 한계를 반영한다.

셋째, 지속적 에이전틱 학습으로: 실세계 하이브리드 평가는 민첩 손용 코드-정책 시스템이 없어서 YAM 플랫폼으로 제한된다. 현재 시스템은 자신의 상호작용으로부터 온라인으로 학습하지 않는다.

비판적 검토

강점

  • WAM에 코드 전문가(code expert)를 통합한 formulation이 명확하다 — 세계 행동 모델(WAM)의 video-action 예측에 코드 기반 계획(code-based planning)을 하나의 mixture-of-transformers(MoT) 생성 과정으로 결합하고, 조건부 생성과 joint denoising을 수식으로 정의해 기여가 구체적이다 (근거: 3.1절 Eq.1-2, 3.2절, Appendix A.1).
  • 스킬 라이브러리와 annotation pipeline이 절차적으로 상세하다 — declaration-only API, annotator/coordinator prompt, frozen skill library, cached reuse, 스킬 예시를 함께 제시해 재사용 가능한 스킬 추출 절차를 보여준다 (근거: 3.4절, Appendix K.1-K.2, Table 8-9, Figure 9-18).
  • 프리트레이닝 데이터 규모와 스킬 구조가 수치로 보고된다 — YAM과 egocentric human의 episode·시간·스킬 수를 정리하고, 임베딩 공간에서 스킬별 분포를 시각화해 skill label이 motion을 구분할 수 있다는 정성적 근거를 제공한다 (근거: B.1절 Table 7, B.5절 Figure 18-19).
  • 하이브리드 실행(hybrid execution)의 tradeoff를 투명하게 제시한다 — code execution과 direct action의 step share를 clean/random 성공·실패별로 보고하고, clean 성능 감소와 validity-only arbitration 한계를 인정해 결론을 과도하게 일반화하지 않도록 한다 (근거: Table 12, L.2절).

약점·의문

  • 핵심 성능 향상 주장에 대한 정량 근거가 제공된 발췌에서 확인되지 않는다 — Abstract와 Introduction은 VLA/WAM 대비 task performance, language following, semantic reasoning, robustness 향상을 주장하지만, Table 1 본문, baseline 구현 세부, 반복 실행·분산·통계적 유의성 수치가 제시되지 않았다 (근거: Abstract, 2.5절, Appendix C는 목차만 존재, Table 1은 참조만).
  • code expert가 action prediction을 실제로 개선하는지 분리된 ablation이 보이지 않는다 — code stream이 video/action denoising에 planning context를 공급한다고 기술되지만, code expert 제거, skill library 크기 변화, hybrid arbitration 제거 등 구성 요소별 성능 비교가 제공된 발췌에 없어 인과 효과가 불분명하다 (근거: 3.3절, 제공된 발췌에 ablation 근거 없음; Appendix F/G/H는 목차만).
  • annotation 정확도와 스킬 커버리지의 영향이 정량화되지 않았다 — Gemini/Claude 기반 annotator와 static validation으로 프로그램을 생성하지만, annotation error rate, skill coverage 부족 사례, downstream 실패와의 관계가 수치로 보고되지 않아 planning quality에 대한 신뢰도가 제한적이다 (근거: 3.4절, Appendix K.2, L.1절).
  • 일반화 범위가 평가된 embodiment/task보다 넓게 읽힐 수 있다 — pretraining은 YAM과 egocentric human 두 소스이고, real-world hybrid evaluation은 dexterous hand용 code-as-policy 부재로 YAM platform으로 제한되는데, Introduction의 distinct environments/tasks에 걸친 compositionality 주장은 제공된 결과만으로 충분히 뒷받침되지 않는다 (근거: B.1절, A.8절, L.3절, 2.5절) (해석).
  • hybrid execution의 이점이 조건부이고 code channel 비중이 작다 — Clean/All과 Random/All에서 code exec는 각각 8.5%, 5.6%에 불과하고, clean 설정에서는 hybrid가 성능을 감소시킨다고 인정되어, robustness 개선이라는 결론은 randomization 성공 episode에 국한된 것으로 해석될 수 있다 (근거: Table 12, L.2절) (해석).

재현 가능성

  • 제공된 발췌에는 코드·데이터·체크포인트 공개 여부가 명시되지 않았고, baseline 구현(Appendix C), 실세계 설정(D/E), hybrid 알고리즘(I), annotation 세부(K) 본문이 빠져 있어 재현에 필요한 핵심 정보가 부족하다. LLM annotator와 skill library 생성 과정의 결정론적 재현 조건은 불분명하다 (근거: 제공된 발췌에 공개 여부 없음; Appendix CONTENTS, K.2) (해석).
