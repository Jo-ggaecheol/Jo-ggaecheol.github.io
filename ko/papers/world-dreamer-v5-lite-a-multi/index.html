World Dreamer v5-lite: A Multi-Robot World Action Model with One Dreamer

World Dreamer v5-lite는 보정된 다중 로봇 카메라 특징을 워크스페이스 좌표의 공유 월드 상태로 만들고, VLM 기반 에이전트 쿼리로 로봇 간 정보를 교환한 뒤 각 로봇의 독립적 액션을 예측하는 멀티로봇 월드-액션 모델이다. 일부 카메라 뷰를 숨기는 협력 학습으로 타 로봇 관측에 의존하도록 유도한다.

TL;DR

다중 로봇 조작에서 각 로봇의 카메라 관측을 작업 공간 좌표의 공유 세계 상태 ϕ\phiϕ로 통합하고, 로봇별 액션 스트림은 분리한 채 포즈 인식 쿼리로만 정보를 교환한다.
VLM은 장면 문맥과 로봇별 쿼리를 제공하고, 비디오 인코더 특징은 캘리브레이션 기하로 ϕ\phiϕ에 적재되며, masked-view cooperative training으로 자기 카메라가 가려져도 팀 관측을 쓰도록 학습한다.
RoboFactory 평균 성공률 74.0%, 실로봇 4개 과제 평균 78.8%로 가장 강한 평가 베이스라인보다 각각 23.7%p, 13.8%p 높고, RoboCasa365 전체 58.08%를 기록했다.

문제 정의

기존 vision-language-action(VLA) 모델과 world-action 모델은 대부분 단일 로봇을 대상으로 한다. 다중 로봇 조작에서는 관측이 분산되어 있고, 각 로봇의 카메라는 이동하며 작업 공간의 일부만 본다. 따라서 서로 다른 카메라의 이미지 패치는 같은 물리적 위치를 가리키지 않는다.

또한 제어는 분리되어 있지만 결정은 결합된다. 로봇마다 embodiment와 액션 공간이 다를 수 있으나, 한 로봇의 행동은 다른 로봇의 위치와 동작에 의존한다. 관측도 불완전할 수 있다. 한 로봇의 카메라가 다른 로봇이나 조작 대상물에 가려지면, 그 로봇은 팀원 카메라에서 본 정보를 써야 한다.

단순히 카메라 토큰을 연결하면 작업 공간 좌표에서의 대응 관계를 만들지 못한다. 각 로봇마다 독립 정책을 쓰면 팀 관측을 활용할 수 없다. 기존 다중 에이전트 정책이 정보 공유 능력을 가져도, 자기 카메라가 충분할 때 다른 뷰를 쓸 유인이 약해진다. 이 논문은 이러한 문제를 풀기 위해 공통 작업 공간 좌표의 공유 세계 상태 ϕ\phiϕ와 masked-view cooperative training을 제안한다.

핵심 아이디어

World Dreamer v5-lite는 여러 로봇의 캘리브레이션된 비디오 특징을 작업 공간 좌표의 고정 크기 상태 ϕ\phiϕ로 모은다. VLM은 지시어와 현재 이미지를 처리하고, 각 로봇 슬롯에 하나씩 learnable agent query를 둔다. 이 쿼리들은 같은 장면 문맥을 공유하면서 ϕ\phiϕ를 읽고, 상대 포즈 정보를 이용해 서로 교환한다. 액션 스트림 자체는 로봇별로 분리되어 있어 이질적인 embodiment와 액션 공간을 유지한다. 학습 시 일부 카메라 뷰를 VLM과 비디오 경로 양쪽에서 동시에 가리지만, 모든 로봇의 액션 목표는 그대로 두어 팀 관측에 의존하는 협동을 유도한다.

방법론

VLM 장면 조건부

지시어와 사용 가능한 뷰의 현재 이미지는 VLM의 공유 prefix가 된다. 고정된 레이아웃이 NNN개 로봇 슬롯을 준비하고, agent mask magent∈{0,1}N\mathbf{m}^{\mathrm{agent}}\in\{0,1\}^Nmagent∈{0,1}N이 해당 결정 단계에 존재하는 로봇을 선택한다. 각 슬롯 뒤에 learnable agent query가 온다. 슬롯 iii의 query 입력 임베딩은

ri=qshared+ei\mathbf{r}_i = \mathbf{q}_{\mathrm{shared}} + \mathbf{e}_iri​=qshared​+ei​

이다. 여기서 qshared\mathbf{q}_{\mathrm{shared}}qshared​는 모든 로봇이 공유하는 learnable embedding이고, ei\mathbf{e}_iei​는 슬롯 iii의 learnable embedding이다. 모든 query가 같은 prefix를 따라서 VLM을 한 번만 돌려도 모든 로봇 query가 같은 장면 조건부를 받는다.

VLM은 Action Decoder에 두 가지를 제공한다. 첫째, robot query 위치의 contextualized hidden state를 투영하고 정규화하여 초기 decoder query qi0∈Rd\mathbf{q}_i^0\in\mathbb{R}^dqi0​∈Rd를 만든다. 논문에서는 d=1024d=1024d=1024로 decoder width를 잡는다. 둘째, prefix 토큰의 layer-wise keys and values를 shared scene-prefix KV cache로 만들어 모든 로봇에 지시어와 이미지 문맥을 공급한다. 사용하지 않는 슬롯 출력은 zero-padding된다.

비디오 인코더와 보조 미래 예측

VLM이 현재 이미지에서 의미론적 문맥을 제공하는 동안, 비디오 인코더는 ϕ\phiϕ를 만드는 공간 증거를 제공한다. 최근 RGB history는 VVV개 카메라 슬롯에 배치된다. 이 카메라 슬롯은 로봇 슬롯 NNN과 별개다. 한 로봇이 여러 뷰를 제공할 수도 있고, 작업 공간 카메라가 추가로 제공될 수도 있다. view mask mview∈{0,1}V\mathbf{m}^{\mathrm{view}}\in\{0,1\}^Vmview∈{0,1}V가 사용 가능한 카메라를 선택하며, 같은 mask가 현재 이미지 중 VLM에 들어가는 뷰도 결정한다.

causal video variational autoencoder(VAE)가 각 RGB history를 latent로 변환하고, pretrained video model의 encoder가 To=3T_o=3To​=3개의 observed latent steps를 처리한다. 학습 시 Tf=2T_f=2Tf​=2개의 noised future steps가 추가로 주어지며, 보조 video-flow prediction task에 쓰인다. prefix-asymmetric attention mask는 observed tokens가 future steps를 attend하지 못하게 한다. 따라서 observed 출력과 ϕ\phiϕ는 관측에만 의존하며, 추론 시 비디오 생성이 필요 없다.

액션 디코더

Action Decoder는 embodiment가 다를 수 있는 로봇들의 제어를 생성하면서, 로봇 간 상호작용도 고려해야 한다. 모든 로봇의 액션 토큰을 하나의 시퀀스로 연결하면 이질적인 액션 공간이 얽히고, 로봇이 추가될 때마다 시퀀스가 길어진다. 반대로 각 로봇을 독립적으로 decode하면 다른 로봇을 무시한다. 그래서 논문은 로봇별 action stream을 분리하고, 로봇 간 통신은 query qi\mathbf{q}_iqi​만 교환하도록 한다.

첫째, Field Injection Block은 각 query qi\mathbf{q}_iqi​가 cross-attention으로 ϕ\phiϕ를 읽게 한다. 모든 로봇이 같은 상태를 읽지만, attention은 로봇 iii에 할당된 카메라 위치 쪽으로 bias되어 각 로봇이 자기 관점부터 ϕ\phiϕ를 읽도록 한다. 다만 먼 영역을 완전히 배제하지는 않는다.

둘째, Scene Decoder Block은 로봇 iii의 action stream을 scene-prefix cache에 조건부화한다. 각 토큰은 대응하는 VLM layer의 cache와, 자기 stream의 이전 토큰에만 causally attend한다. 그래서 action token은 language-image 문맥, 자기 로봇의 proprioception, field-updated query, 이전 action token을 쓸 수 있으면서도 다른 로봇의 action stream과는 분리된다.

Pij\mathbf{P}_{ij}Pij​는 상대 pose이므로 world frame 선택에 의존하지 않는다. 연결 패턴을 고정하지 않고, 상대 포즈가 로봇 간 교환을 조건부화한다. query만 교환되므로 다른 로봇의 정보는 다음 layer에서 action token에 도달하며, 각 stream은 자기 proprioception과 embodiment-specific action token을 유지한다.

출력 head는 최종 action tokens를 flow velocity u^i∈RH×Da\hat{\mathbf{u}}_i\in\mathbb{R}^{H\times D_a}u^i​∈RH×Da​로 변환한다. 추론 시 qi0\mathbf{q}_i^0qi0​, ϕ\phiϕ, scene-prefix cache는 결정 단계마다 한 번 계산되고, 다섯 개의 Euler steps로 decoder를 재평가하여 noise에서 액션 chunk까지 velocity를 적분한다.

masked-view cooperative training

위 구조는 로봇 간 정보 공유를 가능하게 하지만, 그 정보가 실제로 쓰이도록 보장하지는 않는다. 모든 로봇이 항상 자기 카메라를 보면, decoder는 주로 자기 뷰에 의존하고 ϕ\phiϕ와 다른 로봇을 무시할 수 있다. 그래서 학습 중 view mask mview\mathbf{m}^{\mathrm{view}}mview로 무작위로 선택된 한 로봇의 모든 카메라 또는 일부 뷰를 가린다. 같은 카메라가 VLM scene prefix와 ϕ\phiϕ 구성 경로 양쪽에서 동시에 제거된다. camera calibration은 공간 기준과 상대 pose descriptor Pij\mathbf{P}_{ij}Pij​를 정의하는 데 계속 사용된다.

view masking은 관측에만 적용되므로, 기록된 액션 chunk는 카메라가 가려진 로봇을 포함해 모든 로봇의 valid target으로 남는다. 남은 뷰는 ϕ\phiϕ와 scene-prefix cache를 통해 기여할 수 있고, query interaction도 문맥 공유 경로를 제공한다.

학습 목표에서 각 로봇은 masked context 아래에서도 시연된 액션 chunk를 target으로 유지한다. flow time은 ρ∼Beta(1.5,1)\rho\sim\mathrm{Beta}(1.5,1)ρ∼Beta(1.5,1)로 샘플링하고, τ=0.999(1−ρ)\tau=0.999(1-\rho)τ=0.999(1−ρ)를 사용한다. 이렇게 하면 noisy 시작점 근처에 더 많은 샘플이 놓인다. action loss Lact\mathcal{L}_{\mathrm{act}}Lact​는 weighted squared velocity error이며, 각 로봇의 supervised entries 평균을 먼저 계산한 뒤 존재하는 로봇 전체로 평균한다.

비판적 검토

강점

  • 공유 월드 상태가 멀티뷰 대응 문제를 구조적으로 다룸 — 카메라 토큰을 단순히 연결하지 않고, 보정된 영상 특징을 워크스페이스 좌표의 고정 크기 상태 ϕ\phiϕ로 통합해 로봇 수와 무관하게 모든 로봇이 같은 공간 참조를 읽는 설계가 명확하다 (근거: 3.3절, Fig. 2).
  • 멀티로봇 벤치마크에서 보고된 성능 이점이 크다 — RoboFactory 평균 성공률 74.0%74.0\%74.0%로 가장 강한 비교 대상(baseline) π0.5\pi_{0.5}π0.5​의 50.3%50.3\%50.3%보다 23.723.723.7%p 높고, 실로봇 4개 과제 평균도 78.8%78.8\%78.8%로 π0.5\pi_{0.5}π0.5​의 65.0%65.0\%65.0%를 상회한다 (근거: Table 1, Table 2).
  • 추론 시 미래 영상 생성을 피하는 설계가 실용적이다 — 미래 영상 잠재 표현(latent)은 학습 보조 목적만 사용하고, 추론에서는 관측된 특징과 비전–언어 모델(VLM)의 장면 접두사(key/value, KV) 캐시만으로 액션을 예측하므로 test-time video generation 부담을 줄인다 (근거: 3.2절, 3.4절).

약점·의문

  • 기여와 효과 인과를 분리하는 실험이 부족함 — ϕ\phiϕ의 plane layout은 PDFactor/EG3D와 유사하고, 멀티에이전트 협력은 GauDP/CLS-DP가 이미 다룬다. 그럼에도 ϕ\phiϕ, 마스크드 뷰(masked-view) 훈련, 포즈 인식(pose-aware) 쿼리 교환 중 어떤 것이 성능을 만드는지 부분 제거 실험(ablation)이 없어, “공유 월드 상태와 협력 학습”이라는 기여 주장이 직접 검증되지 않는다 (근거: 2절, 3.3–3.5절; 본문에 ablation 표/절 없음).
  • masked-view training의 목표 효과가 테스트 타임에서 검증되지 않음 — 일부 카메라를 숨겨 타 로봇 관측을 쓰게 하려는 설계인데, 평가 시 카메라가 누락된 조건에서의 성공률이나 가림(occlusion) 강건성 결과가 없다. 따라서 “불완전 관측에서 협력”이라는 결론은 직접적으로 뒷받침되지 않는다 (근거: 3.5절; 실험 절에 해당 평가 없음).
  • 통계적 불확실성이 보고되지 않음 — Table 1, Table 2, Fig. 4는 평균 성공률만 제시하고 반복 실행, 표준편차/신뢰구간, 유의성 검정이 없다. 100100100 trials/envs 규모에서 몇 %p 차이는 해석에 주의가 필요하다 (근거: 4.1절, Table 1, Table 2, Fig. 4).
  • RoboCasa365 비교는 멀티로봇 주장과 직접 연결이 약함 — RoboCasa365는 단일 로봇 household manipulation이고, baseline 결과는 공식 리더보드(leaderboard)에서 가져왔다. 따라서 이 벤치마크의 우위가 멀티로봇 협력 능력보다는 일반 조작/학습 스케일링에 더 가까운 증거일 수 있다 (근거: 4.1절, 4.2절, Fig. 4; 해석).
  • 실세계 일반화 범위가 좁다 — 실로봇 평가는 LeKiwi와 OpenArm 팀의 4개 과제뿐이고, RoboFactory도 2~4 에이전트 과제로 제한된다. 더 많은 로봇 수, 이질적 로봇 형상(embodiment), 다른 작업 환경으로의 일반화는 현재 실험만으로는 확신하기 어렵다 (근거: 4.1절, Table 1, Table 2).
  • baseline 비교에서 협력 능력과 모델/데이터 차이가 분리되지 않음 — 단일 로봇 policy를 멀티로봇에 공유하는 방식은 크로스 에이전트(cross-agent) 정보 경로가 제한될 가능성이 크고, 같은 아키텍처에서 협력 경로만 제거한 variant가 없어 성능 차이를 협력 메커니즘만으로 해석하기 어렵다 (근거: 4.2절; 해석).

재현 가능성

  • 제공된 본문에는 모델 코드/데이터 공개 링크가 없고, 10,00010{,}00010,000시간 프리트레이닝 코퍼스의 시뮬레이션/실로봇 비율, 옵티마이저·학습률·배치크기·에폭, masked-view 확률, 실로봇 데이터 규모, GPU 시간과 평가 seed가 명시되지 않아 재현에는 부족하다 (근거: 4.1절, 4.3절; 본문에 코드 링크 없음).
