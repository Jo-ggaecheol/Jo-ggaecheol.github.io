01RL 문제 설정: 상호작용 루프

매 시점 t마다 에이전트와 환경이 상태, 행동, 보상을 주고받는다.

목표는 누적 보상(return)의 기댓값을 최대화하는 정책을 찾는 것이다.

maxπ Eπ[ Gt ],    Gt = Rt+1 + γRt+2 + γ²Rt+3 + ⋯
환경의 동역학 p는 모른다고 가정한다. p를 알고 시작하는 고전 제어 이론과 갈라지는 지점이 바로 여기다.

02지도학습과 뭐가 다른가: 세 가지 축

축지도학습RL
① 피드백 종류instructive: 정답 라벨 y를 준다evaluative: 고른 행동의 점수만 준다. 다른 행동을 했으면 어땠을지는 모른다
② 데이터 분포i.i.d., 고정정책이 데이터 분포를 바꾼다. 어디를 가보느냐가 무엇을 배우느냐를 결정한다
③ 시간 구조샘플끼리 독립보상이 늦게 온다. 100스텝 전 행동이 원인일 수 있다 → credit assignment

03🤖 로봇에서 보면

  • Observation vs state: 카메라·센서로 보는 것은 상태의 일부라서 엄밀히는 POMDP다 (02에서 다룸).
  • Step = 제어 주기: 50Hz면 10초 에피소드가 500스텝이라 ③ credit assignment가 심각해진다.
  • Sparse reward vs shaping: sparse는 학습 신호가 거의 없고, shaping을 하면 reward hacking이 생긴다(물체 근처에서 떨기만 해도 distance 보상을 받음).
  • 탐험 비용: 시뮬레이션은 공짜지만 실제 로봇은 부서진다 → sim-to-real.
  • ②의 귀결: 정책이 바뀌면 방문하는 상태 분포가 바뀐다. imitation learning의 compounding error도 이것 때문이다 (10).

04Multi-armed Bandit이란

카지노 슬롯머신의 별명이 "one-armed bandit"(외팔이 강도)이다. 레버가 팔 하나고, 돈을 뺏어가서 강도다. 그 기계가 여러 대면 multi-armed bandit이다.

  • 기계 k대. 기계 a를 당기면 보상 R ~ νa. 진짜 평균 q*(a) = E[R | A=a]는 모른다.
  • 매 라운드 하나를 골라 당기고, T번 동안 누적 보상을 최대화한다.
  • 고른 기계의 결과만 보인다. 그래서 좋아 보이는 걸 계속 쓸지(exploitation), 덜 해본 걸 알아볼지(exploration)의 딜레마가 생긴다.

현실의 예: A/B 테스트, 임상시험 배정, 광고/추천 선택, 🤖 grasp 후보 선택, 제어기 하이퍼파라미터 선택.

05가치 추정과 증분 업데이트

무엇성질
진짜 목표q*(a): 기계의 진짜 평균알 수 없고 직접 관측할 수도 없다
target이번에 관측한 보상 Rnq*의 noisy 샘플. 매번 흔들리는 과녁이고, 기댓값이 q*다

표본평균을 매번 다시 계산하지 않고 정리하면 다음 식이 나온다.

Qn+1 = (R1 + ⋯ + Rn) / n = Qn + (1/n) · ( Rn − Qn ) 새 추정 = 옛 추정 + 보폭 × (target − 옛 추정)

ML 관점

L(Q) = ½(R − Q)²에 SGD 한 스텝을 하면 Q ← Q + α(R − Q)다. 즉 target을 라벨로 놓은 MSE regression을 SGD로 하는 것과 같다. 기대 업데이트가 0이 되는 점이 Q = E[R] = q*다.

고정 보폭과 수렴 조건

Qn+1 = (1−α)n Q1 + Σi α(1−α)n−i Ri오래된 보상일수록 가중치가 지수적으로 감소 (exponential recency-weighted average)
  • Robbins–Monro 조건: Σαn = ∞ (초기값에서 어디로든 갈 만큼 충분히 움직임), Σαn² < ∞ (보폭이 줄어 노이즈가 사라짐).
  • 1/n은 둘 다 만족한다. 고정 α는 두 번째를 어겨서 완전히 수렴하지 않지만, 그 덕분에 변화를 따라간다. 🤖 마모로 동역학이 변하는 로봇.

06성능 척도: Regret

Regret(T) = Tμ* − E[ Σt Rt ] = Σa Δa · E[NT(a)] μ* = 최적 기계의 평균 · gap Δa = μ* − q*(a) (한 번 잘못 고를 때 손해) · NT(a) = 기계 a를 고른 횟수

"처음부터 최적 기계를 알았다면 받았을 기대 보상"에서 "실제로 받은 기대 보상"을 뺀 값, 말 그대로 후회다. ΣN(a) = T를 쓰면 Tμ* − ΣN(a)q*(a) = ΣN(a)(μ* − q*(a))가 된다.

왜 gap을 곱하나: 실수마다 손해 크기가 다르다

regret은 성적표다

  • 정답 μ*를 알아야 계산된다. 그래서 에이전트 자신은 실행 중이든 끝난 뒤든 계산할 수 없다. 학습 신호가 아니다. ML의 test loss 위치다.
  • 쓰임: ① 실행 전 이론적 보장(예: UCB는 regret ≤ C·log T) ② 실행 중/후 정답을 아는 실험자가 시뮬레이션에서 곡선으로 평가 ③ 실제 배포에선 계산 불가 → 누적 보상 같은 대리 지표.
  • 보상 곡선은 "지금 얼마나 잘하나", 누적 regret은 "잘하게 될 때까지 얼마나 손해 봤나(학습 비용)". 최종 성능이 같아도 늦게 도달하면 regret이 크다.
  • Lai–Robbins 하한: 어떤 합리적인 알고리즘도 Ω(log T)보다 작을 수 없다. → O(log T)면 차수로 최적.
🤖 로보틱스 연결 · 시뮬레이션 학습에서는 최종 성능이 주로 중요하다. 실로봇처럼 학습 중 실수가 실제 비용(파손, 시간)이면 regret 관점이 중요해진다. 딥RL의 sample efficiency도 같은 생각이다.

07단순한 전략: Greedy, ε-greedy, Optimistic init

전략방법문제
Greedy항상 argmax Q초반에 최적 팔이 운 나쁘게 낮게 나오면 다시 안 고름 → 선형 regret
ε-greedy확률 ε로 무작위, 나머지는 greedy최적 팔을 알아낸 뒤에도 ε/k 비율로 나쁜 팔을 계속 고름 → 선형 regret (ε 감소 스케줄이면 로그 가능하지만 gap에 맞춘 튜닝 필요)
Optimistic initQ0를 크게모든 팔이 초반에 한 번씩 시도되지만 탐험이 초반에만 일어남
ε-greedy의 근본 한계: "모르는 것"과 "나쁜 것"을 구분하지 않고 똑같이 무작위로 탐험한다. 좋은 탐험은 불확실성에 따라 해야 한다 → UCB, Thompson sampling.

08UCB: 모르면 좋게 봐준다

원칙: optimism in the face of uncertainty. 각 기계의 "최대로 잡으면 이 정도까지 좋을 수 있다(포텐)"를 계산해서 가장 높은 기계를 고른다.

UCBt(a) = Q(a) + c · √( ln t / N(a) ) 지금 추정치 (활용) + 불확실성 보너스 (탐험)
  • N(a)↑ → 보너스↓: 많이 당겨봤으면 "이제 충분히 안다".
  • ln t↑ → 보너스 서서히↑: 오래 안 고른 기계는 가만히 있어도 포텐이 올라가 언젠가 다시 확인받는다.
  • N(a) = 0이면 식이 정의되지 않으므로 모든 팔을 한 번씩 먼저 당긴다(UCB = ∞).
  • UCB가 높은 이유는 둘 중 하나: 진짜 좋거나(Q 높음), 아직 몰라서(보너스 큼). 낮다 = 충분히 봤는데도 낮다 = 나쁘다고 확인됨.
기계QN보너스 √(2·ln100 / N)UCB
A0.60800.340.94
B0.4051.361.76 ← 선택
C0.55150.781.33

유도: Hoeffding 부등식에서 c = √2까지

P( q* > Q + u ) ≤ exp(−2Nu²) = δ  ⟹  u = √( ln(1/δ) / 2N ) 보상 ∈ [0,1]일 때. "q*는 확률 1−δ로 Q + u 이하" = 신뢰구간 상한 (Upper Confidence Bound)
δ = t⁻⁴  ⟹  u = √( 4 ln t / 2N ) = √( 2 ln t / N )  ⟹  c = √2 (UCB1)
  • 왜 t⁻⁴: 최적이라서가 아니라 증명용이다. 신뢰구간이 틀릴 확률을 모든 (t, N)에 대해 더해도(union bound) 유한한 상수여야 regret 증명이 된다.
  • 보상 범위가 [a, b]면 보너스를 (b−a)배로 키운다. 실전에서는 c를 튜닝하며, √2보다 작게 써도 대체로 잘 된다.
  • √(t/N)이었다면: 보너스가 너무 빨리 커져 과탐험 → regret이 다항식으로 커진다. ln t의 느린 증가가 "log만큼만 확인"을 만든다.

09Thompson Sampling: 믿음에서 뽑는다

UCB가 기계마다 숫자 하나(상한)를 들고 다닌다면, Thompson sampling은 "진짜 확률이 이쯤일 것 같다"는 분포 전체를 들고 다닌다.

  1. 각 기계의 믿음 분포에서 값을 하나씩 무작위로 뽑는다.
  2. 뽑은 값이 가장 큰 기계를 당긴다.
  3. 결과로 그 기계의 믿음 분포를 업데이트한다.

Beta 분포 (보상이 0/1일 때)

  • Beta(α, β): 대략 α − 1 = 당첨 수, β − 1 = 꽝 수. 평균 α/(α+β).
  • 시작은 Beta(1, 1) = 균등분포 ("아무것도 모름").
  • 업데이트: 당첨 → α += 1, 꽝 → β += 1. Beta–Bernoulli 켤레라서 카운트 더하기로 끝난다.
  • 관측이 쌓일수록 분포가 뾰족해진다(불확실성 감소).

공통점: 불확실할수록 더 탐험한다. UCB는 보너스 항으로, Thompson은 분포의 폭으로 구현한다.

  • 장점: 튜닝할 c가 없다 / 연속 보상(Gaussian), context(Bayesian 선형회귀)로 확장이 쉽다 / 무작위성 덕분에 지연·배치 피드백에 강하다.
  • 단점: 사후분포를 계산할 수 있어야 한다. 신경망에서는 근사가 필요하다.

이후와의 연결

  • 딥RL 탐험: 네트워크 앙상블에서 하나를 뽑아 행동 (Bootstrapped DQN, 07)
🤖 로보틱스 연결 · 제어기 게인/보행 파라미터 튜닝은 팔이 연속인 bandit이다. GP 사후분포 + UCB/Thompson = Bayesian optimization으로, 실로봇에서 적은 시도로 파라미터를 찾을 때 실제로 쓴다. Model-based 로봇 학습(10)의 PETS도 동역학 모델 앙상블에서 샘플해서 계획한다.

꼭 가져갈 세 가지
  1. 증분 업데이트 Q ← Q + α(target − Q)는 끝까지 반복되는 뼈대다. 바뀌는 건 target뿐이다.
  2. 좋은 탐험 = 불확실성에 따른 탐험. MDP, 딥RL, 로봇 학습까지 계속 같은 문제로 돌아온다.
  3. bandit에는 상태 전이가 없다. 행동이 다음 상태를 바꾸는 순간 MDP가 된다 → 02 MDP & Bellman 방정식

?확인 문제

답을 먼저 떠올려 본 뒤 펼쳐보자.

문제 1ε = 0.1, k = 10일 때, 최적 팔을 완벽히 알아낸 뒤에도 생기는 스텝당 평균 regret은?

확률 ε로 k개 중 무작위 → 스텝당 regret = ε · (1/k)ΣaΔa = 0.1 · Δ̄ (Δ̄: 최적 팔 포함 k개 팔의 평균 gap). 상수이므로 T번이면 선형으로 쌓인다.

문제 2고정 α 업데이트에서 i번째 보상의 가중치는? Robbins–Monro 조건은 왜 필요한가?

가중치 α(1−α)n−i로 오래될수록 지수적으로 감소한다. Σα = ∞는 초기값의 영향을 지우고 어디로든 갈 수 있게, Σα² < ∞는 보폭이 줄어 노이즈가 사라지게 한다. 고정 α는 두 번째를 어겨 수렴하지 않지만 nonstationary를 따라간다 (그림 5).

문제 3UCB에서 N(a) = 0이면 어떻게 하나? 보너스를 √(t/N)으로 바꾸면?

모든 팔을 한 번씩 먼저 당긴다. √(t/N)은 보너스가 너무 빨리 커져 과탐험 → regret이 log가 아니라 다항식으로 커진다.

문제 4보상 범위가 [−100, 0]인 로봇 문제에 UCB1을 쓰려면?

Hoeffding의 범위 항 때문에 보너스를 범위 폭(100)배 키우거나, 보상을 [0, 1]로 정규화한다.

문제 5로봇 문제 하나를 bandit으로 모델링하고, "상태가 없다"는 가정이 어디서 깨지는지 말해보라.

예: grasp 후보 5개 중 선택. 물체 위치·자세가 매번 바뀌면 상황(context)이 생겨 contextual bandit이 되고, 이전 grasp 실패가 물체를 밀어 다음 상황을 바꾸면 MDP가 된다.

Q&A질문 & 답변

공부하면서 직접 했던 질문들. 답을 먼저 떠올려 본 뒤 펼쳐보자.

Q1bandit이 뭔지 잘 모르겠어.04 · Bandit이란
  • 이름은 슬롯머신의 별명 "one-armed bandit(외팔이 강도)"에서 왔다. 팔이 여러 개면 multi-armed bandit.
  • 설정: 보상 분포를 모르는 슬롯머신 k대. 매 라운드 하나를 골라 당기고 보상을 받는다. T라운드 동안 누적 보상을 최대화한다.
  • 핵심 난점: 고른 기계의 결과만 보인다 → 좋아 보이는 걸 계속 쓸지(exploitation), 덜 해본 걸 알아볼지(exploration).
  • 실제 예: A/B 테스트, 임상시험 배정, 광고/추천, 로봇 grasp 후보 선택, 제어기 하이퍼파라미터 선택.
Q2마르코프 체인 같은 내용은 안 해도 돼?04 · Bandit이란
  • 한다. 02에서 Markov chain → MRP → MDP 순서로 쌓는다.
  • bandit은 상태가 하나뿐인 특수한 MDP라 상태 전이가 없고, Markov 성질을 따질 필요가 없다. 그래서 탐험 문제만 따로 보려고 먼저 다룬다.
Q3증분 업데이트를 더 설명해줘. target이 뭐야? 도달하려는 목표 점이야?05 · 증분 업데이트
  • 진짜 목표 점은 q*(a) = E[R|a]다. 알 수 없다.
  • target은 이번 스텝에 관측한 Rn이다. q*의 noisy 샘플이자 기댓값이 q*인 "흔들리는 과녁"이다. 이번 업데이트에서 Q를 그쪽으로 조금 끌어당긴다. → 그림 5
  • 표본평균을 정리하면 그대로 나온다: Qn+1 = Qn + (1/n)(Rn − Qn).
  • SGD 관점: L = ½(R − Q)²의 경사하강. 기대 업데이트가 0인 점이 Q = q*.
  • 이후 섹션에서는 target만 바뀐다: MC는 Gt, TD는 R + γV(s'), Q-learning은 R + γ max Q(s',·).
Q4regret은 후회 같은 거야? 나쁜 선택 횟수에 gap은 왜 곱해?06 · Regret
  • 그렇다. "처음부터 최적 팔을 알았다면 받았을 기대 보상 − 실제로 받은 기대 보상".
  • 실수마다 손해 크기가 다르다. 한 번 잘못 고를 때 손해가 Δa이니 횟수 × gap = 총 손해. → 그림 6
  • 예: 최적 0.70일 때 B(0.69)를 100번 → 손해 1.0, C(0.10)를 10번 → 손해 6.0. 횟수만 세면 잘못된 결론이 나온다.
  • 기댓값 q*로 계산하는 이유: 운을 실력으로 치지 않기 위해서.
Q5팔을 당긴다는 게 마르코프 체인에서 다음 state를 결정하는 거야?04 · bandit vs MDP
  • 아니다. bandit에서 팔을 당기면 보상만 결정된다. 다음 라운드도 같은 기계, 같은 분포다.
  • MDP에서는 행동이 보상과 다음 상태 p(s'|s,a)를 함께 바꾼다. → 그림 4
  • 계층: Markov chain(상태 전이만) → MRP(+보상) → MDP(+행동). bandit은 상태가 1개이고 모든 행동이 제자리로 돌아오는 MDP다.
Q6평균을 내면 확률을 알게 되고, 알고리즘마다 target과 당기는 식이 다른 거지? regret은 썩은 머신을 빨리 버리게 해주는 거고? MDP는 행동과 보상이 다음 상태를 바꾸니 밴딧머신의 확률이 바뀌는 거야?이해 확인
  • 첫 번째는 맞다. 다만 bandit 알고리즘은 ① 추정(Q 갱신, target)과 ② 선택 규칙으로 나뉜다. bandit에서는 ①이 거의 같고(target = R) ②가 다르다. target이 달라지는 건 MDP부터다.
  • regret은 알고리즘이 쓰는 도구가 아니라 채점하는 성적표다. μ*를 모르니 알고리즘은 계산할 수 없다. "썩은 머신을 빨리 버리고 운빨을 가려내는" 건 UCB/TS가 불확실성을 정량화해서 하는 일이고, 그렇게 하는 알고리즘의 regret이 낮게 나온다.
  • MDP: 다음 상태를 바꾸는 건 보상이 아니라 (현재 상태, 행동)이다. "확률이 바뀐다"보다 "내 행동 때문에 다른 방으로 이동하고, 방마다 기계와 확률이 다르다"가 정확하다.
상황이름
확률이 내 행동과 무관하게 시간에 따라 변함 (마모)nonstationary bandit
방이 바뀌지만 내 행동 때문이 아님 (손님마다 다른 상황)contextual bandit
방이 내 행동 때문에 바뀜MDP
Q7regret은 강화학습이 다 끝난 뒤의 사후평가 같은 거야? 정답(결과)을 알아야 하는 거 아냐?06 · Regret
  • 맞다. 정답 μ*를 알아야 하므로 에이전트 자신은 절대 계산할 수 없다.
  • 다만 "끝난 뒤에만"은 아니다. 정답을 아는 실험자는 시뮬레이션 중 매 스텝 누적 regret을 기록해 곡선으로 그린다. 곡선 모양(직선 vs 로그)이 알고리즘의 성질을 보여준다. → 그림 12
  • 쓰임: ① 실행 전 이론적 보장 ② 시뮬레이션 실험 평가 ③ 실제 배포에서는 계산 불가 → 대리 지표.
  • 딥RL 실험은 보통 return 곡선을 보고하고, regret은 주로 이론 논문에서 쓴다.
Q8MDP는 상태에서 행동하면 보상을 받고, 누적하면서 다음 방(처음 보는 선택지)으로 가서 또 행동하는 느낌이야?04 · bandit vs MDP
  • 흐름은 맞다: 상태 → 행동 → (보상, 다음 상태) → 반복. 할인된 보상 합 G가 최대화 대상이다.
  • 수정 ①: 방은 다시 방문된다. 같은 칸, 같은 자세로 돌아오고 에피소드도 반복한다. 그래서 방 s에서 배운 걸 다시 왔을 때 쓸 수 있고, 학습이 가능하다.
  • 수정 ②: 레버(행동 집합)는 보통 어느 방이나 같고, 결과(보상, 다음 방)가 방마다 다르다.
  • 수정 ③: 누적 보상은 점수판에 쌓일 뿐 다음 방을 바꾸지 않는다. 다음 방은 (s, a)로만 정해진다.
  • 🤖 로봇의 연속 상태 공간에서는 정확히 같은 상태를 다시 볼 일이 거의 없다 → "비슷한 방은 비슷하다"는 일반화(함수 근사, 06)가 필요하다.
Q9탐험 강도 c가 이론적으로 √2인 이유가 있어?08 · UCB
  • Hoeffding 신뢰구간 u = √(ln(1/δ)/2N)에서 δ = t⁻⁴로 잡으면 u = √(2 ln t / N) → c = √2.
  • t⁻⁴는 최적이라서가 아니라 증명용이다. 신뢰구간이 틀릴 확률을 모든 (t, N)에 대해 합해도(union bound) 유한한 상수여야 regret 증명이 된다.
  • 보상 범위 [0,1] 가정이다. [a,b]면 (b−a)배. 실전에서는 c를 튜닝하고, √2보다 작게 써도 대체로 잘 된다.
Q10UCB는 진짜 좋은지 구린지 판단하는 누적 지표네? 높은 놈은 포텐이 있으니 까보고, 낮은 놈은 포텐이 없다는 느낌?08 · UCB
  • 거의 맞다. UCB = "최대로 잡으면 이만큼 좋을 수 있다"는 낙관적 상한, 즉 포텐이다.
  • 주의: UCB가 높은 이유는 진짜 좋거나, 아직 몰라서 둘 중 하나다. 낮다는 건 충분히 봤는데도 낮다, 즉 나쁘다고 확인됐다는 뜻이다.
  • Q, N은 누적되지만 ln t는 매 스텝 커진다. 오래 안 고른 기계는 가만히 있어도 UCB가 서서히 올라간다. 매 스텝 다시 계산하는 점수다. → 그림 8
Q11regret과 이어서 볼 때 gap이 뭐였지? gap의 크고 작음과 UCB, 로그 regret이 잘 연결이 안 돼.08 · UCB · Regret
  • gap Δa = μ* − q*(a): 기계 a를 한 번 고를 때마다 생기는 손해. 진짜 값으로 정의되므로 알고리즘은 모른다.
  • 연결: UCB가 기계 a를 버리려면 a의 상한이 μ* 아래로 내려가야 한다 → 보너스 < Δa → N > 2 ln t / Δa². gap이 작을수록 신뢰구간이 좁아야 하니 많이 당긴다. → 그림 9
  • regret 기여 = Δ × N ≈ ln T / Δ → 총 regret = Σ ln T / Δa = O(log T).
  • 의미: T가 1000배 늘어도 ln T는 2배만 는다. 스텝당 손해가 0으로 간다. 고정 ε-greedy는 실수가 T에 비례한다.
Q12그러면 regret은 RL 전체를 돌린 후의 평가 지표야? 리워드 합 곡선 보고 "여기서 수렴하네" 하는 것처럼?06 · Regret
  • 맞다. 실험자가 학습 과정 전체를 곡선으로 그려 평가하는 지표다.
  • 보상 곡선과 같은 정보를 다르게 본 것이다. 스텝별 regret = 최적선과 보상 곡선 사이의 높이, 누적 regret = 그 넓이. → 그림 7
  • 보상 곡선은 "지금 얼마나 잘하나", 누적 regret은 "잘하게 될 때까지 얼마나 손해 봤나(학습 비용)". 최종 성능이 같아도 늦게 도달한 알고리즘은 regret이 크다.
  • 🤖 실로봇처럼 학습 중 실수가 실제 비용이면 regret 관점이 중요하다.

✓헷갈렸던 개념

  • bandit: 보상 분포를 모르는 슬롯머신 여러 대에서 고르기. 고른 것의 결과만 보인다. Q1

  • 알고리즘의 두 부품: 추정(target) + 선택 규칙. bandit에서는 선택 규칙이 차이다. Q6

  • c = √2: Hoeffding + δ = t⁻⁴에서 나온 증명용 값. 실전은 튜닝. Q9
