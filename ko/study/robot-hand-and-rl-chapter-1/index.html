01에이전트와 환경

강화학습은 한 문장으로 "해 보고, 점수를 받고, 점수가 높아지는 쪽으로 행동을 고친다"이다. 등장하는 것은 둘뿐이다.

용어뜻🤖 엄지 버튼에서는
상태 s세상의 진짜 전체 정보손·공구·버튼의 정확한 위치·속도·접촉력 전부
관측 o에이전트가 실제로 볼 수 있는 것관절 각도·속도, 손끝 압력, 모터 전류, 버튼 위치
행동 a에이전트가 고르는 것관절 목표 변화량 + 손가락별 강성
보상 r방금 행동이 얼마나 좋았는지 매기는 숫자 하나r_reach + r_press + r_click + …
🤖 상태 ≠ 관측. 시뮬은 공구의 정확한 자세(상태)를 알지만 실제 V6 손은 압력과 전류(관측)만 안다. 정책에는 관측만 넣고, 학습 때만 쓰는 부품(보상 계산, critic, 교사)은 상태를 써도 된다. 로드맵 카드의 "(교사만) 정확한 물체 자세"가 이것이다. → Q1 · Q3

보상은 여러 항을 더해도 결국 스칼라 하나다. 그래서 항별 가중치가 중요하다(4장 보상 설계).

02에피소드와 종료

루프를 시작부터 끝까지 한 번 돈 것이 에피소드다. 게임 한 판.

종류뜻🤖 엄지 버튼CartPole
terminated성공이나 실패로 끝남클릭 성공, 공구 떨어뜨림(SLIP)막대 > 12°, 카트 > ±2.4
truncated정해 둔 시간이 다 됨TIMEOUT (5초 = 250스텝)500스텝

03리턴과 할인율 γ

에이전트의 목표는 지금 받는 보상이 아니라 에피소드 끝까지 받을 보상의 합을 최대로 만드는 것이다. 엄지를 버튼 쪽으로 옮기는 순간엔 이득이 없어도, 그래야 나중에 r_press와 r_click(+10)을 받는다.

Gt = rt+1 + γ·rt+2 + γ²·rt+3 + ⋯ ,    0 ≤ γ < 1 리턴 = 앞으로 받을 보상의 할인 합 · 멀리 있는 보상일수록 γk만큼 깎는다

깎는 이유는 세 가지다. ① 에피소드가 길어도 합이 무한대가 되지 않는다 ② 먼 미래는 불확실하다 ③ 같은 +10이라도 빨리 받을수록 가치가 커서 빨리 끝내도록 유도된다.

실무 감각: γ가 보는 시야 ≈ 1 / (1 − γ) 스텝. γ = 0.99면 약 100스텝. 50 Hz로 5초(250스텝) 돌리는 엄지 버튼에서는 0.99 근처를 쓴다. Isaac Lab 예제도 대부분 0.99다. 9장 실습에서 500스텝을 버텨도 할인 리턴이 99.3에서 멈추는 것으로 확인했다.
🤖 보상을 단계형으로 주는 이유. 클릭 +10만 주면 γ 때문에 멀리 있는 보상이 흐릿하게 보이고, 처음엔 우연히 클릭할 일도 거의 없다. 그래서 r_reach(다가가기)와 r_press(눌림 진행률)로 중간중간 길을 알려 준다.

04MDP와 마르코프 성질

MDP = ( S, A, P, R, γ ) 상태 공간 · 행동 공간 · 전이 확률 P(s′ | s, a) · 보상 함수 · 할인율
기호이름🤖 엄지 버튼에서는
S상태 공간손·공구·버튼의 모든 위치·속도·접촉
A행동 공간관절 목표 변화량 + 강성 (연속값)
P전이 확률물리 엔진이 이 역할
R보상 함수r_reach + r_press + r_click …
γ할인율0.99

P는 몰라도 된다. 마찰·접촉을 수식으로 몰라도 step()을 불러 결과만 받으면 학습할 수 있다. 이게 model-free RL이고 PPO도 여기 속한다. 우리가 정할 것은 S·A·R·γ와 종료 조건뿐이다. 문제 카드를 짠다 = MDP를 정의한다.

마르코프 성질: 지금만 알면 과거는 필요 없다

다음 상태는 현재 상태와 행동만으로 정해진다. 그런데 관측만 보면 이 성질이 자주 깨진다. 관측이 상태를 다 못 담는 경우를 POMDP라고 하고, 실제 로봇 문제는 거의 다 POMDP다.

관측마르코프인가이유
관절 각도만❌속도를 몰라 다음 위치를 예측 못 함
관절 각도 + 속도거의 ✅
+ 손끝 압력여전히 부족압력만으로 공구 자세를 완전히 알 수 없음
+ 직전 행동더 나아짐모터 지연이 있을 때 "방금 뭘 시켰는지" 알면 도움

해결책: 속도와 직전 행동을 관측에 넣기 · 최근 몇 스텝을 쌓아서 넣기(아타리 DQN의 frame stacking, Q4) · RNN · 교사–학생으로 이력에서 숨은 물리값 추정(HORA, 6장).

문제 카드의 관측 칸을 채울 때: "이 정보만으로 다음에 뭐가 일어날지 알 수 있나?"

05🤖 엄지 버튼 에피소드 따라가기

커리큘럼 ①(이미 쥔 상태에서 엄지로 누르기)의 에피소드 하나를 끝까지 따라가 본다. 정책은 50 Hz로 행동하고, 그 사이 물리 엔진은 200 Hz로 4번 돈다(Isaac Lab의 decimation = 4).

  • 보상은 받는 즉시 합치지 않는다. 스텝마다 (o, a, r)을 저장했다가, 각 스텝에서부터의 리턴·advantage를 따로 계산한다. 그래야 "t = 10의 행동이 좋았나?"를 따로 평가할 수 있다.
  • 엉뚱한 데를 헤매다 250스텝이 되면 truncated, 공구가 빠지면 terminated(실패)로 끝난다.

06학습 루프: 에피소드 ≠ 업데이트

정책은 매 스텝 고치지 않는다. 경험을 한참 모아 두었다가 한꺼번에 고친다.

그래서 학습 초반엔 엄지가 막 흔들리다가, 반복할수록 "다가가면 벌점이 준다 → 닿으면 +가 나온다 → 끝까지 누르면 +10" 순서로 행동이 자리를 잡는다.

07정책, 가치함수, Advantage

정책 π: 이 상황에서 무엇을 할까

결정적 정책은 같은 관측에 항상 같은 행동을, 확률적 정책은 분포에서 행동을 뽑는다. 로봇 손처럼 행동이 연속값이면 보통 정규분포를 쓴다.

신경망(o) → 평균 μ (관절마다), 표준편차 σ
a ~ Normal(μ, σ)     # 학습 중: σ만큼 흔들림 = 탐험 (8장)
a = μ                # 실기 배포: 보통 평균만

V, Q, Advantage

V(s) = E[ G | s ]  ·  Q(s, a) = E[ G | s, a 먼저 ]  ·  A(s, a) = Q(s, a) − V(s) V = 상황 점수 · Q = 이 행동 하나를 먼저 하고 그 뒤로 정책대로 했을 때 · A = 이 행동이 평소보다 얼마나 나은가

Advantage의 비교 대상은 "지금 vs 나중"이 아니라 "이 행동 vs 여기서 평소 하던 행동"이다.

상황행동QVA판정
엄지가 버튼 2 cm 앞버튼 쪽으로+7+5+2확률 ↑
엄지가 버튼 2 cm 앞반대쪽으로+1+5−4확률 ↓
공구가 기울어짐 (위기)다시 꽉 쥐기−1−3+2나빠도 평소보다 나음 → ↑

PPO에는 Q 신경망이 없다. critic V 하나로 추정한다.

At ≈ rt+1 + γ·V(st+1) − V(st) 실제로 해 보니 − 예상 · TD 오차. 실제로는 여러 스텝을 섞은 GAE를 쓴다 (3장)

08탐험과 활용

뜻🤖 엄지 버튼에서는
활용 (Exploitation)지금까지 가장 좋았던 행동"아래로 누르면 +였지" → 계속 아래로
탐험 (Exploration)안 해 본 행동도 시도옆으로, 다른 각도로, 강성을 바꿔서

활용만 하면 버튼 가장자리를 비스듬히 누르는 어설픈 방법에 갇히고(국소 최적), 탐험만 하면 배운 걸 못 써먹는다.

PPO에서 탐험하는 방법

  1. 확률적 정책의 σ: 학습되면서 저절로 줄어든다
  2. 엔트로피 보너스: σ가 너무 빨리 줄지 않게 "분포가 넓을수록 보너스". 3장의 entropy coefficient
  3. 병렬 환경: 4096개가 각자 다르게 시도
  4. 랜덤 시작 / 도메인 랜덤화: 매번 조건이 달라 같은 행동만 반복해서는 점수가 안 나온다
학습 곡선 신호: entropy가 너무 빨리 0으로 → 탐험 부족, 국소 최적 의심. 계속 높게 유지 → 아직 확신이 없거나 보상 신호가 약함.
🤖 로드맵 랜덤화의 두 번째 역할. 버튼 위치 ±5 mm, 작동력 ±30%, 시작 자세 ±15 mm는 sim-to-real용이면서, 학습 중 다양한 경험을 하게 하는 탐험 효과도 있다.

CartPole

카트 위에 막대를 세워 두고, 카트를 좌우로 밀어 막대가 안 넘어지게 버티는 문제.

관측 obs[카트 위치 m, 카트 속도 m/s, 막대 각도 rad, 막대 각속도 rad/s]. 각도 + = 오른쪽으로 기울어짐
행동0 왼쪽으로 밀기, 1 오른쪽으로 밀기 (이산. 엄지 버튼은 연속)
보상버틴 스텝마다 +1 → 리턴 = 버틴 스텝 수
terminated각도 > 12° 또는 위치 > ±2.4
truncated500스텝 (사실상 성공)

코드 1: 루프 (cartpole_loop.py)

import gymnasium as gym

env = gym.make("CartPole-v1")

for episode in range(3):
    obs, info = env.reset(seed=episode)   # 에피소드 시작, 첫 관측 o₀
    episode_return = 0.0
    t = 0

    while True:
        action = env.action_space.sample()   # 정책 자리. 지금은 무작위
        next_obs, reward, terminated, truncated, info = env.step(action)   # 루프 한 바퀴

        episode_return += reward
        obs = next_obs        # 빼먹으면 정책이 계속 옛날 관측만 봄
        t += 1

        if terminated or truncated:
            print(f"[에피소드 {episode}] 길이 {t}스텝, 리턴 {episode_return:.0f}")
            break

env.close()

코드 2: 규칙 정책 (rule_policies.py)

무작위 대신 obs를 보고 행동을 정하는 사람이 짠 정책. 손바닥 위 빗자루처럼, 기우는 쪽으로 카트를 민다.

policies = {
    "무작위":              None,
    "각도만 obs[2]":        lambda o: o[2] > 0,
    "각속도만 obs[3]":      lambda o: o[3] > 0,
    "각도 + 1.0 × 각속도":  lambda o: o[2] + 1.0 * o[3] > 0,
    "각도 + 0.5 × 각속도":  lambda o: o[2] + 0.5 * o[3] > 0,
    "각도 + 0.1 × 각속도":  lambda o: o[2] + 0.1 * o[3] > 0,
}
G      += reward                  # 할인 없는 리턴
G_disc += (GAMMA ** t) * reward   # γ = 0.99 할인 리턴

무엇을 확인했나

  1. 정책 = obs → action 함수. obs를 쓰기 시작하자 무작위보다 2배 버틴다.
  2. 속도가 왜 필요한가. 각도만 보면 이미 기운 뒤에 반응해 흔들림이 커진다(40.9). 각속도를 보면 넘어가는 중에 미리 반응한다(198.7). 둘 다 보면 500. 각도만 쓰는 정책은 속도를 못 보는 부분 관측과 같다(4장).
  3. k를 손으로 바꾸는 게 튜닝. k = 0.5, 0.1에서 매번 500. PPO는 이런 숫자 수만 개를 자동으로 찾는다(10장).
  4. γ의 시야. 500스텝을 버텨도 할인 리턴은 99.3에서 멈춘다. (1 − 0.99500) / (1 − 0.99) ≈ 99.3. γ = 0.99는 대략 100스텝 앞까지 본다(3장).

설계자가 정하는 곳은 환경 안에 있다

이번 코드에는 튜닝할 곳이 없다. 남이 만든 환경을 쓰기만 했으니까. 설계자가 정하는 값은 CartPole 환경 안에 이미 들어 있고, 엄지 버튼에서는 우리가 정해야 한다.

10🤖 사람은 어디에 관여하나

k는 정책 안의 숫자라서 RL이 자동으로 찾는다. 보상 설계·쉐이핑은 사람 몫이 맞지만 k와는 층이 다르다. k는 "어떻게 풀까", 보상은 "무엇을 잘한 걸로 칠까"다.

그래서 사람의 일은 위아래 양 끝으로 옮겨 간다.

  • 목표 정의: "클릭"이 무엇이고 몇 N까지 눌러도 되는지. 공구·공정·고객 요구에서 나온다
  • 행동을 보고 판단: 보상 곡선은 올랐는데 영상을 보면 버튼을 옆에서 문지르고 있다 → 보상 해킹을 알아채는 눈
  • 하드웨어와 안전: V6 손끝 17.3 N, 연속 작업 발열, MCU 하드 한계
  • 실기 검증: 시뮬에서 된 게 V6에서 되는지, 안 되면 시뮬의 무엇이 틀렸는지
숫자를 맞추는 일에서 "무엇을 잘해야 하는지 정하고, 정말 잘하는지 확인하는 일"로.

?확인 문제

답을 먼저 떠올려 본 뒤 펼쳐보자.

문제 1CartPole 관측에서 속도 두 개(카트 속도, 각속도)를 빼면 어떤 문제가 되고, 어떻게 보완하나?

마르코프가 깨진 부분 관측(POMDP)이 된다. 각도만 보는 정책이 41스텝에서 넘어진 것과 같은 이유다. 최근 몇 스텝의 관측을 쌓아 넣으면(frame stacking) 차이로 속도를 추정할 수 있다.

문제 2γ = 0.9, 정책 50 Hz일 때 시야는 몇 초인가? 55스텝 뒤 클릭 +10은 지금 얼마로 보이나?

1/(1−0.9) = 10스텝 = 0.2초. 10 × 0.955 ≈ 0.03. 클릭이 거의 안 보이니 엄지 버튼에는 너무 근시안이다. 0.99면 10 × 0.9955 ≈ 5.8. (그림 3에서 확인)

문제 3공구를 떨어뜨려 끝난 것과 250스텝이 다 돼서 끝난 것은 각각 무엇인가? 왜 구분하나?

terminated와 truncated. 떨어뜨린 뒤엔 더 받을 보상이 없지만, 시간 초과는 "계속했으면 받았을 보상"이 남아 있다. 둘을 섞으면 critic이 "250스텝째는 원래 가치가 0"이라고 잘못 배운다. 자세한 처리는 3장 GAE에서.

문제 4버튼 앞에서 어떤 행동의 Q = +3, 그 상황의 V = +5다. 보상이 플러스인데 이 행동의 확률은 올라가나?

내려간다. A = 3 − 5 = −2. 평소보다 못한 행동이다. 기준은 "플러스냐"가 아니라 "평소보다 나으냐"다.

문제 5r_push(공구가 손 안에서 돈 각도)는 실제 V6로 잴 수 없다. 보상에 써도 되나? 정책 관측에는?

보상에는 써도 된다. 보상은 학습 때만 쓰고 시뮬은 정답을 안다. 정책 관측에는 넣으면 안 된다. 실기에서 그 값이 없으니까. 넣고 싶다면 교사 관측에만 넣고 학생이 압력·전류 이력에서 추정하게 한다.

문제 6규칙 정책의 k와 r_reach의 −1.0/cm 중 PPO가 찾아 주는 것은?

k. k는 정책 안의 숫자다. −1.0/cm는 "무엇을 잘한 걸로 칠지"를 정하는 문제 쪽 값이라 사람이 정한다(또는 Eureka 같은 바깥 루프로 탐색).

Q&A질문 & 답변

공부하면서 직접 했던 질문들. 답을 먼저 떠올려 본 뒤 펼쳐보자.

Q1세상의 진짜 상태와 관측으로 나누는 이유는? 학습에 영향이 있나? 관측만 넣어도 되지 않나?01 · 에이전트와 환경
  • 정책에는 관측만 넣는 게 맞다. 실기에는 관측밖에 없다.
  • 그래도 나누는 이유 ① 관측이 상태를 다 못 담으면 학습이 안 된다(POMDP). 속도가 없으면 다가가는 중인지 멀어지는 중인지 모른다. → 그림 4
  • ② 보상은 학습 때만 쓰니 상태로 계산해도 된다. r_push는 실기로 못 재지만 시뮬은 안다.
  • ③ critic·교사는 학습 때만 쓰니 상태를 받아도 된다. 로드맵의 "(교사만)". → 그림 7
Q2행동이 잘게 계속 나오면, 매 스텝 새 관측과 보상이 생기고 그걸 누적하고 정책을 고치는 건가? 한 사이클을 종료까지 예시로 정리해 줘02 · 에피소드
  • 맞다. 정책이 50 Hz로 행동을 내고, 매 스텝 새 관측과 보상이 나온다. → 그림 5
  • 다만 보상은 바로 합치지 않고 (o, a, r)을 저장했다가 스텝별 리턴·advantage를 계산한다.
  • 정책은 매 스텝 고치지 않는다. 4096 환경 × 24스텝을 정책 고정으로 모은 뒤 한꺼번에 고친다. 에피소드 ≠ 업데이트. → 그림 6
Q3보상 계산, critic처럼 실기로 안 나가는 것들은 상태값으로 진짜 점수를 알아내서 평가하는 건가?02 · 에피소드
  • 맞다. critic에 상태를 주는 방식을 asymmetric actor-critic이라고 한다.
  • 단서 ① 보상은 "진짜 점수"가 아니라 "우리가 정한 점수"다. 식이 틀리면 엉뚱한 걸 잘하게 된다(보상 해킹, 4장).
  • 단서 ② 실기 성공 판정은 관측으로 만들어야 한다. 로드맵 원칙 "시뮬 성공 판정은 실기 판정기와 같은 신호(압력 패턴, 클릭 힘 변화, 전류)로".
Q4아타리 문제처럼 과거 정보를 조금 쌓아서 상태를 추정하는 건가?04 · MDP
  • 같다. DQN(2015) 아타리는 화면 한 장으로 공의 속도를 몰라 최근 4프레임을 쌓아 넣었다(frame stacking).
  • 로봇은 관절 속도를 직접 넣을 수 있어 이력이 짧아도 되는 경우가 많다.
  • 마찰·질량 같은 숨은 물리값은 긴 이력 + 학습된 추정기로 푼다(HORA의 adaptation module, 6장).
Q5V는 상황 점수, Q는 이 상황에서 이 정책으로 행동했을 때 평균 점수? Advantage는 무엇을 기준으로, 상태 기반으로 평가하나?07 · 정책과 가치함수
  • V는 맞다. Q는 "정책대로"가 아니라 "이 행동 하나를 먼저 하고 그다음부터 정책대로"다.
  • Advantage는 "지금 vs 나중"이 아니라 "이 행동 vs 여기서 평소 하던 행동". 위기 상황에서 덜 나빠지는 행동도 A > 0.
  • 평가 대상은 정책 전체가 아니라 그 스텝의 행동 하나.
  • PPO는 critic V로 A ≈ r + γV(s′) − V(s)를 계산한다. V에 상태를 넣으면 advantage도 정답 정보 기반이 된다. → 7장
Q6VS Code에서 실행하니 ModuleNotFoundError: No module named 'gymnasium'09 · 실습
  • VS Code가 시스템 파이썬(/usr/bin/python3.12)으로 실행했다. gymnasium은 rl-study 환경에만 있다.
  • Ctrl+Shift+P → Python: Select Interpreter → rl-study. 터미널에서는 which python으로 확인.
Q7코드를 한 줄씩 설명해 줘. 실제로 RL을 설계할 때 직접 작성·튜닝해야 하는 곳은?09 · 실습
  • 핵심 줄: reset() = 에피소드 시작, action = … = 정책 자리, step() = 루프 한 바퀴, obs = next_obs = 빼먹으면 옛날 관측만 봄.
  • 이 코드엔 튜닝할 곳이 없다. 설계자가 정하는 값(관측, 행동, 보상, 종료, 시간 제한, 시작 분포, 물리)은 환경 안에 있다. → 9장 표
  • 여기에 학습 하이퍼파라미터(γ, lr, rollout 길이, entropy)가 더해진다(2·3장).
Q8obs가 의미하는 게 뭐고, 과제 1번은 뭘 해 보라는 건가?09 · 실습
  • obs = observation. [카트 위치, 카트 속도, 막대 각도, 막대 각속도], 각도 + = 오른쪽으로 기울어짐.
  • 과제 1: 무작위 대신 obs를 보고 행동을 정하는 규칙 정책 만들기. 빗자루가 오른쪽으로 기울면 손을 오른쪽으로.
  • 목적: 정책 = obs → action 함수임을 체감하고, RL은 이 if문을 신경망이 찾게 하는 것임을 보기.
Q9관측값으로 분기해서 행동하는 건 단순한 "마르코프 분기"가 만들어진 건가?09 · 실습
  • 현재 관측만 보고 행동 → 마르코프 정책(memoryless). 같은 obs면 같은 행동 → 결정적 정책. 기준을 넘으면 확 바꾸는 방식 → 제어 분야의 bang-bang 제어.
  • 결과: 무작위 17/17/37 → 각도 규칙 41/51/35. 각도만 보면 기운 뒤에 반응해서 500에 못 미친다.
Q10AI 시대에 RL에서 사람이 관여할 곳은 k 같은 값을 정하는 것인가? 보상 설계·쉐이핑이 여기에 속하나?10 · 사람의 역할
  • k는 RL이 찾는다. 정책 안의 숫자다.
  • 보상 설계·쉐이핑은 사람 몫이 맞지만 층이 다르다. k = "어떻게 풀까", 보상 = "무엇을 잘한 걸로 칠까". → 그림 11
  • 보상 코드 작성·반복 수정은 LLM이 잘한다(Eureka). 사람은 목표 정의, 영상 보고 보상 해킹 알아채기, 하드웨어·안전, 실기 검증으로 옮겨 간다.

✓헷갈렸던 개념

  • 관측 ≠ 상태: 정책은 관측만, 보상·critic·교사는 상태도 된다. Q1 · Q3
  • 보상은 저장했다가 계산: 스텝마다 (o, a, r) 저장 → 스텝별 리턴·advantage. Q2
  • 에피소드 ≠ 업데이트: rollout은 정책 고정, 업데이트는 수천 에피소드 조각으로. Q2
  • 마르코프는 관측의 성질: 각도 사진 한 장 vs (각도, 각속도). 부족하면 frame stacking. Q4
  • Q는 "이 행동 먼저", Advantage는 "평소 대비". 플러스 보상이어도 A < 0일 수 있다. Q5
  • 설계자가 정하는 곳 = 환경: 관측·행동·보상·종료·시작 분포·물리. Q7
  • 규칙 정책: 마르코프 + 결정적 정책, bang-bang 제어. Q9
  • k vs 보상 가중치: 정책 파라미터(RL이 찾음) vs 문제 설정 값(사람이 정함). Q10
